# Offline consistency review of saved synthetic confirmation reports

`python -m scripts.review_runtime_confirmation_report REPORT.json` reads one local JSON report. It never connects to an exchange/database, changes runtime admission, replays a trade, or grants approval. The existing minute reviewer remains unchanged and intentionally measures trace assumptions only; it is not a confirmation validator. The new reader composes that measurement with a separate report-schema/consistency check.

Required confirmation flags, owner/finalization state, fixed policy limits, counters, stop reason, reported outcome and result proof must agree. Closed reports cannot still claim an active/running owner. Boolean counts, missing fields, unsupported approval/reverification claims, inconsistent seal-failure flags and mismatched order-POST totals are rejected. The POST total checks numeric claims only: payload ownership, LIMIT versus reduce-only semantics, signatures and query shapes are not reconstructed from the redacted trace.

A report with unsealed flows, seal/session failure, an unconfirmed proof, unresolved trace responses, counter inconsistency or insufficient modeled trace headroom requires attention. A zero unsealed-flow count cannot clear an explicit seal failure: an acknowledgement/commit discrepancy may still require review. Conversely, a returned financial proof does not itself prove every flow sealed. The generic reader neither repairs records nor freshly rechecks the financial database.

Exit status 0 means a consistent report under this reader's assumptions only; it is not execution approval. Status 3 means structurally consistent data requiring additional review; status 2 means invalid/missing/contradictory input. Every JSON output says execution_approved=false and next_action=KEEP_PAUSED_REVIEW_ONLY. Input authenticity, current exchange state, financial proof, order payload scopes, actual cost bounds, external order usage and IP capacity remain unverified. Saved evidence can be old or fabricated; passing consistency cannot make it current or authentic. Unknown fields are ignored and never echoed.

Input is capped at 16 MiB, trace size retains the original 20,000-row bound, and JSON nesting is limited to 64 outside quoted strings. Duplicate keys and nonfinite values, including floating overflow, are rejected. Errors use fixed codes without echoing paths, arguments, response data or unknown fields. Review is read-only and does not modify the supplied file.

Fifty-five current reader tests cover contradictions, scope claims, counter types/limits, incomplete reports, ambiguous seal state, trace problems, parser bounds, duplicate/nonfinite JSON, redaction and CLI statuses. A scope comparison mutates ten confirmation facts in a real prior synthetic report: the old minute reader still does its intended trace-only job while the new reader rejects the changed report facts. This is a distinction between tools, not ten newly discovered minute-reader bugs.

Three actual prior TP/partial/seal-failure reports are extracted from the immutable GitHub artifact at commit `6a325b6ed82f1628f63faf97d5e37ab82257cf37` after verifying its full archive SHA-256. Their financial runtime source is `9283140d588a523a2ee030888bfeba8c77284ec1`. Fresh offline replay uses this new reader; the normal two return status 0 and the seal failure status 3. Provenance records retain input hashes, source and archive identity. Historical lifecycle JUnit files are explicitly reused, not claimed as fresh financial executions.

No financial/runtime control file changed relative to that source, so those lifecycles are not rerun merely for this read-only addition. Current core regression/static checks and network-none Docker replay provide new validation. Original lifecycle startup holds were accelerated and observation was 0.8 seconds; these are not new 300-second natural observations or actual exchange measurements. Docker checks saved report parsing/CLI only, without financial execution.

This is an additional offline CLI in the full source repository; the ZIP is review material rather than a standalone installer. Canonical runtime CLI and installed historical source files remain unchanged. Default production execution remains disabled. No Windows installation/database change, real exchange request/order or trading resume occurs in this review.
