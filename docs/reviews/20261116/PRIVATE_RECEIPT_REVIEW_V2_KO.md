# 성공 영수증 선택 오류 수정

첫 읽기 전용 검토는 RECEIPT_DIRECTORY_NOT_UNIQUE_OR_INVALID로 중단됐다. 파일/Docker/서비스 변경은 보고되지 않았다. 성공 화면에서 수동으로 전사한 UUID를 config에 고정해 실제 폴더와 달라진 문제다. 이전 fixture도 같은 config에서 폴더를 생성해 실제 식별자 오기를 찾지 못했다. 사용자 폴더 조회 출력에서 차이를 확인했으며 전체 UUID를 다시 전사해 고정하지 않는다.

v2는 16일자 v3 폴더를 최대 32개까지 살펴보고, 각 폴더의 이름은 32자리 lowercase hex UUID 형식과 reparse 금지를 요구한다. COPY_PRIVATE_WEEK_V3_RECEIPT.json을 읽어 이미 알려진 소스 a70f103b3a5cd764ea43838d9a6e565637dafa32와 성공 종류가 일치하는 후보가 정확히 하나일 때만 고른다. 후보가 없거나 여럿이면 중단하며 최신·첫 폴더를 임의 선택하지 않는다. 선택한 실제 폴더 이름의 UUID에서 clone volume suffix를 확인하므로 다른 이름으로 옮긴 기록도 무조건 허용하지 않는다.

나머지 읽기 전용 다섯 파일 검사는 유지한다. 메타데이터·카운터·기간·합성 검토·101.004초/Decimal/75초 제한·동반 기록/식별자·승인 false/8개 남은 근거를 대조하고 종료 시 길이·SHA256을 재확인한다. Docker·키 파일·원문·현재 컨테이너 상태·외부 해시 pin을 조회하지 않고 파일을 변경하지 않는다. source reference와 로컬 기록의 유일성은 외부 독립 증명이 아니다.

새 시험은 config와 독립된 UUID에서 성공 기록을 생성하고 또 다른 UUID에서도 선택이 되는지 확인한다. 같은 소스의 두 성공 기록은 거부하고 다른 소스는 선택하지 않으며, 성공 파일 없음·잘못된 폴더 형식·directory symlink를 거부한다. 기존 형식·권한·내용·동반 기록·seal·파일 불변성 시험도 유지한다. 성공 표시는 자동 출력되는 결과이며 CMD 입력 명령이 아니다.

소스 56개(41.41초)와 최종 ZIP 56개(38.15초)의 동일 검사 집합이 통과했다. ruff/format/diff 및 소스에서 ZIP 바이트 재생성도 확인했다. 실제 사용자 PC의 수정본 결과는 아직 관측하지 않았다.
