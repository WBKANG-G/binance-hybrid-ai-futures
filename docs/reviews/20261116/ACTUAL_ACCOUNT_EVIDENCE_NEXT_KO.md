# 합성 검증 이후 실제 계정 증빙 준비

사용자는 다음 단계 진행을 요청했다. USB 참조 복사/해시 검증 성공은 Windows 콘솔 사진에서 관찰했고,
물리적 분리는 사용자가 명시적으로 보고했다. Windows 안전 제거 완료는 별도로 확인하지 않았으며,
독립 보관·별도 PC 검증을 완료했다고 처리하지 않는다. 과거 합성 실행 검증 결과는 그대로 보존한다.

이번 단계의 선행 정보는 기존 프로그램이 사용하던 Binance 선물 **데모** 계정에 웹으로 접근할 수
있는지이다. 키·Secret·비밀번호·전체 계정 식별자를 채팅이나 저장소에 수집하지 않는다.
웹 로그인 가능 여부 자체가 계정 신원이나 API 키 연결을 입증하는 것은 아니다.

실제 조회 수집기는 준비 완료로 간주하지 않는다. 기존 합성 sender 테스트와 RAM 서명 검토를
실제 원격 전송 성공으로 승격하지 않는다. 날짜·부팅·주 경계가 변한 기존 원본용 조회 스크립트를
재사용하거나 원본 컨테이너/복구 사본을 시작하지 않는다. USB는 다시 연결할 필요가 없다.

계정 접근을 확인한 후 확보 가능한 자료의 범위를 정하고 로컬에 보관한다.

| 미충족 항목 | 확보할 자료와 한계 |
|---|---|
| 계정 신원·키 문맥 | 해당 데모 계정의 식별 근거와 별도 보호된 키 문맥의 연결. 로그인 화면·서명 성공만으로 동일 계정 판정 금지. |
| 계정·종목 설정 | 포지션 모드, 마진/자산 모드, 대상 종목 설정. 현재 설정이 과거에도 같았다고 추정 금지. |
| 일반·알고 주문 | 두 종류 각각의 현재 미체결 상태와 수집 시각. 빈 일반 주문 목록만으로 손절 알고 주문 부재 판정 금지. |
| 거래·수익·입출금 전체 | 대상 계정·UTC 구간·페이지/누락 범위·원문 출처를 보존한 내역. UI가 내보내기를 지원하지 않으면 부족한 범위를 표시. |
| 일자 경계 평가 | 저장 일/주와 대상 일/주에 해당하는 자정 가치 또는 별도로 검토한 재구성 근거. 현재 잔고를 과거 기준으로 대입 금지. |
| 운영자 진술·근거 수락 | 실제 자료·계정·구간이 정해진 뒤 별도 구체적 진술과 수락. “다음 단계”를 진술/수락으로 변환 금지. |
| 과거 미해결 요청 4건 | 원래 요청 ID에 대응하는 거래소 자료. 요청 ID는 비공개 로컬 자료로 다루고 미조회/없음 응답을 해소로 간주하지 않음. |
| 현재 기간·손실 기준 | 확인 시점의 KST 일/주와 원장·기준액·고점/손실 계산을 재대조. 오래된 기간 자동 초기화 금지. |

다음 안내는 계정 접근 여부에 맞춰 한 단계씩 제공한다. 증빙의 출처·범위가 확인되기 전에는
미충족 항목을 완료 처리하지 않는다. 원본·복구 사본 정지와 실행·주문·LIVE 비활성은 유지한다.
