# 11월 16일 주간 경계의 복사본·임시 키 통합 검증

한국 날짜 2026-11-16은 월요일이다. 현재 검토 일자와 주간 키는 모두 2026-11-16이지만 저장 원장의 일자는 2026-11-13, 주간 키는 2026-11-09다. 이번 단계는 이 차이를 관측하는 합성 검증이며 일간·주간 기준의 채택이 아니다. 기존 15일자 실행기를 다시 실행하거나 실제 키를 입력하지 않았다.

rehearse_private_week_copy 후보는 명시적인 copy_only/synthetic_only 및 주간 경계의 관측 전용 확인을 요구한다. 현재 일/주 키가 16일/16일이고 저장 키가 13일/9일인 DAY_AND_WEEK_SEPARATE_REVIEW 상태만 지원한다. 지난 15일 프로필, 이미 채택된 기간, 확인 누락은 변경 전에 거부한다. 검증 후에도 저장·현재 기간이 같은 조합인지 재확인한다. 이 관측 확인을 operator 진술·근거 수락·기간 채택으로 승격하지 않는다.

기존 합성 파이프라인에는 선택적인 PrivateReadCredentialLease 경로를 추가했다. 기존 기본 경로는 유지하며 새로운 의존성은 private 경로에서만 로드한다. 새 경로는 고정된 합성 key/secret pair만 허용하고 내부 합성 sender만 사용한다. 실제 키처럼 다른 pair는 보조 설정 전에 거부한다. 같은 파일·RAM 서명 문맥·V2 원문 보관·읽기 전용 내용 검사를 연결하며 원장·기간·요청 상태·보호 테이블과 파일을 보존한다. 기존 실제 영수증과 게시 ZIP을 수정하지 않았다.

실제 Docker 검증은 다음 순서로 수행했다.

1. 외부 사용자 데이터와 연결되지 않은 새 합성 PostgreSQL과 runtime을 만들고 기존 형식의 34개 종료 주문·4개 미해결 요청을 심었다.
2. 계좌/감사/체크포인트/전체 스키마와 runtime의 지문을 읽고 pg_dump로 논리 사본을 만든 뒤 합성 원본 PG/helper를 정지했다.
3. runtime을 원본 RO → 새 볼륨 RW로 복사했다. 별도 새 PG에 논리 자료를 복원하고, 시계 변경 전 전체 논리 DB/runtime 지문이 원본과 같은지 확인했다.
4. 원본 데이터와 분리된 새 named tmpfs와 key-holder/registrar/read-helper를 만들었다. 호스트 정책으로 fresh ID, 원본 볼륨/ID 금지, RO 키·RO Unix socket·새 runtime만의 마운트, network none, 비 root, 읽기 전용 루트, no-new-privileges, cap drop ALL, restart no, log driver none을 검사했다.
5. 새 복사본에서 V1 시계 전환 및 실제 70초 이상 대기를 마친 뒤에만 키 lease를 열었다. 실제 ro/noexec/nosuid/nodev tmpfs·권한·만료·같은 파일을 확인하고 합성 서명 GET 한 번, 원문/감사 연결과 내용 검사를 수행했다.
6. 키 파일의 바이트 보존, 기간·원장 보존, 복사본 PG의 정상 정지를 확인했다. 합성 원본은 계속 정지 상태였으며 원본 runtime 모든 파일의 해시가 유지됐다. 테스트가 소유한 컨테이너/볼륨만 정리하고 사전 자원 목록과 대조했다.

첫 검증에서는 PG 초기화 도구가 사용자 지정 PGHOST를 무시하고 기본 소켓에 접속해 시작하지 못했다. 원인을 별도 합성 서버 로그로 확인한 뒤, 초기화용 내부 기본 소켓과 helper용 공유 소켓을 함께 열도록 검사 환경을 수정했다. TCP listen은 비워 두며 외부 네트워크는 없다. 실패한 자료를 재사용하지 않고 새 합성 자원으로 재검증했다.

테스트 24개가 통과했다. 새 주간 경계·기존 파이프라인·private archive 회귀 23개(58.01초), 실제 Docker 통합 1개(97.60초)다. ruff와 후보 두 모듈의 mypy도 통과했다. 과거 날짜 프로필·이미 채택된 기간·관측 확인 누락·다른 자격증명·조회 후 날짜 변경을 차단했다. 합성 키와 실제 tmpfs/PostgreSQL을 같은 경로에서 함께 사용했으며 실제 거래소 HTTP는 0건이다.

Docker fixture의 감사 이력은 시계 0→1, 합성 조회 1→3이다. 사용자 Windows에서 관측한 55→56→58과 다른 합성 자료다. Docker 사본은 합성 DB의 논리 복사본이며 실제 Windows의 원시 보존 백업을 새로 복구한 것이 아니다. 실제 사용자 PC·키·파일을 읽거나 변경하지 않았다. 외부 독립 신원·swap 보호·기간 근거·현재 거래소 상태는 미검증이며 채택·설치·주문 승인은 계속 false다. 키 lease의 75초 수명에는 lease를 연 뒤의 검증 시간도 포함되므로 지연 시 실패하고 부분 기록을 보존한다.

실제 결과는 PRIVATE_WEEK_DOCKER_VALIDATION.json, 코드/검사 범위는 PRIVATE_WEEK_VALIDATION.json에 기록했다. 16일용 Windows 실행 패키지는 이번 단계에서 만들지 않았다. 다음 단계는 이 경로를 묶는 16일자 합성 검토 패키지 준비다. 현재 실행할 추가 명령은 없으며 기존 사본 정지와 USB 분리를 유지한다.
