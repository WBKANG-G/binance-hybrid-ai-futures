# V2 전체 스냅샷과 쓰기 실패 경계 검토

2026-11-14 후속 개발 검토를 완료했다. 기존 `demo_` 접두사 기반 지문은 V2 증거 테이블 및 함수·트리거 변경을 놓칠 수 있었다. 기존 운영 검사 파일을 교체하지 않고 `services/execution/demo_evidence_snapshot.py`에 별도의 읽기 전용 검사 후보를 추가했다. 이 후보와 수정된 V2 검증은 Windows에 설치하지 않았다.

새 검사는 `current_schema()` 안의 모든 지원되는 테이블을 이름 접두사와 관계없이 포함한다. 기본 키 순서로 행을 읽고 길이와 해시를 누적한다. 네임스페이스 소유자/ACL, 테이블 속성과 ACL, 열·타입·기본값·NOT NULL, 기본 키·외래 키·기타 제약조건, 인덱스 정의와 유효성, 트리거 정의와 활성 상태, 함수/프로시저 정의와 소유자/ACL, enum, RLS 정책, rewrite rule도 지문에 포함한다. 각 카탈로그 객체의 지문을 별도로 돌려주므로 새 객체 추가 뒤 기존 객체 정의가 그대로인지 대조할 수 있다. PostgreSQL 18의 `pg_constraint` NOT NULL 항목도 포함한다.

테이블은 명시적으로 현재 스키마를 지정하고 식별자를 인용하여 읽는다. DB 트랜잭션은 REPEATABLE READ/READ ONLY이며 문장·잠금 제한을 둔다. 행당 16 MiB 초과 내용은 본문을 전송하지 않고 거부한다. 시간 60초, 테이블 100개, 테이블별 행 100만개, 전체 DB 직렬화 바이트 128 MiB, 카탈로그 섹션별 4096행/4 MiB 한도를 검사한다. 파일은 지정된 비공개 디렉터리 아래의 일반 파일만 해시하고 symlink 및 WAL/SHM/journal을 거부하며 128개/128 MiB로 제한한다. 응답 본문·계좌 값·함수 원문을 반환하지 않는다.

시퀀스, 뷰, 외부 테이블, unlogged/partitioned 테이블, 상속, RLS가 활성화된 테이블, 기본 키 없는 테이블, 지원하지 않는 타입·루틴은 누락하지 않고 중단한다. 이 검사는 현재 스키마와 지정 디렉터리의 비교 지문이다. 복구 가능한 백업, 외부 스키마/전체 클러스터 의존성 검증, 권한 안전성 증명, 원본 writer 정지 검증으로 표시하지 않는다. DB와 파일은 서로 다른 시점에 관측하므로 두 저장소 전체의 원자성을 주장하지 않는다. 지문 일치가 실행 승인을 의미하지도 않는다.

V2 실행 전 `_schema` 검증도 강화했다. 두 테이블의 열 이름·순서·타입·nullable·기본값·identity/computed, 기본 키, 외래 키 대상과 옵션, 추가 check/unique/index 유무를 예상 정의와 비교한다. 기존 불변 트리거 검증을 유지한다. 열 추가·타입 확대·NOT NULL 해제·외래 키 제거·추가 인덱스/제약조건을 주입한 검사에서 sender 호출 전에 거부했다.

실제 PostgreSQL·SQLite·독립 파일을 사용하는 합성 테스트에서 다음을 확인했다.

- V2 행·함수·트리거·열·외래 키·인덱스·접두사 없는 테이블·enum 변경을 새 지문이 탐지했다. 같은 변경을 과거 접두사 검사는 놓쳤다. rewrite rule과 파일만 변경된 경우도 탐지했다.
- 연결 적용은 기존 모든 테이블 내용과 기존 카탈로그 객체 지문을 보존했다. 추가 내용은 V2 테이블 2개, 바인딩 1행, 이벤트 0행, 함수 1개, 불변 트리거 2개, 기본 키 인덱스 2개와 해당 제약조건, 새 확인 파일 1개였다.
- 연결 시 확인 파일 쓰기 전/후 오류에서 PG 스키마와 바인딩이 롤백됐다. 남은 확인 파일은 그대로 보존하고 다음 적용을 차단했다.
- RESERVE/FINISH 각각에서 0바이트 write, fsync 실패, fsync 직후 실패를 주입했다. 전송 객체는 실패 뒤 중단하고 재호출로 두 번째 전송을 하지 않았다. 부분/완전 파일 기록과 PG 사이 불일치는 재열기를 차단했고 자동 삭제·수정·복구를 하지 않았다.
- 파일이 전혀 기록되지 않은 RESERVE 실패는 전체 롤백이 가능하므로 정상 무결성 검토와 명시적인 새 객체 생성까지 거부할 이유는 없다. 실제 재전송은 하지 않았다. FINISH 실패가 확인 파일에 아무것도 남기지 않았어도 이미 전송된 요청의 RESERVE 기록은 남고, 새 transport는 미완료 요청 때문에 차단됐다.

관련 테스트 112개의 통과를 확인했다. 최종 스냅샷·실패 경계 35개와 기준 이미지 3/4개 후보 메모리 import 검사 2개를 마지막 변경 후 재검증했다. 나머지 관련 회귀 75개는 직전 108개 실행에서 통과했다. 이미지 검사는 네트워크/DB/파일 쓰기 시도 0회이며 기준 파일 89개와 기본 거부 6개를 확인했다. lint와 변경 소스 2개의 타입 검사도 통과했다. 상세 실행 기록은 `GET_FULL_SNAPSHOT_VALIDATION.json`에 있다.

실제 Windows 설치나 원본 writable layer 검증, 실제 GET, 별도 PC 검증은 수행하지 않았다. 테스트용 DB는 다시 정지했다. 원본·보존된 복구 사본·분리된 USB의 상태 변경을 요청하지 않았다.

다음 검토 대상은 원본의 마지막 계좌 일자 2026-11-13과 현재 일자, 변경된 부팅/시계의 처리 설계다. 원본 재시작이나 자동 날짜 채택·CLOCK_REBASE를 실행하지 않고, 복사본에서만 검증할 절차를 먼저 준비해야 한다. Windows 최신 이미지/컨테이너/저장소 정체성 및 실제 writer 정지 확인, 원격 계좌·주문 사용량·IP 용량·요청 비용 상한 등의 설치/실행 조건도 남아 있다. 설치 준비와 거래 실행 승인은 계속 false다.
