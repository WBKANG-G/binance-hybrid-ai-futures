# 보존 이후 확인 상태와 다음 격리 검토

사용자 화면에서 원본 보존 사본의 해시 검증, 새 볼륨에서의 복구와 READ ONLY 계좌 검사, D: exFAT 외장 매체의 파일 10개 복사 및 해시 대조 완료를 관측했다. 사용자는 외장 장치의 분리 완료를 확인했고, 별도 Windows PC는 없다고 답했다. 이 기록은 직접 Windows 접근이나 물리적 보관의 독립 확인을 의미하지 않는다. 별도 PC 재검증, 별도 보관 위치의 명시적 확인, 최신 참조의 독립 보관 검증은 미완료로 남긴다. USB를 다시 연결하도록 요구하지 않는다.

상세 관측과 확인 수준은 POST_BACKUP_STATUS.json에 구분했다. 과거 2026-11-13 계획 문서와 당시 인벤토리는 이력으로 유지한다. 외장 복사본이 있다는 이유로 전체 재무 증명, 원격 계좌 정체성, 미해결 요청 해소나 거래 준비 완료를 인정하지 않는다.

다음 범위는 API 기준 이미지의 파일 89개와 조회 감사 후보 2개의 import/기본 차단 호환성 검사다. 후보 두 개는 `packages/persistence/demo_response_evidence.py`, `services/execution/demo_response_evidence_transport.py`이며 메모리에만 올린다. 원본 및 복구 사본은 정지 상태로 유지하고, 검토 컨테이너에는 원본 볼륨·DB·키 세션을 연결하지 않는다. 기준 이미지 검증은 원본 컨테이너의 writable layer 전체 검증과 구분한다.

검토 컨테이너는 네트워크 없음, 읽기 전용 루트, 비 root 계정으로만 실행한다. 상속된 이미지 환경 변수를 제거하며 자격 증명 값을 출력하지 않는다. 기본 전송/저널 생성 거부, 명시적 schema provision/bind 옵션 요구, 잘못된 provider 거부를 확인한다. 코드 설치, 스키마 생성, DB 연결, 저널 쓰기, 실제 GET은 없다.

통과 이후에도 실제 설치는 준비되지 않았다. 명시적 GET 부트스트랩, 재시작 및 시계 변경 정책, 새 테이블/함수/트리거까지 포함한 스냅샷, 기록 전후 실패 경계 검토가 필요하다. 합성 wire/checkpoint 모듈과 기존 demo.py 변경은 실제 Windows GET 설치 대상에서 계속 제외한다. 원본 writer 자동 재개, 기록 소급 채우기, 과거 요청 재실행/보관/정리는 허용하지 않는다.

2026-11-14 후속 기록: 사용자의 Windows 화면에서 위 2개 후보 검토 통과를 확인했다. 이어 명시적 GET 연결과 재시작·시계 변경 시 차단 정책 후보를 구현하고 개발 환경 테스트 95개를 통과했다. 상세 결과와 남은 설치 조건은 `GET_BOOTSTRAP_AND_CLOCK_POLICY_KO.md`, `GET_BOOTSTRAP_VALIDATION.json`에 기록했다. 앞의 2개 후보 Windows 결과는 수정된 후보 3개의 Windows 실행을 증명하지 않는다.
