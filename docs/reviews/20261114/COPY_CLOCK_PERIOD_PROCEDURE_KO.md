# 복사본 전용 날짜·부팅 변경 처리 절차 검토

이번 단계는 새 합성 테스트 스키마와 비공개 임시 파일을 사용하는 개발 환경 검증이다. 실제 Windows 원본, 보존된 복구 사본, 분리된 USB에 접근하거나 실행하지 않았다. 따라서 사용자의 Windows 문제를 이미 복구했다고 표시하지 않는다.

`services/execution/demo_copy_transition_review.py`에 변경 없는 진단 후보를 추가했다. 명시적인 복사본 검토 옵션을 요구하고, DEMO 환경·설치 ID·계좌 저장소 바인딩을 확인한다. 현재 스키마 및 지정 파일의 지문을 검토 전후 대조하고, PG/SQLite를 읽기 전용으로 열어 V1 감사 기록·복구 증거·V2 바인딩/확인 파일을 검증한다. 날짜와 시계가 맞지 않아 일반 저널 생성이 중단되는 상태에서도 저장된 기록을 그대로 읽어 원인을 구분한다. 검토 중 부팅·시계 변경, 한국 날짜 경계 통과, 저장 상태 변경이 있으면 성공 보고를 거부한다.

보고서는 저장된/현재 한국 일·주 키, 부팅/시계 일치 여부, 미완료 조회 수, 역사적 미해결 주문 요청 수와 차단 사유를 반환한다. 계좌 잔액·서명·키·요청 원문·부팅 ID 원문은 반환하지 않는다. 일시 정지/NORMAL, 소유자/lease, 로컬 노출, 시작 대기, stopped flag도 각각 검사한다. 어느 차단 사유가 없어도 설치나 거래 실행을 승인하지 않는다.

`copy_only_review=True`는 호출자의 확인이며, 독립적인 Docker 격리 증명이 아니다. 진단은 writer 정지나 원본과 복사본의 볼륨 분리를 입증하지 않는다. 실제 Windows 실행기는 아직 제공하지 않았으며 이 옵션만으로 원본에서 실행해서는 안 된다.

기존 `recover_completed_read_clock`에는 V2 차단 가드를 추가했다. 해당 scope에 V2 바인딩 또는 확인 파일이 있으면 V1 `CLOCK_REBASE`를 거부한다. 불완전한 V2 스키마도 거부한다. 가드는 복구 intent 생성과 영구 데이터 변경 전에 검사한다. 다른 scope에서 완전한 V2 스키마만 공유하고 해당 scope의 바인딩/확인 파일이 없다면 기존 V1 경로는 유지한다. V2 이벤트를 꾸며내거나 확인 파일을 삭제해서 기존 복구를 강제로 통과시키지 않는다. 이 소스 변경도 실제 Windows에는 설치하지 않았다.

합성 리허설은 다음 두 경로를 구분했다.

1. **V2 미연결 + 완전한 V1 조회 이력:** 새 테스트 스키마에서 실제 V1 명시적 시계 복구 코드를 실행했다. 감사/체크포인트/보관 증거를 추가하고 전체 시작 대기를 다시 요구했다. 계좌 데이터와 날짜 기준은 바꾸지 않았다. 대기 후 시계가 정상이어도 오래된 계좌 일자와 미해결 요청 4개가 그대로 남았고, V2 연결은 기간 불일치로 차단됐다.
2. **V2 연결됨:** 복사본 진단은 V2 시계 전환 미지원 사유를 보고한다. 기존 V1 복구를 호출해도 새 가드가 거부하며 파일·DB 지문을 그대로 보존한다. V2용 감사 이벤트·확인 파일·체크포인트 전환 계약 없이 우회하지 않는다.

실제 Windows에서 나중에 사용할 절차는 아래 순서로 준비해야 한다. 아직 실행 명령이 아니다.

1. PC 내부의 고정된 백업/복구 영수증과 입력 해시를 검증한다. USB 재연결은 필요하지 않다.
2. 기존 원본과 보존된 복구 사본은 계속 정지시킨다. 새 임시 복사 볼륨/컨테이너만 생성하며, 원본 볼륨·키 세션과 분리된 정체성 및 마운트·라벨을 독립 검증한다.
3. 새 임시 PG 복사본만 네트워크 없이 실행한다. 계좌/감사 진단은 읽기 전용으로 하고 입력 백업 해시는 전후 다시 확인한다. 작업 후 임시 복사본을 정지시킨다.
4. V2 미연결 여부를 실제 복사본에서 확인한다. 미완료 조회·불완전 증거가 있으면 시계 복구를 하지 않는다. 허용된 경우에도 복사본에서 명시적 V1 시계 전환만 리허설하고, 전체 시작 대기와 이력·누적 비용 보존을 확인한다.
5. 날짜 문제는 별도 처리한다. 기존 2026-11-13 기준 금액을 현재 날짜 기준으로 복사하지 않는다. 새로운 날짜의 기준에 필요한 계좌 정체성에 연결된 증거, 입출금·손익 범위, 관측 시각과 원자성 한계, 명시적 채택 범위를 먼저 검토해야 한다. 미해결 요청 4개는 로컬 flat이나 날짜 전환만으로 해소하지 않는다.
6. 원본에 적용할 단계는 새 복사본 리허설과 최신 원본 정체성/정지 확인 이후 별도로 검토한다. 자동 원본 재시작·재시도·주문 전송은 없다.

이전 Windows 화면상 마지막 계좌 일자는 2026-11-13이며 당시 V2 후보는 설치되지 않았다. 현재의 실제 설치/부팅 상태를 새로 조사한 결과는 아니다. V1 경로를 실제 원본에서 지금 실행하라는 근거로 사용하지 않는다.

검증 결과와 실행 범위는 `COPY_TRANSITION_VALIDATION.json`에 기록한다. 다음 범위는 고정된 로컬 백업으로 **새 임시 복사본만** 준비하는 Windows 격리 실행기다. 기존 복구 사본을 재사용해 시작하거나 USB를 다시 연결할 필요는 없다. 설치 준비 및 실행 승인은 계속 false다.
