# 비공개 문의 초안 준비

사용자가 제시한 보정 영수증에서 실제 변경은 로컬 포지션 CLOSED, open_quantity 및
actual_risk 0이었다. 주문은 CANCELED, filled 0, exit_state UNKNOWN으로 유지됐고,
EXIT 요청 SUBMITTING과 STOP_LOSS 요청 UNKNOWN도 유지됐다. 전송 여부나 체결을
해소할 근거로 사용할 수 없다. 수치는 동봉 관측 JSON에 기록했다.

기존 스냅샷, 원래 요청 조회 보고서, 네트워크 없는 복사본의 저장 이벤트를 이미 대조했다.
여기서 추가 로컬 검사를 반복해도 역사적 HTTP 전송 여부는 확인할 수 없다. 따라서
고정된 과거 백업에서 두 원래 식별자를 가져와 사용자 PC의 비공개 문의 초안을 준비한다.
로그인된 공식 지원 채널에 사용자가 직접 전달하기 전까지 외부 전송은 없다.
현재 거래소 조회 보관 정책은 독립 검증하지 못했다. 문의에서 그 범위도 질문한다.

새 패키지는 기존 검증된 읽기 코어를 f3f8e44d11bb4696fe06fc38aed4da14f52837e0에서
그대로 재사용한다. 명시적 확인/생성 모드, 원본 해시 재확인, 두 대상의 요청 해시와
과거 조회 보고서 연결, 동일 진입 주문 연결을 요구한다. 원래 ID는 새 비공개 초안에만
기록한다. 콘솔·영수증에는 ID를 기록하지 않는다. 생성 파일은 CreateNew로 열어
덮어쓰기를 거부하며 읽기 검증 실패 시 성공으로 표시하지 않는다.

합성 자료의 PowerShell 검증은 Windows ACL 검증을 대신하지 않는다. Windows
PowerShell 5.1 실제 실행과 ACL 생성은 아직 사용자 PC에서 확인하지 않았다.
원본·복사본 정지, USB 분리, 기준금액·요청 상태 보존을 유지한다.
