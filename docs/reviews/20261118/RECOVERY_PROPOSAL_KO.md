# 데모 원장 복구 제안 — 2026년 11월 18일

이 문서는 적용 전 검토안이다. 원장·계정 설정·서비스 상태를 변경하는 실행 파일은 포함하지 않는다.
고객지원 문의 없이 진행할 수 있는 다음 작업은 기존 로컬 자료로 복구 미리보기를 만드는 것이다.
과거 요청의 거래소 처리 결과가 모두 입증되었다거나 지금 거래를 재개할 수 있다는 뜻은 아니다.

## 확인된 현재 상태

사용자 Windows 실행 화면에서 전체 종목 일반/알고 미체결과 포지션이 두 차례 모두 0으로
보고되었다. USDT 지갑·가용·마진 잔액은 각각 4998.74183608, 미실현손익과 초기증거금은 0이다.
One-way·단일 자산 모드, BTCUSDT 격리 2배·자동 증거금 추가 꺼짐이 두 관측에서 일치한다.
기존 자료 이후 income 및 BTC 체결 공백 조회도 0건이다.
이는 화면에 보고된 결과이며 이 환경에서 Windows 원본 파일을 직접 검증한 결과는 아니다.
여러 조회는 원자적이지 않고, 관측 종료 이후 활동까지 보증하지 않는다.

## 기존 적용 함수를 그대로 사용할 수 없는 이유

`services/execution/demo_period_review.py`는 원장 last_reconciled와 value.as_of가 일치하고,
그 기준 시점부터 현재까지 최대 7일인 경우만 허용한다. 저장된 평가 시점
2026-11-06T07:25:25.109073Z는 11월 18일에 이미 이 범위를 넘는다.
저장 보고서의 날짜를 평가 시점으로 대신 사용하거나, 타임스탬프를 새로 써서 통과시켜서는 안 된다.
현재 잔액이 같다는 사실만으로 기존 적용 함수를 실행할 근거가 되지 않는다.
기존 함수의 다른 조건까지 모두 통과했다고 검증한 것도 아니다.

## 다음 구현 작업

1. 네트워크와 자격증명 입력 없이 고정 백업, income → trade → current 영수증과 원문 해시를
   연결하는 오프라인 미리보기를 만든다. 중복 실행 폴더, 해시 불일치, 날짜·계정 불일치는 중단한다.
2. 중지된 실제 원장과 백업의 동일성을 확인하고, 일·주 키/기준금액 변경 전후와
   보존 대상 34건·미확정 4건·고점·누적 손익을 명시한다. 현재 원장을 확인하기 전에는 적용 토큰을 만들지 않는다.
3. 7일 범위 밖의 기간 처리 방식은 기존 검증을 완화하지 않는 별도 설계와 테스트가 필요하다.
   운영자 진술을 근거로 채택할 항목과 입증하지 못한 항목을 명시한 뒤 적용 승인을 받는다.
4. ENTRY 두 건의 상태를 바꾸려면 원래 요청 식별자에 대한 감사 가능한 거래소 대조 절차를
   별도로 설계한다. EXIT/STOP_LOSS는 시간·수량이 비슷한 다른 주문과 연결하지 않는다.

과거 요청을 영구 재전송 금지 상태로 격리하거나 새로운 회계 기간으로 분리하는 방법도
설계 대안이지만, 현재 코드에 이미 지원되는 기능은 아니다. 동일 거래소 계정을 로컬에서
이름만 바꿔 미확정 요청 검사를 피하는 방법은 제안하지 않는다. 새로운 정책의 정의·감사 보존·
재전송 방지·위험 한도 연속성 검토가 선행되어야 하며 이 문서로 승인되거나 적용되지 않는다.
