# 중지된 원본의 백업 동일성 비교

사용자는 오프라인 복구 미리보기 성공 결과를 보내고 다음 단계 진행을 지시했다.
현재 원본 DB를 시작하지 않은 상태에서 원장 SQL 행을 직접 조회할 수는 없다.
이를 시작한 것으로 표시하거나 고정 백업의 old_row를 현재 행으로 대신하지 않는다.
이번 구현 범위는 원본 DB/runtime 물리 파일과 고정 백업 manifest의 동일성 검사다.
행 단위 금융 diff 확정은 이 결과와 별도 사본 복구의 원장 보고서를 연결하는 후속 작업이다.

보존 영수증·state·manifest·두 tar·images의 고정 SHA256, NTFS ACL, 원본 중지/재시작 no,
계정 보존 당시의 컨테이너 ID·서비스 역할·볼륨·이미지·외부 소비자 검증을 기존 고정 함수에서
재사용한다. 관련 함수만 추출하며 원본 start/stop/update/rm, 복구/복사 writer는 포함하지 않는다.

사전 검사에서는 생성하지 않는다. 실행 시 새 읽기 전용 helper 하나만 만들고 그 ID가
원본 ID가 아닌지, 캐시 이미지·mount두개·RO·networknone·rootRO·cap·사용자·entrypoint가
정확한지 확인한 뒤 해당 helper ID만 시작한다. Docker 버전에 따라 DAC_OVERRIDE가
CAP_DAC_OVERRIDE로 보고될 수 있어 두 정확한 표기만 허용한다. 권한 추가를 일반 허용하지 않는다.
키/환경변수/시크릿 마운트는 읽지 않는다. 새 볼륨·새 백업 파일·SQL 서버는 만들지 않는다.

worker는 dirfd/O_NOFOLLOW로 두 트리를 각각 두 번 순회한다. 파일 집합·종류·크기·SHA256,
uid/gid/mode/mtime, hardlink/특수 파일·확장 속성 금지, 읽기 전후 inode/ctime 정합성,
깊이·개수·바이트·120초 제한을 검사한다. PG PID/WAL을 그대로 비교하며 수정하지 않는다.
원본 정지·전체 컨테이너 구성, 입력 백업 해시를 작업 후 재검사한다. 원본 볼륨은 읽기 전용이며
Docker metadata에는 helper 생성/실행 기록이 남는다. helper는 완료 후 정지 상태로 보존한다.

실패/통신 단절 시 생성된 helper ID를 보고하며 자동 재실행·삭제·원본 재시작을 하지 않는다.
성공은 원본 파일이 고정 백업과 같다는 뜻이다. 현재 DB의 SQL/원장 상태가 직접 조회되었다거나
실행 중 변동을 원자적으로 배제했다는 뜻은 아니다. Docker 외부 제어권의 동시 악의적 변경을
배제할 수 없다는 운영 한계가 있다. 승인·기준금액 채택·요청 해소·거래 재개는 수행하지 않는다.

시험은 합성 파일 및 Docker 테스트 자원만 사용한다. 사용자 원본은 여기서 접근하지 않는다.
Linux 원문 파일 비교와 helper admission을 실제 Docker로 확인하며 Windows5.1·NTFS ACL 양성
검사는 사용자 실행 결과를 관측하기 전까지 검증되었다고 표시하지 않는다.
