# 완료 감사 모델과 사본 메모리 리허설 준비

사용자의 다음 단계 지시는 모델 구현과 사본 리허설 준비 범위로 수행한다. 출처 수락이나
원본 적용 승인으로 확대하지 않는다. AGENTS의 잠금 사양과 기존 7일 제한은 변경하지 않는다.

새 PeriodCompletionAudit는 별도 policy의 엄격한 형식이다. operation UUIDv4, 초안·증거·
원문/후보 지문, 이전/새 기간 필드, fence 증가1, 별도 수락 기록 지문, UTC 시각을 담는다.
실제 수락과 적용을 주장하는 형식이므로 bool은 정수/문자열을 허용하지 않는다.
자정 평가·전체 계정 이력·최초 자금의 독립 증명과 거래 승인은 false로 고정한다.
형식 검사 자체가 수락이나 DB 커밋의 사실 증명은 아니다.

기존 미승인 초안 모델과 분리했다. 운영용 검사 함수는 ACCEPTED_APPLICATION 문맥과
호출자가 별도로 검증한 수락 기록 지문을 요구한다. 이 함수는 저장/API가 아니며 실제
수락 기록의 수집·검증·권한 확인 절차는 아직 구현하지 않았다. 코드에 모델이 있다는 사실을
실제 적용 경로가 설치되었다거나 완료 영수증이 작성되었다는 뜻으로 해석하지 않는다.

현재 리허설은 COPY_REHEARSAL_ONLY 문맥의 테스트 기록과 후보 원장을 메모리에서 구성한다.
가상 applied/source_accepted=true 값을 사용하지만 실제 적용 검사는 같은 지문을 넘겨도
문맥 때문에 거부해야 한다. 재현 가능한 가상 operation/출처 지문과1970년 시각은 테스트 전용이다.
실제 결과의 source_accepted/database_changed/baseline_adopted는 false다. 기록 원문/적용
payload는 반환하거나 파일로 저장하지 않는다. 출력은 검증 성공 여부와 기존 안전한 지문뿐이다.

고정 effbee73 typed-draft 패키지의 사본 복원·원본 정지 검사·입력 파일 잠금·읽기 전용 SQL·
89개 설치 파일 검사·networknone/비특권 helper·정상 사본 종료 경로를 재사용한다.
검증 모듈은 기존 모델과 새 모듈을 단일 메모리 payload로 묶고 전송 manifest에 해시를 고정한다.
새 모델은 이전 감사 함수를 별도 이름으로 보존한 뒤 추가 검사한다. 기존 helper의 SQL,
복원 worker와 원본 마운트/정지 검사 코드는 바이트 동일하다. 원본의 새 writer는 만들지 않는다.

새 완료 기록은 기존 원장에서 출발한 별도 메모리 후보에만 추가한다. 앞서 만든 미승인 초안을
덮어쓰거나 DB에 남기지 않는다. 일/주 키와 금액, 정합성/스트림 해제 및 새 가상 감사 기록 밖의
모든 원문 JSON과 이전 operations를 보존한다. DemoLedger로 후보 전체도 검증한다.

이번 Windows 실행은 실제 백업 사본의 원문을 이용한 메모리 리허설이다. 사본 DB 자체에
원장·이벤트·outbox를 COMMIT하는 리허설과 원본 적용은 포함하지 않는다. 실제 트랜잭션 검증은
앞선 합성 pg_temp 실험20건이며, 이를 실제 백업 사본 COMMIT 성공으로 표현하지 않는다.
향후에는 별도 수락 경계와 전용 원자적 저장 경로를 구현·검증하고, 실제 적용 직전의 날짜,
원장/버전/정지 상태와 계정 관측을 다시 검토해야 한다. 과거4개 요청 해소나 거래 재개는 별도다.

테스트는 엄격한 타입/추가 주장 거부, 초안과 완료 형식 분리, 실제 수락 기록 없을 때 거부,
리허설 기록의 실적용 거부, 원문 보존, 기존 SQL/복원 코드 동일성, 실제 PostgreSQL/89파일 API
이미지/PowerShell helper의 전체 payload 및 결과 승인 경로를 검증한다. 최종 ZIP에서도 검사한다.
실제 Windows5.1/NTFS 및 사용자 백업 전체 실행 결과는 사용자 관측 전까지 미검증이다.
