# 현재 일반·알고 미체결과 설정의 반복 관측

사용자는 BTCUSDT 체결 대조 성공 화면을 보냈다. 0건, 기존 자금 자료와 비0 손익/수수료
불일치 없음, HTTP 5회, 원장 미변경으로 보고했다. 원본 직접 접근이 아닌 화면 관측이며
계정 전체 과거 이력·자정 평가액·미확정 요청 해소를 뜻하지 않는다. 다음 단계 지시에 따라
새 현재 상태 조회 패키지를 준비한다.

## 보존한 자료의 연결

고정 백업의 계정 대조 기준과 주간 정책을 재사용한다. 기존 성공 income 응답/영수증/시각
창을 해시 대조하고, 같은 income 영수증을 참조하는 성공·빈 BTC 체결 응답을 연결한다.
각각 정확히 하나의 실행을 요구한다. 기존 파일은 읽기 공유 스트림으로 유지하고 새 조회
전후 해시를 다시 검사한다. 원본/복사본/DB/옛 내보내기 guard를 수정하지 않는다.

## 새 조회 범위

같은 데모 키의 서명으로 두 과거 진입 주문을 먼저 대조한다. 계정 모드와 BTCUSDT 설정을
앞뒤 2회, 모든 종목 일반/알고 미체결·positionRisk·account를 2라운드 수집한다.
openOrders/openAlgoOrders/positionRisk에는 symbol 필터를 보내지 않는다. BTC 설정만
symbol=BTCUSDT를 사용한다. One-way·단일 자산·canTrade, BTC 격리 2배·자동 증거금 추가
꺼짐, 미체결/포지션 부재와 USDT 가용·마진·잔고 정합성을 고정 프로필과 비교한다.
설정 불일치/노출/잔고 차이는 issues에 기록하고 취소·설정 변경·자동 보정은 하지 않는다.

기존 income cutoff 이후~마지막 상태 관측 종료 추정 시각의 모든 자산 income과 기존
BTC 체결 조회 종료 이후의 BTC userTrades를 한 페이지씩 조회한다. 빈 공백만 일치로
처리하고 비어 있지 않거나 1000행에 도달하면 불일치/포화로 기록한다. 정확한 원자적
스냅샷/타임스탬프 증명이 아니며 관측 사이의 일시 변화나 종료 이후 활동을 모두 배제하지 않는다.

최대 HTTP 18회, 초기 weight 여유 500, GET 전용, 고정 demo-fapi 호스트, TLS 검증,
리디렉션·자동 재시도·자동 폴링 금지다. all-symbol open 목록은 각각 40 가중치로 두 번씩
계산하며 accountConfig=5, symbolConfig=5, account=5, positionRisk=5, income=30,
userTrades=5 근거를 기존 PINNED_RUNTIME_COST_PROOF에서 재사용한다. 외부 IP 사용량을
완전히 통제하거나 원래 managed journal을 갱신한다고 하지 않는다.

## 결과의 의미

예상 프로필과 두 관측이 일치해도 실행 준비/재개 승인이 아니다. 과거 모든 종목 이력,
경계 시각의 포지션/평가손익, 최초 자금·누적 고점, 미확정 4건의 접수 여부는 별도다.
운영자 무활동 답변을 새 조회 종료까지 자동 연장하지 않는다. 새로운 평탄 스냅샷으로
옛 요청을 NOT_SENT로 바꾸거나 손실한도/고점을 초기화하지 않는다.

현재 조회의 KST 일·주가 보존된 자료와 다르거나 중간에 경계가 바뀌면 중단한다.
보고서에는 현재 관측과 과거 검증의 차이, 비원자적 조회, 미채택/미실행 상태를 표시한다.
오류 시 HTTP 200 원문은 검사 전 새 개인 NTFS 폴더에 보존하고 공개 출력에는 원문이나
client ID/임의 메시지를 내보내지 않는다. 키는 로컬 숨김 입력에만 쓰며 파일/환경변수/명령줄에
저장하지 않는다. 실제 Windows/API 결과는 사용자 실행 전까지 미관측이다.
