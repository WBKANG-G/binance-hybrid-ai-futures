# 복원 원장 보고서와 변경 후보 연결

사용자 화면에서 v2 원본 물리 파일 비교가 2회 성공했다. DB1355·runtime30,
고정 manifest 일치, helper중지, 원본 시작/쓰기 및 HTTP/주문0으로 보고되었다.
로컬 source comparison 영구 영수증을 작성하는 기능은 이전 도구에 없으므로 이 증거는
사용자 화면 관측으로 보존한다. 새 도구가 해당 비교를 독립 재실행했다고 하지 않는다.

이번 패키지는 고정 성공 복원 영수증 SHA256을 파일에서 확인하고 백업 manifest/보존
영수증/복원 source/정상 종료/SQL read-only/paused/기준일·주/주문34·미확정4를 검증한다.
검증된 영수증의 원장 PG지문을 표시하고, 기존 금융·day13채택 보고서와 기준일·수량을
대조한다. 기존 income→trade→current 원문 검증을 재사용해 후보를 같은 출력에 연결한다.

조건부 변경표는 일키 11/13→11/18, 주키 11/09→11/16, 일·주 기준금액
4998.74183608→같은 금액이다. 고점5000·초기5000·잔차realized -1.25816392와
주문34·미확정4는 보존하는 후보이다. 사용자 파일 원본에서 산출되는 값만 출력하며
문서의 기록으로 현재 원장 전체를 새로 검증한 것으로 표시하지 않는다.

중요한 한계: 복원 SQL 영수증은 원장 전체 지문과 key/count만 담고 금액을 담지 않는다.
변경 전 금액은 고정 이전 금융 기록+저장 day13 보고서에서 얻는다. 따라서 전체 현재
금융 diff 검증·새 적용 경로·명시적 기간 source 수락은 여전히 필요하다. PG state::text
지문과 Python canonical JSON commit 지문은 직렬화가 달라 직접 동일 비교하지 않는다.
현재 원본 SQL 조회, apply token, 기준금액 채택, 요청 상태 변경 또는 주문은 없다.

이 패키지는 파일 읽기만 포함한다. Docker/HTTP/키 입력/DB/새파일 쓰기/외부 이관은 없다.
Windows NTFS 보호 ACL과 root-array 호환·원본 해시 재검사를 기존 구현에서 재사용한다.
실제 Windows 실행 성공은 사용자 결과를 관측하기 전까지 표시하지 않는다.
