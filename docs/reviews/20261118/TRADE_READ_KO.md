# 저장된 자금 후보에 대한 BTCUSDT 체결 대조

사용자가 다음 단계 진행을 요청했고, 추가 질문에 11월 16일 이후 직접 거래하거나 다른
프로그램으로 BTCUSDT 이외 종목을 거래한 적이 없다고 답했다. 원문·구간·한계는
OTHER_ACTIVITY_USER_STATEMENT.json에 기록한다. 이 진술을 독립 계정 전체 증명이나
향후 조회 종료까지의 무활동 진술로 확장하지 않는다. 같은 BTC 종목의 다른 봇이 전혀
없었다는 별도 진술로도 확대하지 않는다.

이전 Windows 수집 화면은 일간 11/18·주간 11/16 지갑잔고 후보 4998.74183608,
조회 income 0건, 전후 잔고 동일·포지션 평탄, HTTP 8회로 보고했다. 이것은 평가액
기준금액 확정이나 과거 자정 노출 증명이 아니다. 상세 관측은 별도 JSON에 저장한다.

새 패키지는 기존 자금 응답과 INTENT/WINDOW/영수증을 읽고 모든 로컬 응답 해시를
대조한다. 해당 기간의 성공·0행·평탄·동일 잔고 실행이 정확히 하나여야 한다.
선택에 현재 잔고 금액을 하드코딩하지 않고 실제 보존 원문의 USDT 자산을 다시 검증한다.
원본 파일은 읽기 공유 스트림으로 잡고 새 조회 전후에 해시를 다시 확인한다.

새 API 호출은 데모 GET time/exchangeInfo/계정 대조 진입 2건/userTrades뿐이다.
이전 자금 내역과 계정 스냅샷은 다시 조회하지 않는다. 원래 주간 경계~이번 서버 시각의
BTCUSDT 한 종목이며, 이전 income cutoff 이후 체결도 별도 수로 표시한다. 새 종료는
이전 cutoff보다 최소 5초 뒤여야 한다. 원래 cutoff가 클라이언트 서버시각 추정인 한계는
유지한다. 현 포지션을 새로 갱신했다고 하지 않는다.

userTrades는 startTime/endTime과 fromId를 섞지 않는다. 1000행이면 겹치지 않는
두 시간 구간으로 1회 분할해 추가 조회한다. 절반도 포화면 불완전으로 중단한다.
최대 체결 호출 3회/전체 HTTP 7회, 가중치 여유 100, 7일 구간 제한과 자동 재시도 금지다.

수집 원문은 새 개인 NTFS 폴더에 스키마 검사 전 보관한다. 거래 ID 중복은 제거하되
동일 ID의 재정·종목·시각·방향·포지션 모드·주문번호가 충돌하면 중단한다. 이전 cutoff
이전의 체결 손익/USDT 수수료와 빈 income의 정합성을 비교한다. 손익이나 수수료가
서로 상쇄돼 합계 0이어도 개별 비0 행이 있으면 빈 income과 일치했다고 하지 않는다.
이 합계는 기존 지갑잔고 후보에 다시 합산하지 않는다. 0손익/0수수료 체결도 체결 수에 남는다.

계정 전체 다른 종목의 userTrades·자정 평가손익·현재 전체 노출·보관 완전성은
독립 검증하지 않는다. 빈 BTC 응답을 계좌 전체 무거래/과거 미전송이나 기준금액 채택으로
승격하지 않는다. 미확정 4건, 고점/손실한도, 원본/복사본 정지와 USB 분리를 유지한다.
실제 Windows/API 실행은 사용자 결과 확인 전이며 키는 로컬 숨김 입력에만 사용한다.
