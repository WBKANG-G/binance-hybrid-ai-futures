# PowerShell 5.1 배열 집계 오류와 저장 파일 재분석

사용자 Windows 화면은 두 응답 저장 성공, HTTP 6회, 새 내보내기 0건, 원본/이전 guard
변경 없음으로 보고했다. 그러나 두 목록이 각각 1건·일치 후보 0건으로 출력됐다.
알고 응답의 화면 해시는 UTF8 []의 SHA256과 정확히 일치한다. 따라서 이 실행의
손절 응답 1건 표시는 신뢰할 수 없다. 일반 응답의 실제 행수와 ID 일치 여부도 재검토한다.

네이티브 PowerShell 7에서 ConvertFrom-Json -NoEnumerate로 배열을 한 파이프라인 값으로
전달하면, 이전 @($Body|ConvertFrom-Json)은 []도 Object[] 하나로 집계했다. 이 배열은
-is [pscustomobject] 검사도 통과한다. 이전 코드의 Count=1을 재현했고 수정 후 0을 확인했다.
이것은 Windows 5.1 실행 자체를 클라우드에서 수행한 것이 아니라 동등한 출력 열거 동작의
재현이다. 사용자 화면과 빈 배열 해시가 실제 Windows 오류의 근거다.

수정은 루트 JSON의 문법을 먼저 검사하고 객체의 배열 속성으로 파싱해 명령 파이프라인
열거와 분리한다. 0/1/여러 행을 동일하게 처리하며 실제 PSCustomObject 행만 허용한다.
원래 배열 JSON의 유효성 검사 없이 래퍼 문자열만 파싱해 외부 속성을 주입하는 경우도
거부한다. 수정한 함수는 향후 수집기와 새 오프라인 실행기에 같은 바이트로 사용한다.

후속 패키지는 기존 응답·영수증·INTENT와 고정 백업만 읽는다. 원래 조회기를 다시
실행하지 않는다. 보호 ACL, 최대 32개 후보, 파일 크기 제한·읽기 공유 잠금·전후 해시,
로컬 영수증과 두 응답의 연결을 확인한다. 화면에서 확인한 [] 알고 해시로 기존 실행을
정확히 하나 선택한다. 일반 해시는 로컬 영수증과 대조하는 수준이며 별도 외부 독립
해시로 승격하지 않는다. 여러 실행이 일치하면 임의 선택하지 않고 중단한다.

출력은 새 건수/ID 후보 수와 제한된 숫자·열거형 주문 필드다. 원래 client ID·임의 필드·
오류 원문은 표시하지 않는다. 일반 미리보기는 20행, 정확한 ID 후보 미리보기는 10행까지다.
정확한 후보가 있어도 상태/체결/원장 해소 검증 완료나 재개 승인으로 바꾸지 않는다.
빈 결과는 미전송·전체 이력 완전성을 증명하지 않는다. 기존 내보내기 생성도 미확정으로 보존한다.

키 입력·접근·HTTP·Docker·보고서 쓰기·원본 변경이 없는 로컬 재분석이며 실제 Windows
성공은 실행 화면 확인 전까지 미관측이다. 원본·복사본 정지와 USB 분리를 유지한다.
