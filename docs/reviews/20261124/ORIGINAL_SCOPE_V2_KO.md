# 원본 범위 사전 점검의 오류 표시 수정

사용자 화면은 전송 무결성 통과 후 SCOPE_CHECK_BLOCKED,원본 시작/변경false,주문0이었다.
실제 사용자 원문 파일이나 오류 원문은 접근하지 않았다. 현재 화면만으로 어느 guard나 API가
실패했는지 확정할 수 없다. 이전49개 검사는 Docker/원본 범위를 fixture로 대체했으므로 실제
사용자 환경의 전체 호환성을 증명한 것이 아니었다.

확인한 코드 결함은 catch 코드 허용 접두어에COMPARE가 빠진 것이다. 실제 Read-CopySources,
Container-Ids,Assert-CompareHelper를 유지하고 합성 helper 상태만 허용하지 않는 값으로
설정한 native PowerShell 회귀에서 v1의SCOPE_CHECK_BLOCKED를 재현했다. v2는 같은 guard의
COMPARE_HELPER_SCOPE_INVALID를 보존한다. 이 합성 예가 사용자 helper가 실행 중이라는
진단은 아니다. 사용자 실제 중단 원인은 여전히 미확정이다.

새 단계 표시는 전송/모듈 로드/설정/수락/백업 찾기/영수증/초기 해시/RO 잠금/잠금 후 해시/
백업 상태/원본 범위/컨테이너 재검사/최종 해시를 구분한다. failure_script는 manifest의 알려진
파일 basename에 속하는 경우에만 내보내고 줄 번호를 붙인다. 예외 종류도 공개된 고정 목록에
있을 때만 표시한다. 로드 실패는 알려진 모듈 이름만 표시한다. 원문 메시지·전체 사용자 경로·
실패 명령명/속성명/TargetObject/StackTrace는 출력하지 않는다.

원본/백업/이미지/마운트/RO helper/정지 guard 파일과 기준은 그대로다. 전송/수락 해시도 다시
고정한다. 입력 실패를 우회하거나 이름/라벨 allowlist를 넓히지 않는다. 새 컨테이너·원본 DB·
SQL·HTTP·파일 쓰기 동작을 추가하지 않는다. 실패 시false 권한/중지 상태를 그대로 반환한다.

v2는 진단과 확인 가능한 오류 표시 결함 수정이다. 모든 사용자 환경 문제가 해결됐다고
주장하지 않는다. 새 Windows 결과의 단계/코드/공개 예외 종류/줄 번호로 실제 원인을 확정하고
필요한 호환성 수정만 이어가야 한다. 기존 v1폴더와 자료를 덮어쓰거나 임의로 재시도하지 않는다.
