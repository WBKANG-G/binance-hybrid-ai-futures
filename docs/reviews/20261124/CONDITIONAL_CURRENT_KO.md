# 최신 계정 관측에 승인된 소스 조건 연결

사용자 Windows 화면에서 source-refresh 두 차례 비교 성공을 관측했다. DB 1,355개와 런타임 30개 파일의 내용·메타데이터 일치, 원본 변경 없음 및 기존 helper 정상 종료가 보고됐다. 이 결과는 별도 JSON에 화면 관측으로 기록한다. 클라우드에서 사용자의 원본 파일·비공개 보고서를 직접 확인한 것은 아니다. 새 묶음에는 이 문맥을 연결하되 파일 비교나 원본 SQL 검증을 새로 수행했다고 표시하지 않는다.

사용자의 다음 단계 지시에 따라 DEMO 최신 GET 관측과 기존 조건부 소스 승인 연결을 준비한다. 11월 24일 승인된 고정 금액 4998.74183608 USDT, 주차 11월 23일 및 24~29일 범위만 사용한다. 이전 18일/16일 증빙 키를 새 승인 기간으로 덮어쓰지 않으며 saved_reference, accepted, observed, candidate 기간을 구별한다. 승인 원문·후보·범위·미확인 사실은 고정 해시로 봉인하고 Python 원본 검증기로 빌드 시 검사한다.

기존 서버 호스트·경로·GET·서명·키 입력·시간 제한·응답 한도·가중치·계정 앵커 검증을 유지한다. 18개 기존 요청에 마지막 공개 서버 시간 GET 하나만 추가해 총 예산을 19로 변경한다. 60초 세션 제한은 그대로 유지한다. 계정 전체 일반/알고 미체결 및 포지션, 잔액 두 차례, BTC 설정 두 차례, 기존 소득·체결 cutoff 이후 빈 구간과 페이지 포화 여부를 검사한다. 최종 서버 시간과 관측 시작·종료 사이 5분 및 날짜 일치를 확인하고 양쪽 참조의 7일 제한을 각각 유지한다. 따라서 승인 범위가 29일까지여도 기존 증빙의 7일 한계를 넘으면 중단한다.

관측 후 원본 증빙 해시와 새로 저장한 14개 응답 해시·정확한 파일 집합을 다시 검사한다. 결과 파일 저장 실패 시 승인 연결 성공 플래그를 지우고 런처도 완전한 관측과 연결 성공을 모두 요구한다. 실패는 고정 오류 코드만 출력하고 비공개 응답·식별자·키·상세 예외를 출력하지 않는다. 실패 후 자동 재시도하지 않는다.

조건 판정은 고정 Python 소스 정책과 동등한 PowerShell 구현이며 서로 비교하는 테스트를 포함한다. 실제 API 대신 합성 GET 응답으로 네이티브 PowerShell 서명·경로·요청 예산·오류 경로를 검증한다. 성공 시에도 이는 해당 관측에 대한 소스 승인 연결일 뿐 장기 유효한 apply 토큰이 아니다. 후속 원본 쓰기 준비에는 다시 최신성·원본 상태/fence·소유권 프로토콜 검증이 필요하다.

원본 DB/API/key-session, Docker, 다른 복사본은 시작하지 않는다. 원본 파일·DB, 주문 상태, 과거 요청 4건, 34개 주문, 손익 및 high-water는 변경하지 않는다. 현재 flat 관측이나 빈 거래내역이 과거 요청 미전송·해소를 증명하지 않으며 전체 과거 체결·자정 평가액·초기 자금 출처도 미검증 상태다. 원본 시작·쓰기·소유권 인수·가드 우회·재전송·주문·실거래 권한은 생성하지 않는다.
