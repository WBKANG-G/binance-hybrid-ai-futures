# 정지 원본 파일 비교 갱신

사용자가 제시한 Windows v3 결과에서 Docker 29.9.1 응답과 원본 정지 범위·백업 입력 해시 확인 성공을 관측했다. 앞선 데몬 연결 실패는 이 실행에서 해소됐다. 이 결과만으로 현재 원본 SQL/fence나 새 기간 적용 준비가 완료된 것은 아니다.

사용자의 다음 단계 지시에 따라 기존 비교 helper 521b898bc3181998ab713728aa1a00910ae9059923beea520420cf268b4e9956만 다시 실행하는 파일 비교 묶음을 준비했다. 기존 금융 검토 묶음의 receipt-bound 원본/보조 컨테이너 범위와 정지 검사는 그대로 유지한다. helper의 정확한 이미지, 읽기 전용 원본 볼륨 두 개, 명령, 네트워크 none, rootfs RO, 사용자·capabilities·메모리·PID·재시작 정책을 매번 재검증한다. OpenStdin=true, StdinOnce=true, Tty=false와 직전 정상 종료도 요구한다. 신규 컨테이너/볼륨 생성 및 기존 서비스 시작 함수는 포함하지 않는다.

봉인된 이전 worker와 읽기 라이브러리를 그대로 사용한다. 입력 백업 6개와 복구 증빙 파일은 읽기 전용 스트림으로 고정한다. 동시 비교 mutex를 획득한 뒤 원본 스냅샷을 재확인하고, 관리되는 Docker CLI 프로세스에 ASCII/base64 stdin만 전달한다. JSON 한 줄, 정상 종료, 2 passes, 파일 수·바이트 수 일치를 요구한다. 비교 후 원본 스냅샷·백업 해시·helper 정상 종료를 다시 확인한다. 파일 데이터와 메타데이터를 읽으며 원본 SQL은 실행하지 않는다.

오류 시 자동 재시도, helper 재실행으로 종료 코드 초기화, 컨테이너 강제 종료·삭제는 하지 않는다. CLI 시간 초과 시 해당 CLI 프로세스만 종료할 수 있으며 helper 정지는 미확인일 수 있다. 원본 서비스나 외부 프로그램이 잠시 시작됐다 다시 정지하는 모든 사건을 스냅샷만으로 증명할 수는 없다. Windows 실제 파일 비교 결과는 아직 미관측이다.

클라우드 검증은 합성 데이터와 Docker 28.4.0, PowerShell 7/Linux에서 수행한다. Windows PowerShell 5.1의 StandardInputEncoding 설정은 사용하지 않으며 입력은 ASCII로 제한한다. 실제 사용자 원본 파일, API 키, 거래소에 접근하지 않는다. 원본 SQL/fence, 최신 계정 관측, 조건부 소스 재사용 판정, owner lease 정책, 원본 적용·거래 권한은 이 단계에서 만들지 않는다. 과거 미해결 요청·34개 주문·손익·high-water를 보존한다.
