# 성공한 원본 조회 이후의 미승인 변경 계획

원본 SQL 조회 결과는 state hash 139d14…7450, fence 110, owner NULL, 만료 lease 2026-11-12T00:40:54.427273Z였다. 조회용 서버는 정상 정지됐으며 논리 원장 변경은 보고되지 않았다. PostgreSQL 시작으로 물리 저장소 파일이 바뀌었을 수 있으므로 이전 물리 일치 결과를 새 시작 권한으로 재사용하지 않는다.

이번 Windows 패킷은 기존 비공개 보고서 세 개를 읽고 입력 해시와 작업 UUID가 있는 계획서를 만든다. 원본 서버의 전체 ID와 메타데이터 해시는 현지 파일에서 읽으며 화면의 잘린 문자열을 추측하지 않는다. Docker/API/SQL 호출은 없다. 성공해도 원본 쓰기 승인·apply 토큰·최신 계정 증거가 생기지 않는다.

격리된 합성 PostgreSQL에서 검증하는 Python 후보 엔진은 SERIALIZABLE 트랜잭션, advisory/row lock, 상태·메타데이터·fence CAS, 감사 기록·event·outbox 원자성, 중간 실패 전체 롤백, 응답 유실 후 조회 검증을 구현한다. 원장 전체를 Python 모델로 재직렬화하지 않고 PostgreSQL JSONB 원문을 사용한다. 엄격한 원장 모델이 모르는 최상위 필드는 거부하며, 허용된 operations 문자열과 Decimal 필드의 원문 표현은 보존한다. 소유자와 lease를 지우지 않는다.

후보 엔진의 격리 범위는 호출자가 보증하는 테스트 범위다. 원본 쓰기 진입점은 연결 획득 전 무조건 거부한다. 실제 원본 host adapter, 최신 거래소 증거 어댑터, 최종 실제 payload 및 원본 쓰기 경계는 완성되지 않았다. 검토용 Python 파일은 Windows 명령에서 실행되지 않는다.

이후 원본 변경 전에는 시작 이후 새 백업, 정지 컨테이너 범위 및 남겨둔 임시 서버의 정확한 신원 검토, 최신 조건부 소스와 양쪽 7일 참조 간격 검증, 실제 잠금 하의 상태/소유권 재검증, 실제 payload 검증을 완료해야 한다. 그 후에 구체적인 별도 쓰기 승인을 받는다. 기존 시작 승인은 소비됐으며 이번 패킷은 이를 재사용하지 않는다. 이번 작업을 원본 적용이나 거래 재개로 보고하지 않는다.
