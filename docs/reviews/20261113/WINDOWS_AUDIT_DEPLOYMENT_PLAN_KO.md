# Windows 새 감사 경로: 적용 범위와 롤백 검토

현재 결정은 **설치 보류, 일시정지 유지**다. 사용자 제공 Windows 인벤토리 화면을 기준으로 적용 범위와 실패 시 보존 원칙을 확정했다. 이 문서는 설치 실행 승인서나 거래 준비 완료 증명이 아니다. 이번 단계에서는 Windows 명령 실행, DB 접속, 거래소 요청, 파일 복사, 컨테이너 교체를 수행하지 않았다.

## 확인된 설치 상태

사용자가 실행한 인벤토리는 `READ_ONLY_INVENTORY_COMPLETE_KEEP_PAUSED`로 완료됐다. 기존 Python 코드 89/89개가 기준과 일치한다. 날짜는 KST 2026-11-13, 주간 키는 2026-11-09이며 기간 키가 일치한다. 계정은 일시정지, 위험 상태는 NORMAL이다.

후보 코드 9개는 후보 해시와 일치하지 않는다. 이 중 `packages/persistence/demo.py`는 기존 버전으로 설치된 핵심 파일이고, 나머지는 새 후보 모듈이다. 감사 테이블 5개는 조회 시점에 없었다. 테이블 이름 유무는 스키마·트리거·권한의 완전성 검사가 아니다. 코드 89개 확인은 컨테이너 이미지 전체, 비 Python 설정, 마운트 및 백업의 검증을 의미하지 않는다.

주문 기록 34개와 UNKNOWN 3개·SUBMITTING 1개를 그대로 유지한다. OTHER 56개는 인벤토리가 별도 분류하지 않은 상태들의 합계다. 이를 추가 미해결 56개 또는 해결된 요청으로 해석하지 않는다. 최신 인벤토리에는 새 자금·원격 주문 상태 조회가 없다.

관측 출처와 전사 값은 [관측 기록](WINDOWS_AUDIT_PLAN_OBSERVED_INVENTORY.json)에 보관했다. 화면 관측 이후의 실제 Windows 상태는 새로 조회하지 않았다.

## 설치 대상을 분리한다

| 범위 | 코드 | 이번 결정 |
|---|---|---|
| 향후 GET 감사 | `demo_response_evidence.py`, `demo_response_evidence_transport.py` | 별도 부트스트랩·장애 검증 후 검토할 최소 후보 2개 |
| 오프라인 판독 | `demo_request_outcome_candidate.py`, `demo_submission_link_candidate.py` | 응답·의도 관계 판독만 허용하는 도구 후보; 요청 상태 변경 권한 없음 |
| 격리 합성 실험 | `demo_wire_session_contract_candidate.py`, `demo_wire_checkpoint_candidate.py`, `demo_wire_restore_reference_candidate.py`, `review_wire_restore_reference.py` | 실제 Windows 전송 경로 설치 대상에서 제외 |
| 기존 핵심 파일 변경 | `packages/persistence/demo.py` | 합성 준비 기록용 훅 변경이므로 GET 단계에서 제외 |

정확한 경로·소스 SHA256은 [기계 판독 계획](WINDOWS_AUDIT_DEPLOYMENT_PLAN.json)에 고정했다. 위 분리는 단순히 파일을 복사하면 동작하는 설치 절차를 뜻하지 않는다.

GET 후보는 실제 DEMO GET 전송 함수를 기본 sender로 사용하므로 명시적으로 활성화하면 네트워크 요청을 수행할 수 있다. 합성 전용 코드와 구분해야 한다. 향후 GET 단계에서 검토할 새 테이블은 `read_response_evidence_bindings_v2`, `read_response_evidence_events_v2` 두 개다. 세 `wire_checkpoint_*_v2` 테이블은 합성 단계에만 해당한다. 테이블 생성만으로 GET 감사 연결이 완료되지 않는다.

정적 AST 검사에서는 새 후보 모듈을 직접 import하는 기존 운영 모듈이 발견되지 않았다. 동적 import, 호출자 조립, 실제 sender 안전성까지 입증하는 검사는 아니다. 해당 검사 결과만으로 활성화를 허용하지 않는다.

## 기존 설치·롤백 도구의 부족한 범위

기존 `scripts/review_demo_read_code_install.py:preserved_snapshot`은 `demo_` 접두사 테이블과 지정 저장 디렉터리 파일의 해시를 계산한다. **이 해시는 복원 가능한 백업이 아니다.** 새 `read_response_evidence_*_v2`, `wire_checkpoint_*_v2` 테이블은 접두사가 달라 DB 해시 범위에서 빠진다. 함수·트리거 정의를 포함한 새 스키마 검증도 별도로 필요하다.

기존 설치기의 컨테이너 보관·이름 복귀 기능만으로 DB와 파일 증거를 복원하거나 검증했다고 간주할 수 없다. 새 증거를 기록한 뒤 예전 writer를 다시 실행하면 감사 기록 누락을 만들 수 있다. 기존 설치 ZIP을 후보 파일 이름만 바꿔 재사용하지 않는다.

합성 `create_reference_manifest`는 새 합성 저널·체크포인트를 전제로 한다. 현재 Windows의 기존 shared-weight/order-quota 기록에 그대로 적용할 수 없다. 합성 테이블을 만드는 방식으로 기존 이력을 소급 인증하지 않는다.

## 실제 설치 전에 준비할 보존 범위

1. 컨테이너 ID·이미지 digest·Compose 구성·마운트 식별자를 고정한다. 모든 writer의 정지를 독립적으로 확인하고, 그동안의 기록 경계를 고정한다. 현재 인벤토리는 writer 정지를 증명하지 않는다.
2. 대상 DB의 스키마·데이터·함수·트리거·필요 권한을 포함하는 복원 가능한 백업과, 실제 마운트된 영속 파일의 일관된 복사본을 준비한다. 별도 계정·서비스를 덮어쓸 수 있는 DB 전체 복원은 자동 절차로 두지 않는다. 로컬 상태의 범위와 의존 테이블을 먼저 조사한다.
3. `/app/demo-export-state/demo-runtime-20261111/shared-weight`와 `order-quota`, 연결된 영수증·체크포인트·기존 감사 자료를 포함한다. 해당 경로는 이전 설정에서 확인된 경로이므로 실제 마운트 및 계정 바인딩과 다시 대조한다. SQLite WAL/SHM 또는 실행 중 복사본을 조용히 제외하지 않고, writer 정지와 일관성 확보 방법을 검증한다.
4. API 키·Secret·서명·RAM 세션을 공개 산출물에 넣지 않는다. 컨테이너 구성의 비밀값은 화면이나 검토 JSON에 출력하지 않으며 필요한 복구 정보는 보호된 로컬 보관 범위로 별도 관리한다.
5. 네트워크가 차단된 격리 환경에서 복원 연습을 수행하고, 주문 34개·미해결 4개·재무 이력·감사 체인·파일 연결의 동일성을 확인한다. 성공한 코드 빌드나 인벤토리는 복원 연습을 대신하지 않는다.
6. 사용자가 선택한 별도 기기·오프라인 보관 방식으로 참조와 최신 해시를 실제 인계한다. 현재는 선택만 기록됐으며 기기·경로·인계·최신 해시 등록은 미완료다. 기존 합성 참조 CLI로 실제 레거시 보관을 완료했다고 표시하지 않는다.

## 기록 경계에 따른 롤백

| 실패 시점 | 조치 | 자동으로 하면 안 되는 작업 |
|---|---|---|
| 이미지 빌드·정적 검사 중, 영속 변경 전 | 원본 컨테이너·데이터 유지; 새 이미지 보관 또는 폐기 | DB/파일 복원, 시간 복구, 요청 재실행 |
| 코드 교체 후, 새 바인딩·증거 기록 전 | writer 정지 유지, 데이터 불변 확인 후 고정된 원본 코드 복귀 검토 | 변경 여부 확인 없는 원본 writer 재시작 |
| 바인딩·스키마·감사 증거 기록 후 | 새 기록 전체 보존, writer 정지, 관측한 단계에 맞는 복구 검토 | 과거 DB/파일로 되돌려 새 기록 제거, 테이블 삭제, 예전 writer 자동 재개 |
| PG와 파일 사이 커밋 틈 또는 해시 불일치 | 양쪽 증거 보존, 재개 거부, 수동 원인 검토 | 환불·체인 재작성·소급 채우기·자동 재시도 |

원본 컨테이너와 후보 컨테이너가 동시에 writer로 시작되지 않도록 restart 정책도 검증해야 한다. 컨테이너 재시작 후 boot/clock 변경은 새 감사 경로의 명시적 정책이 필요하며, 현 V2 증거 경로의 CLOCK_REBASE 미지원 문제를 설치 중 자동 복구로 숨기지 않는다. 전체 DB와 파일을 함께 과거로 돌린 공격·실수는 같은 위치의 해시만으로 독립 검출할 수 없다.

## 완료 범위와 다음 구현

이번 단계는 범위·의존관계·롤백 정책의 정적 검토까지 완료했다. 설치기·백업·복원 기능은 새로 구현하거나 실행하지 않았다. 다음 구현 범위는 **기존 Windows 런타임의 백업 범위와 의존성을 확인하는 읽기 전용 사전 검사**다. 비밀값이나 이벤트 본문을 출력하지 않고, 설치·거래소 접근·요청 상태 변경 없이 필요한 보존 범위를 확인하도록 설계한다.

GET 부트스트랩, writer 차단, V2 전체 스냅샷, clock 정책, 실패 경계 검증 및 실제 오프라인 인계가 갖춰지기 전에는 설치로 진행하지 않는다. 미해결 요청 정리, 기록 보관 처리(archive), 거래 재개는 이 계획에 포함되지 않는다.
