# GET 응답 증거 V2 후보 구현 검토

현재 Windows에 설치하지 않은 후보 코드다. 클라우드 테스트는 합성 응답만 사용하며 실제 거래소 호출, Windows 데이터 접근, 주문 제출, 거래 재개를 하지 않는다.

## 해결한 문제와 저장 방식

기존 읽기 감사 기록은 요청 예약·완료와 체크포인트를 결합하지만, 별도로 출력한 응답 본문 해시는 그 감사 체인에 소급해 결합할 수 없다. V2는 새 요청부터 정규화한 GET 메타데이터와 정확한 응답 바이트의 SHA-256·길이·HTTP 상태를 기록한다.

- `packages/persistence/demo_response_evidence.py`: 명시적인 스키마 생성·바인딩, 증거 체인 검증, 읽기 전용 검토, 감사 저널 확장.
- `services/execution/demo_response_evidence_transport.py`: 기존 GET 전송·비용 예약·중단 정책을 사용하는 명시적 선택형 전송 경로.
- 예약 시 PENDING 행을 커밋한 뒤 전송한다. FINISH의 응답 메타데이터는 기존 감사 FINISH 행과 체크포인트를 생성하는 **같은 PostgreSQL 트랜잭션**에 추가한다.
- 증거 행은 기존 감사 행의 scope/sequence를 외래 키로 참조하며, 감사 해시·체크포인트 digest·이전 증거 해시를 포함한다.
- 별도 파일 증인에 루트와 각 행의 해시를 추가하고 fsync한다. PG 증거를 재작성하고 해시를 재계산해도 파일과 다르면 거부한다. DB와 파일을 모두 변경할 수 있는 공격자에 대한 외부 신뢰 앵커는 제공하지 않는다.
- 키·서명·헤더·응답 원문은 증거 테이블이나 증인에 저장하지 않는다. 주문 조회의 원래 식별자와 정규화한 허용 파라미터는 저장하므로 증거 저장소는 비공개로 취급해야 한다.

두 보조 테이블은 `read_response_evidence_bindings_v2`, `read_response_evidence_events_v2`다. 금융 테이블을 분류하는 기존 `demo_*` 범위와 구분한 자원 증거다. 향후 실제 설치 시 스냅샷·백업·복원·무결성 검토 범위에 두 테이블과 증인 파일을 명시적으로 포함해야 한다. 기존 금융 테이블이나 설치 파일을 이 단계에서 변경하지 않는다.

## 실패·재시작 동작

PG 내부의 세 기록은 원자적으로 커밋된다. SQLite·파일·PG 전체를 하나의 원자적 트랜잭션으로 보장하지는 않는다. 파일 또는 SQLite가 앞선 뒤 PG 커밋이 실패하면 다음 검토·사용에서 불일치를 거부한다. 파일 일부 쓰기나 fsync 실패도 성공으로 처리하지 않으며 자동 잘라내기·환불·재전송·증거 재생성을 하지 않는다.

네트워크 오류는 OUTCOME_UNCERTAIN과 미완료 예약을 보존한다. HTTP 400을 포함해 응답을 받은 사실은 OBSERVED일 뿐 성공·취소·미전송 증명이 아니다. 미완료 예약이나 중단 상태에서 새 전송 객체를 열어 재시도할 수 없다. 저장 한도에 도달하기 전에 완료 증거를 위한 공간을 남기고 새 예약을 거부한다.

현재 감사 이력을 바인딩 기준점으로 삼을 수 있지만 이전 행의 응답 증거를 채우지 않는다. 기존 감사 행과 체크포인트는 보존한다. 기본 생성자는 비활성이고 저널은 기본 읽기 전용이다. 명시적 스키마 생성·바인딩·쓰기 선택이 모두 필요하다.

V2 바인딩 이후 구형 writer를 사용하면 증거 누락으로 거부한다. 설치 전에 모든 구형 writer를 중지하고 독립적으로 확인하는 절차가 필요하다. V2 이후 CLOCK_REBASE/자동 시계 복구·마이그레이션은 구현하지 않았으며 지원되지 않는 전이는 거부한다. 기존 시계 복구 도구를 그대로 실행하는 경로는 제공하지 않는다.

## 현재 증명하지 않는 것

로컬 `DEMO-` 계정 라벨은 거래소 계정 신원 증명이 아니다. 본문 해시 대조는 응답 원문 아티팩트의 영구 저장·서명 검증·내용의 업무상 판정을 대신하지 않는다. 별도 원문 저장·계정 바인딩·요청별 결과 검증과 인증서 정책은 후속 작업이다.

기존 Windows의 네 미해결 요청, 과거 본문 해시, 34개 주문 이력은 변경하지 않았다. 이 후보는 원격 결과 확정, 요청 상태 조정, 과거 이력 보관 허가, 용량 부족 해결을 하지 않는다. 거래소 요청 비용 상한·실제 공인 IP 용량·계정 주문 사용량도 증명하지 않는다. 모든 검토 결과의 archive/execution/orders/LIVE 승인은 false다.

설치 패키지나 활성화 CLI는 제공하지 않는다. Windows에서 실행할 새 명령은 아직 없다. 다음 구현은 이 원자적 결합 증거를 입력으로 하는 원문 아티팩트·요청별 결과 검증 경로이며, 설치와 거래 재개는 별도 검토 대상이다.

## 검증

실제 PostgreSQL·SQLite·파일을 사용한 통합 테스트와 합성 전송으로 검증했다. 요청 전 예약, 완료 해시 결합, 기존 이력 무소급 바인딩, 키·서명·본문 비저장, append-only 트리거, PG 커밋 실패, 파일 일부 쓰기, 해시를 다시 계산한 DB 변조, 구형 writer 누락, 계정 라벨 변경, 미완료 예약 재시작, POST 거부, 증거 한도를 포함한다. 기존 감사·시계 복구·읽기 비용·체크포인트 회귀 테스트도 실행한다. 정확한 결과는 `RESPONSE_EVIDENCE_V2_VALIDATION.json`에 기록한다.
