# 복사본의 서명 계좌 응답 원문 수집 후보

이 단계는 새 날짜 기준 증거를 수집·보관하는 코드와 계약의 검증이다. 실제 Windows 실행 패키지, 거래소 조회, 날짜 채택은 포함하지 않는다. 원본·기존 복구 사본은 정지 상태이고 USB는 분리 상태를 유지한다.

`CopyAccountArchiveTransport`는 기본 비활성화이며 copy_only와 enable_capture를 명시해야 한다. 내장 네트워크 sender가 없으므로 호출자가 전송 경로를 별도로 주입해야 한다. 서명된 GET `/fapi/v3/account` 한 번만 허용한다. 생성 시 지정한 API 키와 호출 키를 메모리에서 비교하고, 서명 timestamp가 현재 로컬 UTC와 5초 이내인지 보내기 직전에도 확인한다. 요청 signature 자체를 이 모듈이 비밀키로 재검증하는 것은 아니다. 기존 DEMO 호스트·GET·비용 모델·감사·체크포인트·시계 검사도 유지한다.

새 비공개 디렉터리에 intent.json을 배타 생성하고 fsync한 뒤 조회한다. 응답은 최대 4MiB이며 원문 바이트 그대로 response.bin에 배타 저장·fsync한다. API 키나 현재 요청 서명이 응답에 그대로 포함되면 저장을 차단한다. 응답 헤더·API 키·전체 서명 query는 기록하지 않는다. 응답 원문은 계좌 정보를 포함할 수 있으므로 로그·커밋·브라우저에 노출하지 않고 비공개 로컬 파일에만 보관한다.

기존 전송기의 FINISH 완료 후 전체 V1/V2 이력을 읽기 전용으로 검증한다. 요청 토큰·scope·sequence·감사 해시·checkpoint revision/digest 및 응답 길이/해시를 대조하고, 수집 종료까지 75초 이내·UTC 순행·같은 한국 날짜임을 확인한 뒤 receipt.json을 배타 저장한다. 영수증 SHA256을 고정해 원문과 감사 기록 연결을 다시 읽기 전용 검증한다. 수집 시각은 로컬 관측이며 거래소 자정 평가 시각을 뜻하지 않는다.

실패한 디렉터리는 보존한다. 네트워크 오류, HTTP 오류, 비용 헤더 누락, 저장 또는 fsync 실패, 시계·날짜 경계 변경은 성공 보고를 차단한다. 일부 경우 응답이나 감사 완료가 이미 남았을 수 있으므로 객체 재호출 및 같은 디렉터리 재개는 거부한다. 자동 재조회·삭제·원장 복구·미해결 요청 해소는 없다. 다른 디렉터리를 이용한 사람이 승인한 후속 조회까지 전역적으로 차단하는 기능은 이 후보에 없다. 그 판단은 향후 실행기에서 영수증과 보존된 실패 상태를 검토해야 한다.

credential_context_id는 호출자가 제시한 문맥 식별자다. 운영자 진술 수신, 원격 계좌 신원 확인, 같은 실제 거래소 계좌라는 증명으로 취급하지 않는다. copy_only도 호출자의 진술이므로 실행기의 볼륨·네트워크·프로세스 격리 검증이 별도로 필요하다. 성공 보고는 원문과 완료 감사 기록의 연결만 확인한다. 계좌 응답 내용의 의미, 외부 거래 전체 범위, 자정 평가, 원천 수락, 날짜 채택, 설치·주문 승인은 계속 false다.

새 날짜 근거를 수락하려면 이후 별도 계약에서 원격 계좌 신원과 자격증명 문맥, 정확한 기간과 검토 마감 시각, 완전한 거래·수입·이체 범위, 평가 또는 재구성 방식, 검증된 원문 영수증을 함께 고정해야 한다. 과거 금액·외부 활동 없음·사용자 동의를 추정하지 않는다. 같은 주의 일간 전환이면 주간 기준은 보존한다. 하나의 최신 account 응답만으로 이 요건이 충족되지는 않는다.

다음 범위는 실제 실행 전에 필요한 계좌 문맥·응답 내용 검증과 증거 수락 입력 계약을 준비하는 것이다. 이번 단계에서는 Windows에서 추가 명령을 실행하거나 USB를 다시 연결할 필요가 없다.

관련 검증 102개가 통과했다. 최종 수집·이미지 검사 36개와 변경하지 않은 회귀 검사 66개이며, 반복 실행을 중복 집계하지 않았다. ruff와 후보 모듈 mypy도 통과했다. 상세 실행 범위는 COPY_ACCOUNT_CAPTURE_VALIDATION.json에 기록했다.
