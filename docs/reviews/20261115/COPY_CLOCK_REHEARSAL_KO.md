# 새 임시 복사본의 V1 시계 전환 검증

사용자의 2026-11-15 Windows 출력에서 직전 진단 완료를 확인했다. 기준 이미지 89개·후보 3개가 검증됐고, 감사 이력 55건, 미완료 조회 0건, V2 미연결, 저장 일자 2026-11-13, 현재 일자 2026-11-15, 미해결 요청 4개 및 시계 불일치가 보고됐다. 원본 시작 없음, 백업 해시 유지, 새 진단 복사본 정지가 함께 보고됐다. 이것은 사용자 콘솔 관측이며 새 독립 Windows 도구 접근이나 물리적 보관 검증이 아니다.

직전 COPY_REVIEW_RECEIPT.json의 고정 SHA256은 `df50d9b96a9cc67b2d46110eeb75858c2ad6057eb95c796b31a881a6c2937365`다. 해당 영수증의 코드 참조는 `dce468d351738b92ef4651a395b7b8f47265baad`다. 새 실행기는 이 영수증, 원시 백업 manifest/receipt, 기존 복구 영수증을 검증하고 모든 기존 컨테이너와 직전 진단 helper 3개의 정지·이미지·마운트·재시작 정책·정상 종료를 확인한다. 기존 복사본을 재사용해 시작하지 않는다.

새 DB/runtime/socket 볼륨을 만들어 고정된 백업을 복원한 뒤 새 PG만 네트워크 없이 실행한다. 전환 직전의 새 복사본 지문이 직전 성공 진단의 지문과 정확히 일치해야 한다. 이 일치와 V2 미연결·미완료 조회 없음·paused/NORMAL·로컬 flat·활성 소유자 없음 등의 조건을 통과한 경우에만 복사본에서 명시적 V1 CLOCK_REBASE를 실행한다.

기준 이미지 89개를 대조하고 후보 5개를 메모리에만 올린다. 기존 V1 시계 복구 모듈도 V2 차단 가드가 포함된 버전으로 메모리에 대체한다. helper는 비 root·네트워크 없음·읽기 전용 루트이며 새 runtime만 쓰기 가능하다. PG 읽기 엔진과 명시적 쓰기 엔진은 동일한 새 Unix socket 주소로만 접속한다. 원본·기존 복구 사본·직전 진단 복사본·키 세션·USB에 쓰거나 서비스를 시작하지 않는다.

적용 동안 계좌 공유 잠금과 기존 스키마 전역 잠금을 유지한다. 기존 감사 이력과 모든 scope의 감사/체크포인트 행을 비교하여 해당 scope의 CLOCK_REBASE 행과 체크포인트 각 1건만 추가됐는지 확인한다. 기존 행 수정·삭제나 다른 scope의 행 추가도 허용하지 않는다. 두 보조 테이블 이외 모든 테이블 내용과 카탈로그 지문은 그대로여야 한다. 누적 비용과 stopped 플래그는 그대로 보존한다. runtime에서는 해당 SQLite 파일만 바뀔 수 있고, 원본 SQLite 바이트를 보관하는 복구 파일과 intent 파일 각 1개만 추가된다. 기존 다른 파일의 해시는 모두 유지돼야 한다.

commit 완료 후부터 다시 최소 70.001초 이상을 기다리고 실제 Linux 단조 시계로 시작 대기 충족을 확인한다. `COPY_CLOCK_HOLD remaining_seconds=...` 진행 메시지가 표시된다. 이후 새 읽기 전용 세션에서 시계 일치, 저장 상태 유지, 기존 일/주 키와 미해결 요청 수 보존을 검증한다. 대기 중 시계 후퇴·부팅 변경·wall/mono 불일치·한국 날짜 경계 통과·외부 상태 변경은 성공 보고를 차단한다. 날짜 채택이나 미해결 요청 해소는 없다.

성공 시 감사 이력은 이 사용자의 입력 기준 55→56건이어야 하며 리소스 체크포인트도 1건만 증가한다. 새 복사본만 정상 정지하고 입력 해시와 기존 컨테이너 상태를 재확인한다. COPY_CLOCK_RECEIPT.json을 별도로 남긴다. 상위 결과의 clock_rebased는 이번 시계 전환을 뜻한다. diagnostic_after 안의 변경 여부 필드는 읽기 전용 후검사 자체가 변경하지 않았음을 뜻하며, clock_matches가 전환 후 상태를 나타낸다.

실패하면 새 복사본에서 시계 전환이 이미 완료됐을 수 있다. 이 경우 자동 재시도·롤백·정리·추가 rebase를 하지 않고 남은 복사본과 영수증을 보존한다. timeout 시 확인된 소유 helper만 종료하고 새 PG만 정지시킨다. 실행 창 강제 종료나 PC 전원 차단까지 정지 완료를 보장하지 않으므로 창을 닫지 않고 완료 출력을 확인한다. 원본 적용이나 실제 GET/주문은 허용되지 않는다.

합성 PG/SQLite 검사에서는 기존 복구 기록을 포함한 감사 55→56건과 누적 비용 135 보존, V2/미완료 요청 거부, 틀린 지문 거부, 다른 scope의 변경 거부, 대기 중 계좌/시간 변경 탐지, 중단 뒤 재처리 차단을 확인했다. 별도 실제 Docker 절차에서는 새 복사본의 Unix socket 쓰기와 실제 70초 이상 대기, 읽기 전용 후검사 및 정상 정지를 확인했다. Docker fixture의 사전 감사 이력은 0건이며 0→1건을 검증하므로 실제 Windows 55건 실행 결과와 혼동하지 않는다. Windows ACL과 입력 경로 탐색은 Linux 테스트에서 대체했고 실제 Windows 시계 전환은 아직 수행하지 않았다.

최종 ZIP 검증 기록은 COPY_CLOCK_VALIDATION.json에 남긴다. USB를 연결하지 않고 RUN_CHECK.cmd 성공 후 RUN_CLOCK_REHEARSAL.cmd를 한 번 실행하는 범위다. 설치 준비와 거래 승인은 계속 false다.
