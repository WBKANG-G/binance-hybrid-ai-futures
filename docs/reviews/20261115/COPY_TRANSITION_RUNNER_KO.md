# 새 임시 복사본 날짜·부팅 진단 실행기

2026-11-15 새 Windows 실행기를 준비했다. PC 내부의 고정된 보존 manifest/receipt와 기존 성공 복구 영수증 해시를 확인한다. 기존 원본·보존된 복구 사본·보관 helper의 ID/이미지/마운트/재시작 정책/정지 상태를 검증한다. 분리된 USB는 사용하지 않는다.

`RUN_CHECK.cmd`는 입력 해시와 정지 상태만 확인하며 새 볼륨/컨테이너/결과 폴더를 만들지 않는다. `RUN_COPY_REVIEW.cmd`는 검사를 다시 수행하고 새 DB·runtime·socket 볼륨을 생성한다. 기존 archive 검증/복사 코드를 재사용하여 새 볼륨에만 원시 바이트와 메타데이터를 복원하고, 검증된 PID만 복사본에서 제거한다. 새 PG 복사본만 네트워크 없이 복구한다. 원본과 기존 복구 사본에는 start/exec/stop을 보내지 않는다.

새 PG는 외부 listen과 preload/restore/archive 명령을 비활성화하고 기본 읽기 전용으로 연다. 비 root 진단 helper는 네트워크 없음·읽기 전용 루트·권한 제거 상태에서 새 runtime/socket만 읽기 전용으로 마운트한다. PG 데이터 볼륨·원본 볼륨·키 세션·Docker socket은 진단 helper에 연결하지 않는다. 이미지 환경 변수는 지우고 로컬 Unix socket으로만 접속한다. 모든 진단 세션에 읽기 전용 옵션을 적용하고 SHOW로 확인한다.

기준 API 이미지 파일 89개와 후보 3개의 해시를 검증한다. 후보는 응답 증거 검증·전체 스냅샷·복사본 날짜/부팅 진단 모듈이며 메모리에만 올린다. scope/저널/설치 ID는 복사된 계좌 바인딩에서 얻고 runtime 안에서 해당 SQLite 위치가 하나인 경우만 허용한다. 읽기 전용 진단은 기존 감사/확인 파일 무결성을 검증하고 전후 지문을 대조한다. 기본 키 없는 테이블, 불완전 스키마, 저장소 busy/불일치 등은 차단한다.

완료 시 새 PG 복사본을 정상 정지하여 exit 0/OOM false를 확인한다. 기존 컨테이너 스냅샷과 백업 입력 해시를 다시 대조한다. 새 helper/볼륨과 비공개 COPY_REVIEW_RECEIPT.json은 남기고 삭제·자동 재시도하지 않는다. 실패 시에도 새 PG만 소유 ID/볼륨/네트워크를 재검증하여 정지시킨다. 검사에 실패해 소유 범위를 확신할 수 없으면 임의의 컨테이너에 신호를 보내지 않고 잔여 ID를 보고한다.

시계 복구·날짜 채택·schema 생성·바인딩·실제 GET·주문은 없다. `blockers`가 있어도 진단 자체가 완료될 수 있다. 로컬 flat이나 시계만으로 미해결 요청 4개를 해소하지 않는다. 설치 준비/실행 승인은 false다.

개발 환경에서 실제 Docker/PG18/API 이미지와 원시 백업→새 복구→Unix socket 진단→정상 정지의 전체 절차를 검증했다. 실제 Windows ACL과 입력 경로 탐색만 Linux 테스트에서 대체했으므로 실제 Windows 검증을 주장하지 않는다. 기준 이미지 hash/payload 변경 거부, mount/프로젝트/네트워크 변경 거부, 전송 manifest 변조 차단도 검사했다. 배포 ZIP의 최종 검증은 동봉 별도 실행 기록에 기록한다.

실제 Windows에서는 Docker Desktop 엔진만 실행된 상태에서 ZIP을 새 폴더에 풀고 먼저 RUN_CHECK.cmd를 실행한다. 성공 메시지를 확인한 뒤 RUN_COPY_REVIEW.cmd를 한 번 실행한다. 출력 JSON/완료 메시지를 확인하기 전 반복 실행하지 않는다. USB를 다시 연결하거나 기존 컨테이너를 시작할 필요는 없다.
