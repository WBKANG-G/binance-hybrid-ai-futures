# 복사본의 새 날짜 기준 증거 준비

사용자 Windows 콘솔에서 새 임시 복사본의 V1 시계 전환과 시작 대기가 성공한 것을 확인했다. 감사 이력은 55→56, 리소스 revision은 58→59이며 누적 비용 284가 보존됐다. 전환 후 boot/clock 일치, 원본 미시작, 새 복사본 정지, 백업 해시 유지가 보고됐다. 이는 사용자 화면 관측이며 독립 Windows 접근이나 물리적 보관 검증이 아니다.

저장 일자는 2026-11-13, 현재 일자는 2026-11-15이며 두 주간 키는 2026-11-09다. 따라서 이번 전환은 일간 기준만 검토해야 한다. 주간 기준은 보존한다. 주가 바뀐 뒤에는 일간·주간 전환을 별도로 검토한다. 과거 금액 4998.74183608을 오늘 기준으로 재사용하지 않는다.

일반 V2 초기화는 현재 일/주 키를 요구하므로 새 날짜 증거 수집 전에 막힌다. 일반 운영 검사는 변경하지 않았다. 별도의 명시적 복사본 전용 후보는 검증된 paused/NORMAL·로컬 flat·소유자 없음·미완료 조회 없음·현재 시계 일치 상태에서만 증거 보조 스키마와 연결을 준비한다. 오래된 날짜와 역사적 미해결 요청 4개는 이 보조 준비에 한해서 허용되며, 원장이나 요청 상태는 바뀌지 않는다.

필요한 증거는 다음과 같다.

1. 고정된 복사본 입력과 현재 시계.
2. 자격증명 문맥에 연결된 최신 원격 계좌 신원.
3. 서명된 USDT 계좌·잔액 및 노출 없음 또는 노출 설명.
4. V2 감사·체크포인트에 연결된 재생 가능한 응답 원문.
5. 검토 시점까지의 거래·수입·이체 전체 범위.
6. 일자 경계 평가 또는 명시적으로 수락한 재구성 근거.
7. 운영자의 명시적 진술과 근거 수락.
8. 적용 직전 현재 기간 재검사와 손실·고점 한도 검사.

현재 V2 응답 해시 연결만으로 계좌 신원, 자정 평가, 전체 거래 이력 또는 날짜 채택을 증명하지 않는다. paused·정지·로컬 flat은 외부 거래 없음에 대한 운영자 진술을 대신하지 않는다. 기존의 모호한 답변도 새 기간 진술로 재사용하지 않는다.

후보는 기존 전체 테이블·카탈로그·파일 지문을 비교한다. 새 V2 테이블 두 개와 해당 scope의 연결 및 witness만 허용하고 기존 다른 scope 연결은 보존한다. V1 감사 backfill, 시계 전환, 원장·일/주 키·요청·리소스 체크포인트 변경은 허용하지 않는다. 파일 또는 commit 도중 실패하면 고아 기록을 자동 수리하거나 재시도하지 않는다. copy_only 플래그는 호출자의 진술이므로 실제 격리는 향후 실행기 경계에서 별도로 확인해야 한다.

합성 PostgreSQL/SQLite 통합 검사 및 네트워크 없는 기존 이미지의 메모리 import/default-denial 검사 70개가 통과했다. ruff와 후보 모듈 mypy도 통과했다. 일반 운영 경로의 오래된 날짜 거부, 다른 scope 보존, 부분 스키마·고아 witness 거부, commit 실패, 설정 중 시계 변경을 포함한다. 실제 Windows 적용·실제 거래소 GET·날짜 채택은 수행하지 않았다. 새 Windows 실행 패키지는 이번 단계에 포함하지 않는다.

다음 범위는 서명 응답 원문 보관·계좌 문맥·근거 수락을 갖춘 새 증거 수집 후보의 검증이다. 날짜 채택 승인과 주문 활성화는 계속 false다. 원본과 기존 복구 사본은 정지 상태로, USB는 분리 상태로 유지한다. 이번 결과를 확인하기 위해 USB를 연결하거나 Windows 명령을 추가로 실행할 필요는 없다.
