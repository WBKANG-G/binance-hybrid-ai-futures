# 새 복사본의 합성 증거 경로 통합 검증

기존 시계 전환, 보조 증거 연결, 원문 보관, 내용 검사를 새 임시 복사본에서 순서대로 연결하는 후보를 추가했다. 실제 Windows 실행이나 거래소 조회는 이 단계에 포함하지 않는다. 기존 Windows ZIP과 실제 계좌 데이터는 변경하지 않는다.

`rehearse_synthetic_copy_evidence`는 copy_only와 synthetic_only를 정확한 boolean true로 요구한다. 네트워크 sender나 실제 거래소 자격증명을 입력받지 않고 코드 내부의 합성 전송 함수와 합성 서명 키만 사용한다. 서명된 계좌 GET의 기존 감사·체크포인트 동작을 재현하지만 거래소 HTTP 시도는 0건이다. 비용 모델과 synthetic used-weight는 복사본의 테스트 기록이며 실제 IP 사용량이나 거래소 수용량의 증명이 아니다.

검증 순서는 다음과 같다.

1. 외부 수명 주기 절차가 새 DB/runtime/socket 볼륨을 만들고 고정된 백업을 복구한다.
2. 기존 V1 시계 전환을 새 복사본에서만 실행하고 실제 또는 검사 시계로 최소 시작 대기를 충족한다.
3. 새 지문, 현재 시계, 시작 대기, paused/NORMAL·로컬 flat·소유자/미완료 조회 없음과 V2 미연결을 검사한다.
4. 복사본의 보조 스키마/연결만 준비하고 새로운 비공개 합성 응답 디렉터리를 지정한다.
5. 합성 계좌 응답 한 번을 원문으로 저장하고 V1/V2 FINISH·감사 해시·체크포인트와 대조한다.
6. 고정된 원문 영수증을 읽기 전용으로 검증하고 계좌 내용의 제한된 산술 관계를 검사한다. 사용자 진술이나 근거 제안을 전달하지 않는다.
7. 전체 테이블·카탈로그·파일을 비교하고 새 복사본을 정상 정지한다. 외부 수명 주기 절차가 원본/이전 사본 상태와 입력 해시를 재검사한다.

통합 후보는 계좌 공유 잠금을 유지하며 기존 보조 준비 함수의 스키마/파일 보존 검사를 사용한다. 준비 완료 후 스키마는 바뀔 수 없고, 조회로 추가되는 V1 감사와 리소스 체크포인트는 해당 scope에서 각각 2건이어야 한다. V2 이벤트도 2건만 증가한다. 기존 원장·다른 테이블·연결, 기존 다른 파일은 보존하며 해당 SQLite와 V2 witness 및 새 원문 디렉터리의 세 파일만 조회 과정에서 바뀔 수 있다.

새 복사본의 로컬 시계 및 응답 내용만 검사한다. historical unresolved 요청을 해결하거나 저장 날짜·금액을 변경하지 않는다. 실제 원격 계좌 신원, 미체결 주문 없음, 계좌 설정, 전체 외부 이력, 자정 평가 및 사용자 진술·근거 수락도 확인된 것으로 처리하지 않는다. content_review의 기준 채택·원천 수락과 설치/주문 승인은 계속 false다.

실패하면 이미 생긴 V2 연결·감사 기록·원문 일부를 보존한다. 보조 설정 후 중단, 원문 쓰기 실패, 내용 검사 실패, 다른 테이블 변경은 성공 보고를 막는다. 새 V2 연결이 남았으면 재진입을 거부한다. 자동 재시도·재조회·롤백·고아 기록 수리 또는 정리는 없다. 클라우드 테스트의 finally 정리는 테스트가 소유한 합성 자원에만 적용한다.

라이브러리의 copy_only는 호출자 진술이다. Docker 테스트에서 외부 절차가 네트워크 none, 새 볼륨만 쓰기 가능, 소켓 마운트, 비 root 읽기 전용 루트, 재시작 no 및 원본 미시작을 검사한다. Windows 입력 경로 탐색과 NTFS ACL은 Linux에서 대체하므로 실제 Windows ACL 검증이나 별도 PC 검증을 주장하지 않는다.

검사용 clock 결과의 after_snapshot_sha256과 diagnostic_after는 시계 단계 종료 시점의 중간 상태다. 이후 보조 연결과 합성 조회가 추가되므로 최종 상태 지문은 synthetic_evidence_rehearsal.after_snapshot_sha256에서 확인한다. 검사용 패키지는 전달 파일 목록·해시·worker 문법을 사전 검사하며, 기존 Windows ZIP을 덮어쓰지 않는다.

다음 범위는 이 합성 경로를 실제 Windows에서 실행 가능한 검토용 패키지로 고정하고 전달 파일·입력 영수증·정지 범위를 검증하는 것이다. 실제 서명 GET와 날짜 채택은 여전히 포함하지 않는다. 사용자는 현재 원본·복구 사본 정지 및 USB 분리 상태를 유지하면 된다.

관련 테스트 12개가 통과했다. PG/SQLite 통합·실패 경로 10개(33.47초), 검사용 전달 목록/해시/문법 검사 1개(0.42초), 실제 Docker 수명 주기 1개(189.50초)다. ruff와 후보 모듈 mypy도 통과했다. 최초 전달 목록 검사의 누락과 교체 문자열 충돌은 검사용 fixture에서 수정했고, 사전 검사를 추가한 후 최종 Docker 절차를 통과했다. 상세 범위는 COPY_EVIDENCE_PIPELINE_VALIDATION.json 및 COPY_EVIDENCE_DOCKER_VALIDATION.json에 기록했다.

실제 Docker fixture의 감사 이력은 시계 단계 0→1건, 합성 조회 단계 1→3건이었다. 이는 사용자 Windows의 55→56건 시계 실행 이력과 다른 합성 데이터다. 새 복사본 정상 정지와 입력 해시 재검증이 확인됐고 합성 sender 호출은 1회, 실제 거래소 HTTP 시도는 0건이었다.
