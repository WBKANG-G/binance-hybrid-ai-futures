# 계좌 응답 내용과 근거 제안 입력 검증

보관된 계좌 응답을 읽기 전용으로 검사하는 후보를 추가했다. 실제 Windows 적용, 거래소 조회, 날짜 채택 또는 기존 요청 해소는 수행하지 않았다. 원본·기존 복구 사본은 정지 상태이고 USB는 분리 상태를 유지한다.

먼저 고정된 archive 영수증과 전체 V1/V2 감사 연결을 검증한다. HTTP 200, 원문 SHA256, intent/receipt 연결을 다시 확인한 뒤 종료 관측에서 5분 이내이며 같은 한국 날짜인 응답만 현재 검토에 사용한다. 현재 시각은 호출자가 전달한 UTC 관측이며 독립 거래소 시각 증명이 아니다.

응답은 최대 4MiB의 UTF-8 JSON 객체여야 한다. 중복 키, JSON 실수·NaN·Infinity, 과도한 깊이·필드 수를 거부한다. 금액은 최대 정수 20자리·소수 18자리의 엄격한 십진 문자열로만 읽고 Decimal로 비교한다. 부동소수점 반올림이나 지수 표기를 허용하지 않는다.

양수 USDT wallet과 총 wallet/margin/available 값이 같고 미실현 손익·초기/유지/포지션/주문 증거금은 모두 0이어야 한다. USDT 자산 행은 하나이며 다른 자산이 있으면 해당 잔액·증거금도 모두 0이어야 한다. 자산 행은 최대 32개, 포지션 행은 최대 500개이며 중복을 거부한다. 모든 포지션은 BOTH·수량 0·손익과 증거금 0이어야 한다. 응답에 dualSidePosition/multiAssetsMargin이 있으면 정확한 boolean false만 허용한다. 이 필드가 없다고 설정을 추정하지 않는다.

검사 성공은 응답에 적힌 제한된 flat-USDT 산술 관계만 확인한다. 다른 GET에서 확인할 계좌·심볼 설정, 일반/알고 미체결 주문 없음, 원격 계좌 신원, 누락 없는 외부 이력은 증명하지 않는다. 응답의 uid/accountAlias 같은 임의 필드로 신원을 만들어 내지 않는다. 출력에는 잔액 금액이나 계좌 식별자를 포함하지 않는다.

근거 제안 입력은 선택 사항이다. 입력이 없으면 사용자 진술이나 수락을 추정하지 않는다. 입력 시에는 account 영수증 SHA256·credential_context_id, 저장 일/주·대상 일, UTC 이력 시작/종료, 신원·이력·평가 자료의 SHA256, 평가 방식, 명시적인 진술/근거 수락 주장 boolean을 정확한 필드로 요구한다. 계좌 응답의 문맥·해시와 현재 대상 일을 대조한다. 이력 시작은 제시한 저장 일의 한국 자정보다 늦을 수 없고 종료는 수집 종료 이후·현재 관측 이전이어야 한다. Monday 주간 경계의 같은 주 일간 전환만 지원하며 주간 전환은 별도 검토로 차단한다.

`proposal_input_shape_complete=true`는 형식과 구간의 요건을 만족했다는 뜻이다. 참조 자료의 실제 내용, 입력한 저장 기간과 실제 원장의 일치, 신원·이력·평가 증명 또는 사용자 수락 검증을 뜻하지 않는다. 이 후보는 참조 파일을 열어 검증하거나 진술을 저장하지 않는다. caller_claims_present는 호출자가 주장을 전달했다는 뜻이며 사용자의 독립 진술 확인이 아니다. 참조 SHA256이 올바른 길이여도 referenced_proofs_verified는 false다.

계속 필요한 것은 원격 계좌/자격증명 증명, 계좌·심볼 설정, 일반/알고 미체결 주문, 전체 거래·수입·이체 이력, 자정 평가 또는 재구성 근거, 명시적 사용자 진술/근거 수락, 과거 미해결 요청의 독립 원격 증거, 적용 직전 기간·손실·고점 한도 재검사다. baseline_source_accepted와 baseline_adoption_approved는 항상 false이며 원장·일/주 키·요청·체크포인트를 변경하지 않는다.

다음 범위는 새 임시 복사본에서 시계·보조 연결·원문 수집·내용 검사를 함께 연결하는 격리 실행 경계의 검증이다. 실제 서명 GET 실행과 날짜 채택은 별도 단계로 남긴다. 지금 사용자가 실행할 추가 명령이나 USB 연결은 필요하지 않다.

관련 테스트 124개가 87.12초에 통과했다. ruff와 후보 모듈 mypy도 통과했다. 합성 PostgreSQL/SQLite 원문 보관·읽기 전용 보존 검사, 내용/입력 거부 검사, 네트워크 없는 기존 이미지의 import/default-denial 검사를 포함한다. 상세 범위는 COPY_ACCOUNT_CONTENT_VALIDATION.json에 기록했다.
