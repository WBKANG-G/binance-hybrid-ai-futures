# Windows 합성 증거 검토 패키지

`windows-demo-copy-evidence-rehearsal-20261115.zip`을 준비했다. 사용자 텍스트로 받은 직전 COPY_CLOCK_RECEIPT.json SHA256 `8bd24518a93cb977479dbcaed2670236c256386ac400e9b129f35965a167d6f5`를 고정했다. 이전 화면에서 읽은 63자리 값은 사용하지 않았다. 그 영수증의 코드 참조는 기존 시계 패키지 CONFIG.json과 대조한 `4d1d90e8815e405d8f338a8e972ae1acff10b7e6`다.

패키지는 백업·복구·읽기 전용 진단 영수증뿐 아니라 직전 시계 성공 영수증과 보존된 helper/볼륨도 검증한다. 시계 영수증의 감사/체크포인트 계보, 시작 대기, boot/clock 일치, V2 미연결, 기존 기간·미해결 요청 수, 이미지·마운트·네트워크 none·정상 정지·재시작 no를 확인한다. 입력 파일을 읽기 핸들로 잠그고 실행 후 해시를 다시 확인한다.

기존 시계 사본을 시작하지 않는다. 원시 백업에서 별도의 새 DB/runtime/socket 볼륨을 복원하고 새 사본에서 시계 전환과 시작 대기, V2 보조 연결, 합성 계좌 응답 1회, 원문/감사 연결 및 내용 검사를 실행한다. 원본·기존 사본·USB·키 세션은 사용하지 않는다. 기준 이미지 89개 파일을 대조하고 후보 10개를 메모리에만 올린다. helper는 네트워크 none·비 root·읽기 전용 루트이며 DB는 새 Unix socket으로만 접속한다.

합성 잔액 12는 실제 잔액이나 새 날짜 기준이 아니다. 실제 API 키와 실제 거래소 HTTP는 사용하지 않는다. 사용자 입력 기준 감사 이력은 새 복사본에서 시계 단계 55→56, 합성 조회 단계 56→58이 예상된다. 기존 원장·34개 주문·4개 미해결 요청·저장 일자 2026-11-13 및 주간 기준은 보존한다. 날짜 채택·미해결 요청 해소·실제 증거 수집·설치·주문 승인은 없다.

ZIP SHA256은 `dd9fb020cfbc668a7cdb3d428ef68c60e57c82f7abbb8230965a164281868e63`다. 소스는 `3ff5bc4`로 고정했고 ZIP 28개 항목 및 모든 후보 파일을 소스와 대조했다. 최종 ZIP을 읽는 검사 24개와 실제 Docker 수명 주기 검사 1개가 통과했다. Docker 절차는 288.34초에 완료됐으며, 두 단계의 실제 시작 대기와 새 복사본 정상 정지·입력 해시 재검사를 포함한다.

Docker에서 사용한 코드 바이트가 최종 ZIP과 같은지 대조했다. Linux의 테스트 입력 탐색·ACL 함수는 파일 뒤에 대체 함수로 추가하며, 합성 백업/복구/시계 영수증의 해시와 경로를 테스트 자료로 바꾼다. 따라서 실제 Windows ACL·사용자 데이터·실제 PC 실행 또는 원격 계좌 신원 검증을 주장하지 않는다. 이 절차의 합성 감사 이력은 0→1→3이며 사용자의 55→56→58과 구분한다. 상세 근거는 artifacts 폴더의 SOURCE_MANIFEST.json, VALIDATION.json, DOCKER_EXECUTION_VALIDATION.json에 있다.

USB를 분리한 상태로 유지한다. Docker Desktop 엔진은 실행하고 기존 컨테이너는 정지 상태로 둔다. ZIP을 바탕화면에 풀고 명령 프롬프트에서 해당 폴더로 이동해 RUN_CHECK.cmd를 실행한다. 성공할 때만 RUN_EVIDENCE_REHEARSAL.cmd를 한 번 실행한다. 70초 이상 대기와 진행 메시지가 표시되며 완료될 때까지 창을 닫지 않는다.

성공 표시는 `COPY_SYNTHETIC_EVIDENCE_VERIFIED_NEW_COPY_STOPPED_NO_ORDERS`다. COPY_EVIDENCE_RECEIPT.json과 새 자원은 보존한다. 실패하면 새 복사본에 시계·보조 연결·감사·원문 일부가 남을 수 있으므로 반복 실행하거나 삭제·수리하지 않고 출력 JSON을 검토한다. 현재 실제 Windows 실행은 아직 관측되지 않았다.
