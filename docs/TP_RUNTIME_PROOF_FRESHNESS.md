# Fresh observations before full-proof admission — synthetic review

After bookTicker was excluded from weight observations, a separate batch-admission gap remained. The original WindowTPBudget.require_proof checked untrusted metadata and available modeled weight, but did not require a current observation. At age 5.001, 6 and 60.002 seconds, the prior owned runtime admitted the proof budget check. The individual HTTP gate still rejected stale non-clock requests; these reproductions do not demonstrate an actual exchange send or weight overrun.

OwnedSharedBudget.require_proof now checks monotonic time and requires the existing authoritative observation to be no older than five seconds before delegating to the original local/shared cost checks. Missing or stale observations cause ProofDeferred, without transport, shared reservation, domain write or journal mutation. Five seconds exactly remains accepted, matching the existing policy. Diagnostics distinguish these deferrals from capacity deferrals. This does not certify a route's observed header as an actual cost upper bound.

There is no new polling or retry loop. The existing coordinator confirm_exit_budgeted already makes a scoped WATCH clock read before proof when metadata is stale, and handles ProofDeferred with its existing bounded wait/deadline. An explicit accepted GET /fapi/v1/time can supply a new observation and the next check applies the original capacity rules. The clock read retains its normal modeled charge and durable shared completion record. A clock response failure, missing trustworthy header or 418/429 cannot reopen proof admission. A transport-uncertain request stays pending; it is not marked completed or refunded. A backward/nonfinite clock remains a hard stop, not a recoverable metadata deferral.

The proof check is admission only, not a reservation for a whole batch or proof of flatness. Every individual request still passes the original method/query, scope, ownership, cost, shared and durable order controls. The full historical/signed confirmation alone can establish VERIFIED_FLAT. A caller can still lose freshness after this check; the individual gate remains responsible then. Existing cleanup deadlines, canonical CLI and historical installed source files are unchanged.

Tests reproduce three before-fix failures and cover fresh boundaries, missing observation, repeated no-send deferrals, explicit read recovery, missing/throttled/lost refresh responses and clock regression. Stale deferral leaves account/event/outbox snapshots and both journal trees unchanged. Refresh failures preserve a pending weight-one attempt. TP and partial-fill cleanup continue through the original full-flat proof with missing/exaggerated bookTicker headers and an independent synthetic meter. Startup holds are accelerated; observation is 0.8 seconds. These are not fresh 300-second or actual exchange measurements.

Actual account order usage, external IP capacity and complete request-cost upper bounds remain unproven. Default production execution is disabled; no Windows installation or Windows DB change, actual exchange request or real order occurs in this development review.
