# 오프라인 검토 결과의 새 파일 저장

전체 저장소에서 다음과 같이 사용합니다. 결과 경로의 부모 디렉터리는 미리 있어야 합니다.

```bash
python -m scripts.review_runtime_confirmation_report report.json --save-receipt receipt.json
python -m scripts.review_runtime_confirmation_report report.json --verify-receipt receipt.json
```

`--save-receipt`는 명시적으로 새 파일만 생성합니다. 기본 표준 출력 방식과 읽기 전용 `--verify-receipt`는 유지됩니다. 두 옵션을 함께 지정하면 거부합니다. 저장한 JSON은 표준 출력의 검토 결과와 같고 기존 영수증 정책·버전·바이트 연결 형식도 유지됩니다. 정상 검토는 종료 코드 0, 추가 검토가 필요한 유효한 결과는 3, 입력·저장 오류는 2입니다. 코드 3도 결과가 정상 저장될 수 있습니다.

원본과 같은 정규화 경로는 읽기 전에 거부합니다. 기존 파일, 디렉터리, 하드 링크, 심볼릭 링크(끊어진 링크 포함)는 교체하지 않습니다. 입력 검토가 끝난 뒤 대상과 같은 디렉터리에 비공개 임시 파일을 만들고 전체 내용을 기록·flush·fsync한 다음 배타적인 하드 링크로 완성된 파일을 게시합니다. 경합 중 다른 프로세스가 만든 대상도 덮어쓰지 않습니다. 하드 링크를 지원하지 않는 파일 시스템에서는 실패하며 직접 쓰기나 덮어쓰는 이름 변경으로 우회하지 않습니다. 부모 디렉터리를 자동 생성하지 않습니다.

저장 오류에는 고정 코드와 `storage_publication_attempted`, `storage_publication_confirmed`, `temporary_cleanup_incomplete`만 보고하며 원본 경로·운영체제 오류 세부 내용은 출력하지 않습니다. 게시 호출이 오류를 반환했어도 파일이 만들어졌을 가능성이 있습니다. 게시 성공 뒤 임시 파일 정리가 실패하면 완성된 결과와 임시 파일이 남을 수 있습니다. 이런 경우 종료 코드는 2이며 최종 파일을 삭제하거나 재작성하여 되돌리지 않습니다. 기존 결과는 `--verify-receipt`로 읽기 전용 대조할 수 있습니다. 같은 경로에 자동 재시도하여 덮어쓰지 마십시오.

지원 파일 시스템에서 완성된 새 디렉터리 항목의 배타적 게시를 검사합니다. 부모 디렉터리 fsync, 전원 장애 후 영구 보존, 악의적인 동시 디렉터리 항목 교체까지 인증하는 기능은 아닙니다. 입력 파일은 한 번 읽은 버퍼와 연결되므로 읽은 후 외부에서 변경된 현재 경로를 인증하지 않습니다. 셸의 `> report.json` 같은 리다이렉션은 Python 실행 전에 파일을 자를 수 있어 이 기능으로 보호할 수 없습니다. 파일 저장에는 명시적 옵션을 사용하십시오.

해시·대조 성공은 보고서 출처, 서명, 현재 거래소 상태, 금융 증명 재실행 또는 실행 승인이 아닙니다. 모든 결과의 `execution_approved`는 false입니다. 금융 실행 코드·거래 재개·Windows 설치·실제 거래소 요청은 이 변경 범위에 없습니다.
