# bookTicker weight observation provenance — synthetic review

The pinned official SDK says bookTicker's X-MBX-USED-WEIGHT-1M is inaccurate and should be ignored. See `request_cost_evidence/PINNED_PUBLIC_QUERY_PROOF.json`. Previously the owned runtime let that header replace both its local observation and durable shared floor, and a missing header poisoned admission. Five before-fix cases reproduce this with 0, 999999, missing, malformed and negative values. These are synthetic responses; no exchange overrun was measured.

The owned runtime now excludes GET /fapi/v1/ticker/bookTicker from weight observations. The same response/body/header objects reach the original client. Modeled cost 2 remains charged locally and durably; a known completed response retains that cost for the full window after completion, without creating a weight floor. Earlier trustworthy floors continue to include later charges. The shared PostgreSQL checkpoint covers this completion through the existing transaction hooks. The SQLite schema and rollback checks are unchanged.

The installed historical WindowTPBudget remains byte-identical. The opt-in OwnedSharedBudget adapts its response observation only: it captures metadata after the sender returns, restores the four observation fields, and suppresses only the known bookTicker missing-header marker. Capturing after transport preserves nested trustworthy observations. Per-instance context and the existing lifetime lock isolate nested requests. Cost, attempt history, clock faults, actual transport failures, throttle states and UNKNOWN records are never restored/refunded. All other routes keep the existing strict missing-header behavior. SharedManagedOrderWindowBudget defaults to observing headers; only the owned runtime opts into this policy.

A bookTicker response never refreshes the five-second observation deadline. If there is no fresh authoritative observation, admission remains blocked by the existing freshness guard; no automatic polling/retry or substitute header is added. 418/429 and invalid statuses still poison shared admission and retain the pending request. A real transport failure still stops both layers.

Focused tests cover the five original failures, stale metadata, 418/429 with and without headers, transport failure, nested trustworthy observation, another route's missing header, and shared completion retention/invalid statuses. The full TP lifecycle uses missing quote headers; partial-fill cleanup uses exaggerated quote headers. The independent synthetic wire meter remains unchanged. Both must still pass the original full flat proof. Startup holds are accelerated and the observation is 0.8 seconds; this is not a fresh 300-second or exchange validation.

This fixes a metadata provenance defect, not the production admission proof. The official bookTicker nonauthority warning remains in the query-contract report; quote_header_policy separately records how it is handled. Actual account order usage, external IP pressure and complete request-cost upper bounds remain unproven. Production execution stays disabled. No Windows installation, Windows DB change, live exchange request or real order was performed.
