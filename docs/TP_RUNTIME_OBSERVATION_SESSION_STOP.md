# 관찰 대기 중 수신 실패 후 일반 재조회 중단

EventInbox는 수신 오류를 만나면 즉시 coordinator.session_failed를 설정합니다. 기존 관찰 대기는 그 값을 확인하지 않아, 대기 중 수신기가 실패하거나 공유 예산 점검 중 실패가 도착해도 예산 반환 뒤 원래 일반 재조회를 다시 호출할 수 있었습니다. 수정 전 단절 시나리오의 두 검사(대기 중, 예산 반환 직전)가 모두 예상 거부에 실패했습니다.

새 관찰 세션 검사는 원래 연결·소유권 검사와 함께 session_failed를 확인합니다. 관찰 시작 전, 대기 반복, 예산 반환 뒤 소유한 청산 상태 재확인, 원래 일반 재조회에 들어가기 전에 검사합니다. 예산 점검 후 원장이 바뀐 경우도 같은 재확인에 걸립니다. 원래 120초 시작 기한은 마지막 상태 확인 후에도 다시 검사합니다.

이 검사는 일반 관찰을 중단합니다. 예산이나 공유 저장소를 새로 오염시켜 위험 축소 경로까지 막지 않으며, 이미 실패한 시험을 다시 정상으로 만들지도 않습니다. 기존 fenced 위험 축소, 원래 전체 금융 청산 확인과 봉인, 동일 coordinator의 단일 확인 호출 규칙은 그대로 유지합니다. 원래 소스의 수신·이벤트 검증·진단은 수정하지 않습니다.

수정 뒤 작은 검사는 실제 EventInbox로 연결 단절, listenKeyExpired, 오래된 이벤트, 잘못된 JSON, 128개 상한을 넘은 대기 이벤트를 발생시킵니다. 대기 중과 예산 점검 반환 시점 각각에서 일반 재조회가 재개되지 않는지 확인합니다. 이미 실패한 세션은 flat 힌트가 없어도 재개하지 않습니다. 이 작은 검사에서 원래 일반 재조회 진입은 표시용 함수로 대체되며, 전체 금융 실행 검사는 별도로 수행합니다.

별도의 전체 실행 검사는 합성 HTTP·격리 PostgreSQL·실제 localhost WebSocket을 사용합니다. TP가 체결되고 로컬 청산 상태가 확인된 뒤, 전체 관찰 조회 예산 점검에서 ProofDeferred를 한 번 주입하여 대기 위치에 도달하게 합니다. 이 주입은 실제 계정 예산 부족을 실측한 것이 아닙니다. 대기 중 서버 소켓을 실제로 닫고 원래 EventInbox의 실패 플래그를 기다립니다. 이후 원래 전체 청산 확인과 봉인을 수행합니다.

이 오류 검사의 정상적인 결과는 다음과 같습니다.

- 신규 진입 한 번, 추가 진입·임의의 위험 축소 주문 재시도 없음
- 원래 시험 결과 UNKNOWN / NOT_ACCEPTED 유지
- 별도 전체 금융 확인 VERIFIED_FLAT, 세션 실패를 남긴 PROOF_VERIFIED_SESSION_FAILED
- 과거 기록·기준값 보존, paused 유지, 실행 승인 false

이 결과를 TP 성공이라고 집계하지 않습니다. 오류 처리 검사 자체가 예상 동작을 통과했다는 의미입니다. 정상 TP·부분 체결·봉인 실패 경로도 새로 실행해 검증합니다. 시작 대기는 가속되고 정상 짧은 관찰은 0.8초, 수신 오류 관찰의 설정 상한은 10초이며 실제 실패가 발생하면 더 일찍 종료됩니다. 새로운 300초 자연 관찰을 수행했다고 주장하지 않습니다.

이전 공통 WSS 테스트 fixture는 그대로 보존하고 오류 주입용 서버 wrapper를 별도 추가했습니다. wrapper는 localhost에만 연결합니다. 수신 실패 후 이미 실행 중인 동기 DB/HTTP 작업을 강제로 취소하지 않으며, 검사 순간과 다음 명령 사이에 어떤 다른 스레드도 상태를 바꿀 수 없다는 원자적 보장은 하지 않습니다. 기존 settled_call의 작업 완료·취소 처리와 fencing은 유지합니다.

요청 비용표·SDK 문서 근거·요청 한도와 여유는 바꾸지 않았습니다. 실제 계정 주문 사용량·외부 IP 여유·실제 거래소 비용 상한은 여전히 별도 검증 대상입니다. Windows 설치·DB 변경, 실제 거래소 요청·주문·거래 재개는 수행하지 않습니다. 실제 검사 수와 통과 여부는 검토 ZIP의 VALIDATION.json 및 evidence/에 기록합니다.
