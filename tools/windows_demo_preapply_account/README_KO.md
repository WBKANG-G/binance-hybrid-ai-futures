# 출처 수락 연결 후 현재 데모 계정 재조회

RUN_CHECK.cmd 성공 후 RUN_READ_PREAPPLY.cmd 한 번만 실행한다.
DEMO API Key/Secret을 로컬 숨김 입력에만 넣는다. 채팅/명령줄/환경변수에 넣지 않는다.
원본 DB/Docker/API/키 세션은 시작하지 않는다. 고객지원·USB는 필요 없다.

수락한 범위는11/18 일자·11/16 주 시작·일/주 각각4998.74183608 USDT 후보의 출처다.
질문에 대한 실제 사용자 답변을 검토 ID/후보/한계와 묶어 기록했다. 정확한 메시지 시각은
제공되지 않아 날짜만 기록한다. 이 기록은 대화상 수락의 해시 연결이며 외부 서명 증명이 아니다.
원본 쓰기/시작/owner 인수/보호 조건 해제/과거 요청 처리/거래 승인은 포함하지 않는다.
이전 검토 JSON의 acceptance=false는 수락 전 문서의 불변 내용이다. 현재 수락은 별도
SOURCE_ACCEPTANCE.json으로 연결하며 미증명 자정/전체 이력/최초 자금 사실은 그대로 둔다.

사전 검사는 전송 파일 해시, 수락 기록과 후보, 기존 income/trade 저장 파일 연결만 검사한다.
키를 읽거나 HTTP/파일 쓰기를 하지 않는다. 실제 조회는 기존 검증된 DEMO 전용 GET 전송으로
현재 전 종목 미체결 일반/조건부 주문·포지션·USDT 잔액을 두 차례 읽고, 단방향/단일자산/
BTC격리2배/자동 증거금 추가 해제 설정과 공백 구간 수입/BTC 체결도 확인한다(보통18HTTP).
아무 설정이나 주문을 변경하지 않는다. 수량/과거 요청도 바꾸지 않는다.

저장 잔액과 다르거나 포지션/주문/활동/설정 불일치가 있으면 중지한다. 이전 도구는 불일치
관측을 저장하면 일반 수집 성공으로 표시할 수 있었지만 이 패키지는 issues가 비어야 계정
일치로 표시한다. 수락한 기간과 현재 조회 기간이 다르면 새 기간 검토 필요로 별도 표시하고
preapply_account_conditions_matched=false를 유지한다. 수락한18일/16일을23일로 옮기지 않는다.
조회 중 날짜/주가 바뀌면 중지한다. 기존 참조 이후7일을 넘는 공백은 조회하지 않는다.
이7일 조회 범위 제한은 기존 원장 적용 함수의7일 제한과 별개이며 어느 제한도 해제하지 않는다.

새 응답과 영수증은 WBKANG-DEMO-PreapplyReads/preapply-account-20261123-...에만 저장해
기존 CurrentReads의 유일한 원본 참조 선택을 방해하지 않는다. 원문 응답은 private NTFS
폴더에 저장하며 키/Secret은 저장하지 않는다. 기존 source 파일도 수정하지 않는다.
실패 시 부분 기록을 보존하고 자동 재시도하지 않는다.

수락한 기간과 같은 기간의 계정 일치: PREAPPLY_ACCOUNT_MATCHED_NO_ORIGINAL_WRITE_NO_ORDERS
새 기간에서 계정 프로필 일치: CURRENT_ACCOUNT_MATCHED_NEW_PERIOD_REVIEW_REQUIRED_NO_ORDERS
11월23일 조회라면 후자가 예상된다. 이 경우 accepted_period_matches_observed_period=false이며
새 기간의 수락이나 적용 승인이 아니다. 계정 일치는 수집 당시 잔액/포지션/설정 관측의 일치다. 장래 시점의 신선함이나 원본 지문/
버전/정지/권한 인수/실제 적용 준비 완료를 증명하지 않는다. original_apply_ready=false이며
원본 적용·거래 재개는 여전히 별도 검토 사항이다. 결과 화면만 확인하고 원문/키는 공유하지 않는다.
