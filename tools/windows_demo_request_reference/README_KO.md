# 보존 원장 사본에서 과거 요청 4건의 대조 정보 읽기

ZIP을 바탕 화면에 압축 해제하고 RUN_INSPECT.cmd를 한 번 실행합니다.
USB 연결, Docker 시작, API 키 입력은 필요하지 않습니다.

고정된 원본 manifest.json SHA256과 runtime.tar SHA256을 확인합니다.
백업 안의 일자13 채택 이전 old_row.state와 과거 조회 계획을 메모리로 읽고,
미해결 4건의 요청 해시/역할/상태와 매칭되는 주문의 거래소 번호·가격·수량만 출력합니다.
현재 원장 상태를 읽거나 복구하는 것은 아닙니다. 과거 스냅샷임을 결과에 표시합니다.
요청 해시는 기존 조회 계획과 일치해야 하며 주문34/미해결4/진입2·손절1·종료1 조건을 검사합니다.
원래 Client Order ID, 계정 원문, 키, 원문 응답은 출력하지 않습니다.
서버 번호가 없으면 null입니다. 종료 주문의 서버 번호 대신 진입 주문번호를 넣지 않습니다.
entry_server_order_id는 관련 진입 주문번호이며 종료 주문번호가 아닙니다.
signal_closed_candle_at_utc는 신호 기준 캔들 시각이며 체결/주문 생성 시각이 아닙니다.

tar.exe는 -xOf로 지정 JSON을 표준 출력으로 읽는 데만 사용합니다.
디스크 압축 해제·저장 파일 변경·컨테이너 시작·거래소 조회·주문·자동 재시도가 없습니다.
백업을 읽는 동안 읽기 전용 공유 스트림을 유지하고 끝에서 두 해시를 재확인합니다.
오류 시 원문 대신 고정 오류 코드만 출력합니다. 오류가 나면 결과를 확인하고 임의 추출하지 마세요.

이 출력은 거래소 화면의 주문번호와 비교할 출발 자료입니다.
과거 미해결 요청 해소, 계정 신원 독립 확인, 전체 이력 검증, 기준액 채택이나 거래 재개 승인이 아닙니다.
원본·복구 사본 정지와 USB 분리 상태를 유지하세요.
