# 복원 원장 보고서와 기준금액 후보 연결

RUN_LINK.cmd 한 번을 실행한다. API 키·Docker·USB 연결이 필요 없으며 기존 파일만 읽는다.
기존 income→trade→current 원문/영수증 및 백업 기록을 다시 연결하고, 고정 성공 복원 영수증의
SHA256·원본 백업 manifest/보존 영수증·복원 source·read-only SQL 원장 보고서를 검증한다.
복원 원장 기준일/주, 주문34·미확정4·paused를 저장된 채택 보고서와 대조한다.

결과는 조건부 변경표다. 원장 실제 쓰기/금융 diff 확정/기준금액 수락/거래 재개를 하지 않는다.
복원 SQL 보고서의 원장 지문은 금융 금액 전체를 담은 보고서가 아니므로, 금액의 변경 전 값은
고정 과거 재무 기록에서 가져온다는 한계를 명시한다. 현재 원본 SQL을 조회하지 않는다.
PostgreSQL state::text 지문과 Python canonical JSON commit hash는 직렬화 방식이 달라
서로 같은 해시여야 한다고 검사하지 않는다. byte 대조는 이전 사용자 성공 화면의 관측 사실로
기록하며, 이번 도구가 물리 비교를 새로 수행했다거나 영구 영수증을 검증했다고 하지 않는다.

성공: RECOVERY_LINK_COMPLETE_CONDITIONAL_DIFF_NO_APPLY_NO_HTTP_NO_WRITES
현재 저장 후보는 2026-11-18 KST 일/2026-11-16 주에 대한 것으로, 이후 날의 최신 금액이 아니다.
실행 오류가 있으면 결과 화면만 확인하고 원본/사본 컨테이너를 수동 시작하거나 삭제하지 않는다.
