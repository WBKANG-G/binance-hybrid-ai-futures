# 중지된 원본과 백업의 파일 비교

바탕화면에 압축을 풀고 RUN_CHECK.cmd를 실행한다. 성공하면 RUN_COMPARE.cmd를 한 번 실행한다.
Docker Desktop은 기존 상태로 두고 원본 API·DB·키 세션이나 사본 DB를 수동 시작하지 않는다.
API 키 입력·고객지원·USB D: 연결은 필요 없다.

기존 보존 영수증·상태·manifest·archive·이미지 해시, 원본 7개 컨테이너의 중지 및 재시작 no,
원본 ID·볼륨·이미지 관계와 외부 볼륨 소비자 부재를 기존 검증기로 검사한다.
비교 시 캐시된 고정 API 이미지로 새 보조 컨테이너 하나만 생성·실행한다. 원본 볼륨 두 개만
읽기 전용으로 마운트하고 네트워크 없음·루트 읽기 전용·재시작 no로 제한한다.
DB 서버나 애플리케이션은 실행하지 않는다. 루트 사용자와 DAC_OVERRIDE는 기존 PG 파일을
읽기 위해 쓰며 원본 볼륨은 읽기 전용이다. 키 마운트·환경변수 조회·출력 볼륨은 없다.

두 번의 전체 순회에서 파일 집합·종류·크기·SHA256·소유권·권한·mtime을 고정 manifest와
대조한다. 누락·추가 파일, 링크·특수 파일·확장 속성이나 내용/메타데이터 차이는 차단한다.
중지 상태·컨테이너 구성을 비교 전후 다시 확인한다. 외부 프로세스 동시 접근 전체를
운영체제 잠금으로 배제하는 검사는 아니며 Docker 제어권이 외부에서 악의적으로 바뀌지 않는다는
운영 조건이 필요하다. 데이터 볼륨의 파일을 수정하거나 PID/WAL을 정리하지 않는다.

성공 마지막 줄:
SOURCE_BYTES_MATCH_BACKUP_NO_ORIGINAL_START_NO_LEDGER_CHANGE

성공은 물리 파일이 백업 시점과 일치한다는 뜻이다. 실제 DB에 SQL 질의를 수행하지 않아
current_database_logical_state_verified=false로 남는다. 별도 사본 복구 원장 보고서와의
연결 및 변경 전후 재무 diff 확정은 후속 단계이며, 미확정 요청 해소·기간 기준금액 채택·
재개 승인이 아니다. 새로운 보조 컨테이너는 중지된 채 남기고 자동 삭제하지 않는다.

실패하면 재실행하지 말고 화면 결과만 확인한다. 남은 보조 컨테이너를 임의 시작/삭제하지
않는다. 원본 파일·백업·키는 업로드하지 않는다. 사용자의 실제 Windows 실행은 별도로
관측해야 하며 Linux 시험을 사용자 원본 검증으로 표시하지 않는다.
