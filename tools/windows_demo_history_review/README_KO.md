# 저장된 주문 이력의 배열 집계 수정 — 오프라인 검토

사용자 화면의 알고 응답 해시 4f53cda18c2baa0c0354bb5f9a3ecbe5ed12ab4d8e11ba873c2f11161202b945는
UTF8 []의 SHA256과 같다. 빈 배열이 1건으로 보인 것은 PowerShell 5.1의 ConvertFrom-Json
파이프라인 출력이 배열을 하나의 값으로 전달하는 동작과 기존 파서가 맞지 않았기 때문이다.
빈 배열/다중 행의 집계와 ID 후보 대조가 잘못될 수 있어 이전 수치를 그대로 사용하지 않는다.

RUN_REVIEW.cmd만 실행한다. API 호출, 키 입력/접근, 파일 쓰기, 내보내기 생성은 없다.
기존 RUN_READ_HISTORY.cmd나 RUN_REQUEST_EXPORT.cmd를 다시 실행할 필요가 없다.

고정된 기존 백업으로 요청 해시를 다시 읽고, 보호된 LOCALAPPDATA의 history-read-20261117-*
폴더에서 성공 영수증과 INTENT를 찾는다. 두 응답의 SHA256을 로컬 영수증과 대조하고
알고 응답이 화면에서 관측한 [] 해시인 실행을 정확히 하나 선택한다. 후보 폴더는 최대 32개다.
기존 폴더 ACL을 검사하고, 파일은 읽기 공유 스트림으로 잠그고 끝에서 해시를 재검증한다.
일반 응답 해시는 로컬 영수증에 의존하며 독립 외부 해시 검증을 주장하지 않는다.

수정 파서는 JSON 배열을 객체 속성으로 읽어 0/1/다중 행을 동일하게 처리한다.
중첩 배열, null/스칼라 행과 1000행 초과는 거부한다. JSON 자체의 유효성도 먼저 확인한다.
화면에는 수정된 건수와 일치 후보 수, 원래 client ID를 제외한 제한된 주문 필드만 표시한다.
일반 미리보기는 최대 20개다. 그 밖의 임의 필드·오류 메시지·비공개 client ID는 출력하지 않는다.

정확한 ID 후보가 있어도 원장 해소/재개 승인으로 취급하지 않는다. 빈 목록과 1000행 미만
결과가 과거 미전송이나 전체 이력 완전성을 증명하는 것도 아니다. 기존 내보내기 작업의
접수 여부는 미확정으로 보존하고, 원본·복사본 정지와 USB 분리를 유지한다.
Windows PowerShell 5.1 실제 재분석은 사용자 실행 화면으로 확인해야 한다.
