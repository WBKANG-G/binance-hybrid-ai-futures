# 새 임시 복사본의 날짜·부팅 진단

USB를 연결하지 않습니다. PC 내부의 고정된 백업 manifest/receipt와 이전 성공 복구 영수증의 SHA256을 검증합니다. 원본·기존 복구 사본과 보관 helper의 정지/설정/마운트를 확인한 뒤 새 DB·runtime·Unix socket 볼륨만 만듭니다.

Docker Desktop 엔진은 실행되어 있어야 하며 기존 컨테이너는 정지 상태로 둡니다.

먼저 `RUN_CHECK.cmd`로 입력/정지 상태만 확인합니다. 성공 후 `RUN_COPY_REVIEW.cmd`를 한 번 실행합니다. 새 PG 복사본만 네트워크 없이 복구하고, 읽기 전용 runtime/socket만 연결한 비 root 진단 helper에서 후보 3개를 메모리에 올립니다. 기준 API 이미지 파일 89개의 해시를 먼저 대조합니다. DB 연결은 새 복사본의 Unix socket만 사용하며 모든 세션을 기본 읽기 전용으로 설정합니다. 키/기존 환경 변수는 사용하지 않습니다.

결과의 blockers는 다음 변경이 필요하다는 진단이며 실행 승인이나 오류 숨김이 아닙니다. 시계 재설정, 날짜 채택, schema 생성, 주문/실제 GET, 원본/기존 복구 사본 시작은 없습니다. 완료 시 새 PG 복사본을 정상 정지하고 입력 해시와 기존 컨테이너 설정을 다시 검사합니다.

새 helper/볼륨과 비공개 결과 영수증은 보존합니다. 실패하면 자동 재시도·복구·삭제하지 말고 출력 JSON을 확인합니다. 같은 실행기를 반복하면 새 자원을 만들 수 있으므로 임의로 반복하지 않습니다. `COPY_REVIEW_RECEIPT.json`은 이 진단의 별도 영수증이며 기존 복구 성공 영수증을 대체하지 않습니다.

독립 Windows ACL·실제 PC 실행 여부는 동봉 검증 기록과 구분합니다. 이 도구가 날짜/부팅 문제나 역사적 미해결 요청 4개를 해결했다고 표시하지 않습니다.
