# 현재 KST 일·주 범위의 자금 내역 수집

RUN_CHECK.cmd 성공 후 RUN_READ_INCOME.cmd를 한 번 실행합니다. 동일 데모 API Key와
Secret은 PC의 숨김 입력란에만 입력합니다. 키는 파일·환경변수·명령줄에 저장하지 않으며
채팅에 보내지 마세요. 프로세스 메모리/관리자로부터의 방어를 뜻하지 않습니다.

고정된 과거 백업과 진입 주문 2건을 대조하고 https://demo-fapi.binance.com의 GET만 사용합니다.
내보내기 생성/asyn/주문 전송·취소 경로는 없습니다. 기존 guard·원장·원본·복사본은 건드리지 않습니다.

서버 시각과 백업의 week_start_kst 설정으로 이번 KST 일·주 경계를 계산합니다. 대상은
이번 주 경계부터 잔고 조회 직후 고정한 cutoff까지이며 symbol/incomeType을 제한하지 않고
계정 범위의 모든 자금 흐름을 요청합니다. 과거 11월 13일이나 최초 지급액을 재구성한 것은 아닙니다.

ACCOUNT_BEFORE/AFTER, INCOME_PAGE_*.json, COLLECTION_INTERVAL_INCOME.json,
WINDOW.json, RECEIPT.json을 LOCALAPPDATA\WBKANG-DEMO-IncomeReads의 새 보호 NTFS
폴더에 보관합니다. 현재 사용자/SYSTEM만 허용하는 ACL과 파일 CreateNew·읽기 검증을 요구합니다.
HTTP 200 본문은 스키마 검사 전에 저장합니다. 원래 ID와 비공개 원문은 콘솔에 출력하지 않습니다.

일반 HTTP는 최대 10회이며 income은 페이지당 1000행, 최대 3페이지입니다. 1000행이
반환되면 다음 페이지를 한 번 조회하고, 새 거래 ID가 없거나 세 페이지 모두 가득 차면 중단합니다.
429/오류/시간초과의 자동 재시도는 없습니다. 분당 한도·현재 사용량에서 여유 300을 요구하지만
같은 IP의 다른 프로그램 사용량을 완전히 통제하지는 않습니다. income은 문서 기준 요청당 가중치 30입니다.

합산 키는 (incomeType,tranId)입니다. 동일 재정 필드의 반복은 한 번만 합산하고 금액/자산/
시각/종목이 충돌하면 중단합니다. 금액은 12자리 정수부·소수 8자리까지의 고정 소수 문자열만
Decimal로 처리합니다. 수수료·손익·펀딩은 income 표에서만 합산해 체결표와 이중 차감하지 않습니다.
USDC/BTC 등은 별도 행수로 표시하고 USDT 잔고에 더하거나 환산하지 않습니다.

수집 전후 USDT 지갑잔고가 같고 그 사이 자금 흐름이 없으며 검토되지 않은 USDT 유형이
없을 때만 과거 지갑잔고 후보를 계산합니다. KST 경계와 같은 밀리초의 이벤트가 있으면
해당 경계의 후보는 내지 않습니다. 페이지가 끝나도 서버 보관·반영 지연·충전/초기화의
전체 기록 완전성을 독립 검증한 것은 아닙니다. 기간 변경/불안정/불완전 결과는 후보가 없습니다.

현재의 평탄한 포지션은 과거 자정의 포지션 증명이 아닙니다. 출력은 지갑잔고 후보이며
계좌 평가액 기준 확정, 고점 초기화, 미확정 요청 해소, 원장 채택이나 거래 재개가 아닙니다.
최초 지급액을 기억하지 못해도 이 제한된 역산 후보 수집은 가능하나 증빙 한계는 보존합니다.

출력 화면만 공유하고 비공개 원문은 올리지 마세요. 실패 시 반복 실행하지 않습니다.
원본·복사본 정지와 USB 분리를 유지합니다. 실제 Windows 실행/서버 응답은 사용자 결과로 확인합니다.
