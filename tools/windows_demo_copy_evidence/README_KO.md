# 새 복사본 전용 합성 증거 경로 검토

USB를 연결하지 않습니다. Docker Desktop 엔진만 실행하며 원본·기존 복구 사본·시계 검증 사본 등 기존 컨테이너는 정지 상태로 둡니다. 이 실행기는 고정된 내부 백업·복구/진단/시계 영수증을 검증한 뒤 새 DB/runtime/socket 복사본을 만듭니다.

RUN_CHECK.cmd가 성공하면 RUN_EVIDENCE_REHEARSAL.cmd를 한 번 실행합니다. 최소 70초 이상의 시작 대기와 COPY_EVIDENCE_STAGE 진행 메시지가 표시됩니다. 창을 닫지 말고 완료 출력을 기다립니다.

네트워크 none, 비 root, 읽기 전용 루트의 helper에서 기준 API 이미지 89개 파일을 대조하고 후보 10개를 메모리에만 올립니다. DB 연결은 새 복사본의 Unix socket만 사용합니다. 복사본에서 시계 전환, V2 보조 연결, 합성 계좌 조회 1회, 원문/감사 연결 및 내용 검사를 수행합니다. 합성 잔액 12는 실제 계좌 잔액이나 새 날짜 기준이 아닙니다. 실제 API 키·키 세션·거래소 HTTP를 사용하지 않습니다.

원장·저장 날짜·주간 기준·기존 주문·미해결 요청 4개는 유지합니다. 날짜 채택, 실제 증거 수집, 미해결 요청 해소, 설치 또는 주문 승인은 없습니다. 성공 후 새 PG 복사본을 정상 정지하고 입력 해시와 기존 컨테이너 설정을 재검사합니다.

COPY_EVIDENCE_RECEIPT.json과 새 helper/볼륨을 보존합니다. 실패하면 보조 연결·감사 기록·원문 일부가 남았을 수 있습니다. 임의로 반복 실행·삭제·수리하지 말고 출력 JSON을 확인합니다. 실행기를 다시 누르면 또 새 복사본을 만들 수 있으므로 자동 재시도하지 않습니다.

clock 단계의 after_snapshot_sha256은 중간 상태입니다. 최종 상태는 copy_evidence_result.synthetic_evidence_rehearsal.after_snapshot_sha256입니다. 실제 Windows 실행/ACL과 별도 PC 검증은 클라우드 합성 테스트와 구분합니다.
