# 원본 DB 한정 시작·읽기·종료 실행안 — 승인 전 차단

이 ZIP은 검토용이다. 원본 DB 시작 승인은 아직 없으며, RUN_INSPECT.cmd는 ORIGINAL_START_APPROVAL_REQUIRED로 중단하도록 봉인돼 있다. 승인 파일을 임의로 만들거나 기존 source 승인 파일을 수정하지 않는다. RUN_CHECK.cmd는 원본 정지 범위와 고정 백업을 읽는 점검만 수행한다.

승인 요청 범위는 다음과 같다.

- 원본 서비스 컨테이너 DB/API/key-session 및 이전 복사본은 계속 정지한다.
- 기존 정확한 읽기 전용 helper로 원본 DB·런타임의 파일 내용·메타데이터를 고정 백업과 두 번 비교한다.
- 원본 DB 볼륨 hybrid-windows_postgres_data만 연결하는 임시 PostgreSQL 컨테이너 한 개를 만든다. 원본 런타임 볼륨은 그 서버에 연결하지 않는다. 새 볼륨은 만들지 않는다.
- 고정 백업의 정확한 캐시 이미지, PGDATA /var/lib/postgresql/18/docker와 그 디렉터리의 UID/GID를 사용한다. 외부 네트워크 none, TCP listen 없음, Unix socket /tmp, 재시작 no, rootfs read-only를 재검증한다.
- 서버 준비 대기 루프는 60초 기준으로 두고, REPEATABLE READ READ ONLY SQL을 두 번 실행한다. 원장 해시·재무·미해결 요청·소유권·fence와 미승인 기간 후보를 조회만 한다. row/advisory lock은 획득하지 않는다.
- 임시 서버에 PostgreSQL 정상 빠른 종료 신호 SIGINT만 보내고 30초 기준 관측 루프로 정상 종료를 확인한다. 강제 종료 SIGKILL, 원본 PID 파일 직접 삭제, 컨테이너/볼륨 삭제, 자동 재시도는 하지 않는다.

개별 Docker CLI에는 별도 최대 15초 제한이 있어 전체 소요 시간은 대기 루프 기준보다 길어질 수 있다. 종료를 확인하지 못하면 성공으로 표시하지 않는다.

**PostgreSQL 시작·종료 자체가 원본 볼륨의 WAL·복구·제어 파일 등에 기록할 수 있다.** SQL 기본값 read-only는 이 저장소 변경을 막지 않는다. 따라서 기존 원본 서비스 컨테이너를 시작하지 않더라도 원본 데이터베이스를 실제로 여는 별도 승인이 필요하다. postmaster.pid 등의 문제로 시작하지 못하면 자동 수정·재시작하지 않는다.

원장 UPDATE, fence 증가, owner/lease 인수·해제, 기준액 적용, 과거 요청 해소·재전송, 거래소 HTTP, 주문·실거래는 이 실행안에 포함되지 않는다. API 키를 입력하지 않는다. 실제 원본 쓰기 프로그램이나 apply 토큰도 생성하지 않는다.

승인이 부여될 경우 같은 질문·정확한 proposal 해시와 사용자 답변에 묶인 별도 승인 파일을 포함한 봉인 묶음을 제공한다. 이번 검토 ZIP은 그대로 실행 가능 상태로 전환되지 않는다. 승인별 결정적인 비공개 결과 디렉터리를 단일 시도 표식으로 사용하며, 실패 후 동일 승인을 재사용하지 않는다. COMMIT 같은 원장 쓰기는 없지만 DB 시작 결과가 불명확하거나 정상 종료를 확인하지 못하면 그 사실을 보고하고 자동 재시도하지 않는다.

성공하더라도 원본 DB 파일이 백업과 그대로 같다고 표시하지 않는다. 시작 이후에는 물리 파일이 달라질 수 있어 예전 백업과의 비교를 우회해 재실행하거나 원본을 덮어써서는 안 된다. 보고서는 LOCALAPPDATA의 WBKANG-DEMO-Backups 아래 승인별 비공개 폴더에 보존한다. 향후 원본 적용에는 별도 구현·검증·최신 계정 관측·쓰기 승인이 필요하다.
