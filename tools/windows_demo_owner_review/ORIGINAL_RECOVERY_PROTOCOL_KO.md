# 미승인 원본 복구 프로토콜 초안

이 문서는 원본 시작·쓰기·소유권 인수 승인이 아니며 원본 실행 프로그램도 제공하지 않는다. 이번 실행은 새 격리 복사본의 읽기 전용 SQL과 후보 JSONB 차이 조회까지만 수행한다. 복사본 DB 시작 자체는 복사본의 crash recovery·WAL 등 파일을 변경할 수 있으나 원본 볼륨은 연결하지 않는다.

일반 DemoStore.acquire는 fence를 증가시키고 원장을 모델로 다시 직렬화하며 리더 획득 이벤트·outbox를 기록한다. 이번 원본 복구에는 그 경로를 사용하지 않는 별도 유지보수 트랜잭션이 필요하다. 알 수 없는 기존 JSONB 필드와 과거 요청·원장 작업을 보존해야 한다.

향후 준비할 구체적인 순서는 다음과 같다.

1. 원본 writer들의 정확한 컨테이너·볼륨·정지·재시작 정책과 백업을 재검증한다. 승인 대상은 정확한 원본 볼륨 두 개와 전용 유지보수 경계로 한정한다. Docker 엔진, 원본 DB, API, key-session 시작을 구분한다.
2. **원본 DB를 여는 별도 승인** 이후에만, 기존 서비스는 정지 상태로 두고 TCP·외부 네트워크가 없는 임시 PostgreSQL 서버로 정확한 원본 DB 볼륨을 연다. 기본 read-only와 Unix socket만 사용한다. 이 단계도 crash recovery·WAL·제어 파일 등 원본 디스크를 변경할 수 있으므로 단순 파일 조회로 표현하지 않는다. 이번 묶음은 이 단계의 실행 코드를 포함하지 않는다.
3. 그 경계 안에서 원본 SQL의 state::text SHA256, fence, 소유자 해시·임대 기한 및 metadata hash를 다시 읽는다. 복사본 값이나 110을 원본 현재 값으로 대입하지 않는다. 그 결과와 정확한 계정·기간·금액·기존 소유권에 묶인 적용안을 다시 만든다. 기간 승인 자체는 원본 시작·쓰기·소유권 인수를 허용하지 않는다.
4. 실제 원본 적용 코드와 전체 쓰기 payload·감사 스키마·rollback 및 commit 불명확 경로의 검증을 끝내고 구체적인 변경안을 승인받는다. 현재 초안에는 승인 토큰이나 실제 원본 completion record가 없다.
5. 적용 직전에 같은 계정의 최신 소스 관측·원본 정지 범위를 재확인한다. 승인 범위·같은 주차·같은 금액·기존 양쪽 7일 간격·최신성 가드를 모두 만족해야 한다. 마지막으로 저장된 관측이 만료되면 새 관측이 필요하다. 트랜잭션 안에서 HTTP를 호출하지 않는다.
6. 짧은 단일 PostgreSQL 트랜잭션 안에서 계정별 advisory lock과 계정 row lock을 timeout과 함께 획득한다. DB 시계로 lease를 평가하고, 원본 state hash·fence·기존 소유권 전체가 승인된 기대값과 같은지 다시 검사한다. 활성 lease는 승인으로 덮어쓰지 않는다. owner가 남아 있고 lease만 만료된 경우에는 그 소유자 해시에 묶인 별도 인수 승인이 필요하다. owner/lease가 모순되면 먼저 원인을 검토한다.
7. 모든 조건이 맞을 때만 원본 JSONB에 허용된 기간 키·기준액·reconciled=false·stream_ready=false를 patch하고, 승인된 감사 항목만 operations에 추가한다. paused=true, 초기값 5000, high-water 5000, 손익 구성과 평가 시각, 34개 주문, 전체 요청·과거 operations 및 그 밖의 모든 JSONB 필드를 보존한다. 소유권 메타데이터의 변경도 정확한 기대값 CAS로 묶는다. 오프라인 복구 트랜잭션은 계정 리더 lease를 남기지 않고 종료하는 설계다.
8. 같은 트랜잭션에서 fence를 기대값에서 한 번만 증가시키고 completion 감사 항목·event·outbox를 모두 기록한다. 현재 복사본 기대값은 110→111 초안이며 원본에서 검증되기 전에는 확정값이 아니다. 원장/event/outbox 중 하나라도 실패하면 모두 rollback돼야 한다. 실제 payload와 보존 검증은 후속 원본 writer 구현에서 완료해야 한다.
9. COMMIT 응답을 잃으면 적용을 자동 반복하지 않는다. 원본 서버·트랜잭션 상태를 확인하고 operation ID, state hash, fence, 감사 기록, event와 outbox를 읽어서 정확히 일치하는지 판정한다. 찾지 못했다는 이유로 자동 재적용하지 않는다.
10. 별도 연결로 commit 결과와 보호 필드를 확인하고 원본 유지보수 DB를 정상 종료한다. API/key-session/알림·웹·주문 루프는 시작하지 않는다. 거래 재개는 미해결 요청·재조정·스트림·위험 가드가 별도로 충족된 후의 별도 범위다.

현재 확인하지 않은 것: 원본 SQL·현재 소유자·현재 fence·원본 row/advisory lock·원본 DB 시작 경계·실제 원본 writer·실제 원본 commit payload. 이 초안 또는 복사본의 만료 lease를 원본 쓰기 허가로 사용할 수 없다. 실패 시 원본 볼륨을 백업으로 자동 덮어쓰는 rollback은 제공하지 않는다.
