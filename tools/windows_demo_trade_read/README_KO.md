RUN_CHECK.cmd 성공 후 RUN_READ_TRADES.cmd를 한 번 실행합니다. 기존 데모 API Key와
Secret은 PC의 숨김 입력란에만 입력하고 채팅에 보내지 마세요. 키를 파일·환경변수·명령줄에
저장하지 않습니다. 메모리/관리자 접근으로부터의 보호를 뜻하지 않습니다.

기존 income-read-20261118-*의 성공 영수증·시각 창·잔고 전후 응답·빈 income 두 응답을
읽어 해시를 대조합니다. 11/18 일간·11/16 주간, 자금 변동 0건, 잔고 동일·포지션 0의

일치하는 실행이 여럿이면 임의로 최신 파일을 고르지 않고 중단합니다.

원래 고정 백업의 계정 대조 기준 2건을 새 서명 조회로 확인한 후, 저장된 주간 시작부터
이번 서버 시각까지 BTCUSDT /fapi/v1/userTrades를 조회합니다. 새 cutoff는 기존 자금 cutoff보다
5초 이상 뒤여야 하고 전체 구간은 7일 이하여야 합니다. 기간이 지나면 단축 조회로 위장하지 않고 중단합니다.

목록이 1000건이면 구간을 서로 겹치지 않는 두 절반으로 나눠 각각 한 번 더 조회합니다.
어느 절반도 1000건이면 불완전으로 중단합니다. 총 HTTP 최대 7회, 체결 요청 최대 3회이며
자동 재시도는 없습니다. GET 전용, demo-fapi.binance.com 고정, TLS 검증·리디렉션 금지,
요청 가중치 사전 여유 100을 요구합니다. 같은 IP의 외부 사용량 전체를 통제하지 않습니다.

금액은 중단합니다. Decimal로 손익/USDT 수수료를 대조하되 기존 지갑잔고 후보에 다시 합산하지 않습니다.
