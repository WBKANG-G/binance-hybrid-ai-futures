# 계정 설정 읽기 전용 비교 검사

현재 Windows 승인 소스 70a854ca677b0a8e3355b7f99ac0e0cce3bc6ba5에서만 실행합니다. 소스 31개의 SHA256이 다르면 키 조회 전에 중단합니다.

압축을 바탕화면에 풀고 RUN_COMMAND.txt의 두 줄을 CMD에 입력하세요. API 컨테이너가 실행 중이며 기존 DEMO 키 세션이 필요합니다. 세션이 없다면 기존 등록 명령 `docker exec -it hybrid-windows-api-1 python -m scripts.demo_key_session --ensure`를 사용하고, 키는 터미널의 숨김 입력에만 넣으세요.

기존 모드 두 조회 → 새 accountConfig → 새 accountConfig → 기존 모드 두 조회 순서로 비교합니다. 정상 경로는 서명 GET 6회, 공개 GET 2회입니다. 30초 요청 시작 기한, 최대16회 HTTP, 시계3회, 공개 한도60%와 추가100 가중치 여유 조건이 있습니다. 각 HTTP timeout5초 때문에 마지막 진행 중 요청은 시작 기한 후 끝날 수 있습니다. 418/429, 누락 필드, 문자열 bool, 미지원 모드, 응답 불일치, 누락 가중치 헤더는 즉시 중단하며 자동 재시도하지 않습니다.

성공 표시는 `TWO_MODE_FIELDS_MATCH_READ_ONLY_NO_RUNTIME_SWITCH`입니다. 추가 계정 설정 필드는 출력하지 않습니다. 실패 JSON의 stop_reason을 확인하세요. `DEMO_CREDENTIAL_SESSION_UNAVAILABLE`은 세션 재등록이 필요함을 뜻합니다. 소스 해시 불일치는 검사를 우회하지 말고 설치 버전을 확인해야 합니다.

이 검사는 DB에 접근하지 않고 주문/포지션을 조회하거나 변경하지 않습니다. 일자 기준값 일치나 계정 비어 있음도 확인하지 않습니다. 기존 주문 재개 명령을 실행할 근거가 아닙니다. 설치 파일, Compose 변경, 런타임 전환, TP 재시도는 포함하지 않습니다.

공식 SDK의 모델 가중치는 기존30+30, 새5입니다. 실제 DEMO 지원/필드 일치는 실행 결과를 받아 확인해야 합니다. IP 카운터 차이는 타 활동과 분 경계의 영향을 받으므로 개별 요청 비용 상한이나 활성 TP 가중치 예산 충족을 입증하지 않습니다.

## 격리 환경의 통합 검증

integration-review는 이전 closed-receipt parser 후보를 실제 공통 모듈에 적용한 격리 체크아웃 검토 자료입니다. 운영 파서 소비자7개가 동일 함수에 연결됨을 확인했습니다. full historical snapshot과 현존 주문/포지션 검사는 유지됩니다. 원본 코드와 패치는 검토용이며 Windows 설치 명령은 제공하지 않습니다.

운영 회귀1602개, 승인본의 버전 고정 가드52개, 새 읽기 전용 검사62개가 각각 통과했습니다. 추가 소비자9개 집중 실행은 운영 회귀와 중복되므로 합산하지 않습니다. 오래 걸리는 자연 lease SIGKILL5개 파일은 다시 실행하지 않았습니다. TEST_SCOPE.json을 참고하세요. 기존 private-stability 테스트의 시간 처리 문제는 승인본에서도 재현되어 테스트 관측 시계만 수정했으며, 실제25분 갱신 조건과30초 실시간 watchdog을 검증합니다. 운영 stability 코드는 변경하지 않았습니다.

실제 Windows 환경에는 이 후보 파서를 설치하지 않았습니다. 기존 설치 가드의 승인 해시는 확장하지 않았으며, 새 파서를 적용한 소스는 기존 가드가 키/DB 접근 전에 거부합니다. main 브랜치 변경/병합 없음, 실제 거래소 주문 없음, LIVE 활성화 없음.
