# 코드 설치부터 영속 저장소 구성까지 한 번에 진행

Windows PC는 현재 클라우드 실행 환경과 직접 연결되어 있지 않습니다. 이 패키지는 PC에서 명령 한 번으로 승인된 다음 단계들을 차례로 실행합니다. 이전처럼 각 단계마다 명령을 따로 입력할 필요가 없습니다.

ZIP 안의 `windows-demo-runtime-auto-setup-v2-20261111` 폴더를 바탕화면에 놓고 CMD에서 실행하세요.

```bat
cd /d "%USERPROFILE%\Desktop\windows-demo-runtime-auto-setup-v2-20261111"
RUN_NEXT.cmd
```

자동 진행 순서:

1. 전송 파일과 설치된 핵심 소스 55개를 검증합니다.
2. 제어 코드가 없으면 포함된 V3 설치기로 의존 파일 66개를 설치하고 사전/사후 원장 해시를 확인합니다. 이미 정확히 설치되어 있으면 이 단계를 건너뜁니다.
3. 11월 11일 적용 영수증, NORMAL·정지 상태, 원장상 노출 없음, 현재 일간/주간 날짜를 확인합니다.
4. 전용 SQLite 주문 한도·공유 예산 저장소와 PostgreSQL의 보조 테이블 3개·추가 전용 불변성 함수를 생성하고 등록 정보를 기록합니다.
5. 계정 리스를 해제한 상태에서 기존 공유 예산의 약 70초 시작 대기를 지킵니다. 대기 중에는 읽기 전용 상태 확인만 합니다.
6. 준비된 저장소를 검증하여 바인딩을 완료하고 완료 영수증을 기록한 뒤 다시 읽어 확인합니다.

이번 명령은 이미지 코드, 영속 저장소 파일, DB의 저장소 등록·감사 이벤트를 변경합니다. 일간/주간 기준금액·고점·평가 시각·청산 이력·기존 영수증은 해시로 보존합니다. 거래소 API나 DEMO 키 세션에 접근하지 않고 주문도 전송하지 않습니다. 주문 한도 writer session이나 거래 실행을 시작하지 않습니다. 신규 진입 일시정지와 실제 실행 기본 차단을 유지합니다.

성공 마지막 문구:

```
CODE_AND_STORAGE_CONFIGURED_KEEP_PAUSED_NO_ORDERS
```

마지막 JSON의 `runtime_storage_setup`은 `CONFIGURED_KEEP_PAUSED`입니다. 첫 실행은 코드 빌드와 약 70초 대기를 포함합니다. 완료된 뒤 다시 실행하면 저장소·완료 영수증을 읽어서 검증하고 재생성하지 않습니다.

저장 위치는 기존 `demo_export_data` 영속 볼륨 안의 전용 `demo-runtime-20261111` 하위 디렉터리입니다. 기존 export 파일을 삭제하거나 덮어쓰지 않습니다. 원래 Compose 폴더·파일이 없으면 실행 중인 API의 설정을 보존해 설치하는 복구 경로로 자동 전환합니다. 환경변수 값은 별도 파일이나 로그에 기록하지 않습니다. 지원하지 않는 설정은 변경 전에 중단합니다. 완료 뒤에는 이 패키지 폴더와 `code-install/INSTALL_STATE.json`, 생성된 경우 `runtime-image.override.json`을 보관하세요. 복구 경로에서 보관한 이전 API 컨테이너는 삭제하지 마세요.

파일과 DB는 서로 다른 저장소이므로 생성 도중 중단될 수 있습니다. 부분 생성 상태에서는 알 수 없는 파일을 자동 채택·삭제·덮어쓰기 하지 않고 중단합니다. 완료 직전 바인딩만 기록된 경우에는 같은 바인딩과 빈 저장소를 다시 검증한 뒤 완료 영수증을 기록할 수 있습니다. 중단 코드가 나오면 폴더/DB를 수동 초기화하거나 반복 실행하지 말고 마지막 출력을 공유하세요. 실제 계정 주문 사용량·외부 IP 여유·거래소 비용 상한은 이 단계가 검증하지 않으며 실행 승인은 계속 false입니다. 이 절차는 2026-11-11 적용 상태에 한정하며 날짜가 달라지면 기준값을 자동 갱신하지 않습니다.

검증: 격리 PostgreSQL/SQLite 및 Docker 기반 29개, PowerShell 7의 두 JSON 반환 형태에서 자동 흐름 검사 12개가 통과했습니다. Docker 독립 프로세스·영속 볼륨·사용자 10001로 실제 시간의 시작 대기를 새로 검증했습니다. 대기 전 finalize 거부, 대기 후 구성 완료, 금융 상태 보존, 중복 방지, 부분 실패 후 중단을 확인했습니다. 실제 Windows PowerShell 5.1이나 Windows Compose 교체를 클라우드에서 수행한 결과는 아닙니다. 포함된 V3의 기존 검사 66개는 이번 41개 결과에 다시 합산하지 않았습니다.

재현용 소스와 JUnit은 evidence/에 있습니다. 전체 프로젝트 테스트 환경, TEST_DATABASE_URL, 지정 Docker 이미지/테스트 PG 컨테이너, PowerShell 7(PWSH_EXECUTABLE)이 필요합니다. 실행 환경의 테스트 계정과 볼륨만 사용하며 사용자 DEMO 거래소에는 연결하지 않았습니다.


이번 수정에서는 실제 Docker/합성 PostgreSQL 기반 정상 설치 1개, DB 감사 이력 변경 시 중단·기존 API 복원 1개, 설정 보존·HTTP 전달·모의 전체 설치 29개 등 31개가 통과했습니다. 앞서 통과한 저장소 구성 41개와 V3 검사 66개를 이번 수에 합산하지 않았습니다. 저장소 구성 코드와 SDK 66개 파일은 바뀌지 않았습니다. 실제 Windows PC에서의 설치를 이 클라우드에서 실행한 것은 아닙니다.

**입력할 명령은 `RUN_NEXT.cmd`입니다.** `STARTUP_HOLD_KEEP_PAUSED_NO_ORDERS`와 `CODE_AND_STORAGE_CONFIGURED_KEEP_PAUSED_NO_ORDERS`는 화면에 출력되는 상태 문구이며 직접 입력하는 명령이 아닙니다. 중단 코드가 나오면 마지막 출력만 공유하고 같은 명령을 반복 입력하지 마세요.
