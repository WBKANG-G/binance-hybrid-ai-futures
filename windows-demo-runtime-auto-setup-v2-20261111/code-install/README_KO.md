# 원래 Compose 경로가 없어도 현재 API 설정을 보존하여 코드 설치

원래 Compose 파일이 있으면 기존 설치 경로를 사용합니다. 작업 폴더 또는 파일이 없으면 현재 실행 중인 API의 설정을 메모리에서 읽어 같은 환경변수·볼륨·네트워크·포트·실행 명령으로 새 API 컨테이너를 만듭니다. 환경변수 값은 별도 파일이나 로그·명령 인수에 남기지 않고 기존 Docker 연결의 표준입력으로 전달합니다. 새로운 원격 접속 포트나 서비스를 열지 않습니다.

새 컨테이너를 먼저 생성한 후 현재 설정과 DB 스냅샷을 다시 확인합니다. 기존 API는 중지·이름 변경해 보관하고 새 API를 시작합니다. 설정 해시와 금융 원장 스냅샷이 유지되는지 확인합니다. 생성 거부 시 기존 API는 유지됩니다. 교체 후 검증 실패 시 원래 컨테이너를 복원하고 결과를 보고하며, 변경된 DB 이력은 삭제하거나 되돌리지 않습니다. 이 경우 상위 자동 흐름도 중단됩니다.

지원할 수 없는 설정(예: 정적 IP, 임의 포트 할당, 코드 경로를 가리는 마운트, 볼륨 상속, root 사용자, privileged 등)이면 기존 API를 교체하기 전에 중단합니다. 기존 볼륨을 삭제하지 않습니다. 정상 완료 후 복구용 이전 컨테이너와 INSTALL_STATE.json을 보관하세요. INSTALL_STATE.json에는 이미지/컨테이너 식별자만 저장하며 환경변수는 저장하지 않습니다.

이번 배포 복구 관련 검사 31개가 통과했습니다. 실제 Docker/합성 PostgreSQL 원장으로 정상 설치와 감사 이력 변경 시 원래 API 복원을 새로 검사했습니다. 실제 Windows PowerShell 5.1에서 실행한 결과는 아니며 Linux PowerShell 7에서 두 JSON 반환 형태를 검사했습니다. SDK 코드 66개와 저장소 구성 코드는 이전 패키지와 같습니다.
