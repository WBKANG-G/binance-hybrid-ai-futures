# 원본 구성 비교 차단 진단 — 읽기 전용

기존 복구 실행은 RESTORE_SOURCE_SCOPE_CHANGED에서 중단됐으며 복제 자원은 생성되지 않았습니다. 이 패키지는 어떤 비교가 달랐는지만 구분합니다. 원본 ID·볼륨·이미지·권한 등 필드와 값의 일치 요구는 유지합니다. 실시간 스냅샷 재확인은 Docker가 반환하는 마운트 목록 순서만 정렬해 비교하며 모든 마운트 필드/값을 유지합니다. 필드 추가·값 변경은 계속 차단합니다. 보존 당시 스냅샷과의 JSON 비교 조건은 변경하지 않습니다. 이미지 참조의 정규 ID 해석, JSON 직렬화와 메타데이터 값 비교 결과는 진단용이며 실행 허용에 쓰지 않습니다.

바탕화면에 압축을 풀고 CMD:

```bat
cd /d "%USERPROFILE%\Desktop\windows-demo-restore-scope-diagnostic-20261114"
RUN_CHECK.cmd
```

출력 JSON의 `scope_probe`에 단계·역할·개수·일치 여부만 표시합니다. 실제 볼륨 경로/이름, 환경 변수, 백업 내용, 원래 주문 ID는 출력하지 않습니다. 영수증과 파일 해시 확인은 동일하게 수행합니다.

런처는 항상 CheckOnly로 호출합니다. RUN_RESTORE.cmd는 배포하지 않습니다. 수동으로 ExecuteRestore 인수를 주어도 검사 모드만 호출됩니다. 복제 볼륨/컨테이너 생성, 원본 시작/정지, DB 복구/수정, 파일 생성은 하지 않습니다. 콘솔 결과만 공유하고 원본과 보존 파일은 그대로 유지하세요. 진단을 통과해도 기존 RUN_RESTORE.cmd를 다시 실행하지 마세요. 차단 원인 확인 후 별도 안내가 필요합니다.
