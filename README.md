# DEMO 긴급 경고 큐와 네이버 본인 이메일

사용자가 선택한 네이버 메일 수신 경로입니다. 새 windows-demo-urgent-alert-queue 폴더에 ZIP을 풀고 URGENT_ALERT_START_HERE_KO.md를 따릅니다. 같은 hybrid-windows 프로젝트로 빌드해 추가0004 migration과 alerts worker를 기동합니다. SMTP 설정이 없으면 발송 없이 대기합니다. 실제 위험 사건을 만들거나 주문을 추가하지 않습니다.

위험 변경/기존 audit/outbox/새 경고를 한 트랜잭션에 기록합니다. STOP 보호 실패·청산 결과 UNKNOWN·새 비상/손실 잠금·감시 실패를 최소 고정 payload로 큐에 넣고 원래 과거 UNKNOWN이나 heartbeat를 반복 발송하지 않습니다. 거래 트랜잭션에서 원격 전송하지 않습니다. 별도 전달기는 claim/시도/ACK/실패를 보존하고 같은 ID로 재시도하며 이전 claim 소유자의 완료를 차단합니다.

네이버 SMTP는 smtp.naver.com:465의 검증된 TLS와 본인 From=To만 허용합니다. 앱 비밀번호는 사용자가 PC에서 한 번 숨김 입력하고 보호된 RAM에12시간만 보관합니다. 기존 API 키는 별도 파일 그대로 재사용합니다. .env/DB/이미지/일반 호스트 파일에 앱 비밀번호를 저장하지 않습니다. 유효 설정을 명시적으로 활성화하면 대기/새 긴급 경고가 본인 메일로 자동 전송됩니다. SMTP 인증 거부는 설정 변경을 기다리고 같은 비밀번호로 계속 로그인하지 않습니다.

전체1339개, 집중48개 및 보완 worker16개 재검증과 Ruff/mypy121개 소스 통과. 실제 격리 PG와 로컬 HTTP/검증 TLS SMTP로 롤백·이전 schema 업그레이드·실패/유실/잘못된 ACK·중복 claim·앱 비밀번호 보호를 검사했습니다. 실제 네이버 인증/본인 수신은 아직 확인 전입니다. 클라우드에서는 실제 API 키/메일 인증 정보나 외부 사람 대상 전송을 사용하지 않았습니다.

설정 후 명시적 테스트 메일 한 통을 보내고 SMTP_ACCEPTED_CHECK_YOUR_INBOX와 실제 받은메일함/스팸함 수신을 함께 확인합니다. 테스트 메일은 가짜 긴급 사건이나 거래를 DB에 만들지 않습니다. delivered는 채널 수락 기준이며 사람의 열람이나 최종 수신 보장이 아닙니다. SMTP 응답 유실 시 같은 Message-ID로 중복 수신될 수 있습니다. 과거 사건을 소급 발송하지 않습니다.

기존448개 중446개 파일은 동일하며 저장소 코드의 원자적 알림 기록과 Compose만 변경했습니다. 새로운 파일15개를 추가했습니다. 원래 coordinator/SDK/리스크·시계/거래 리스/펜스·기준금·키 도우미·exports는 유지합니다. main/LIVE/Phase5와 실제 부분체결/TP·시장 장애 미완료를 성공으로 바꾸지 않으며 Phase4 전체 완료를 선언하지 않습니다.
