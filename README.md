# API 키 한 번 입력 후 재사용 및 읽기 전용 준비 확인

새 windows-demo-one-key-session 폴더에 ZIP을 풀고 ONE_KEY_START_HERE_KO.md를 따릅니다. 같은 hybrid-windows 프로젝트로 빌드한 뒤 --ensure에서 DEMO API Key와 Secret을 한 번 숨김 입력합니다. 이후 check_demo_session_ready는 -T로 실행하며 입력 없이 같은 RAM 세션을 사용합니다.

유효기간은 최초 등록부터 12시간으로 재사용해도 연장되지 않습니다. 네트워크 없는 별도 key-session 컨테이너가 보호된 tmpfs 마운트를 유지하므로 API 재생성 중 키를 보존합니다. Docker/호스트 재시작, 마지막 마운트 제거, 만료 이후에는 재입력이 필요합니다. .env/DB/이미지/호스트 일반 파일에 비밀을 저장하지 않습니다. RAM 평문과 호스트 메모리 보호 범위는 시작 문서를 참고합니다.

다음 단계는 NORMAL/paused·기준일 일치·로컬 및 거래소의 비어 있는 상태를 읽기 전용으로 검증합니다. 주문, 취소, 청산, 진입 재개, 기준금 변경은 없습니다. 일간 기준금은 사용자 실제 적용 증거대로 2026-11-01 / 4999.03492670 USDT이며 주간 기준금/고점/기존 이력·미해결 요청을 유지합니다.

전체1260개, 집중46개 시험 및 Ruff/mypy113개 소스 통과. 실제 Docker에서 합성 키로 소비 컨테이너 교체 후 재사용·만료 시각 불변·마지막 마운트 해제 후 소멸을 확인했습니다. Windows의 이번 준비 상태 결과와 API 재생성 후 재사용은 아직 확인 전입니다. 실제 키나 인증된 거래소 요청을 클라우드 검증에 사용하지 않았습니다.
