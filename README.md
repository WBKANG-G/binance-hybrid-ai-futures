# 보호 중 worker 강제 종료·자연 리스 인계 검증 자료

사용자 Windows에서 실행할 새 명령은 없습니다. 앱/Compose/키/SDK/리스크와 부모443개 파일을 바이트 동일하게 유지했습니다. 새 시험 helper/통합 시험/단위 시험과 한국어 보고서·검증5개 파일만 추가했습니다. 재빌드·키 재입력·추가 주문을 요구하지 않습니다.

원래 coordinator로 합성 최소 수량0.0007 진입과 SL/TP 검증을 끝내고 신규 진입을 정지한 실제 child 프로세스를 SIGKILL했습니다. 프로세스 종료 코드-9, finally 표식 없음과 기존 리스 소유권 유지를 확인했습니다. 실제59.969초 동안 원래60초 리스의 자연 만료를 기다렸고 lease_until이 변경되지 않았습니다. SL/TP를31회 점검한 뒤 펜스1→2로 인계했고, 실제 두 번째 로컬 WebSocket 연결과 REST 재검증으로 같은 client/server 진입 ID와 보호 ID를 회복했습니다. 인계 전 진입POST1/보호POST2를 유지했습니다. 이전 소유자의 부작용 callback/renew와 신뢰 전 신규 진입은 거부됐습니다. 후속 합성 정리는 VERIFIED_FLAT으로 끝났습니다.

전체1291개·집중9개 시험과 Ruff/mypy115개 소스 통과. 새 helper는 명시적 시험 플래그·고유 schema·loopback 주소·고정 합성 키만 허용하고 실제 BINANCE 환경이나 원격 주소를 거부합니다. 실제 API 키 캐시나 사용자 계좌를 사용하지 않았습니다.

증거는 실제 PostgreSQL/실제 child SIGKILL/자연 리스 대기와 별도 공유 합성 거래소·로컬 ws:// 연결의 범위입니다. 실제 Binance/TLS·listen-key 수명·실제 시장 변동 중 SL/TP 체결·제출 중 종료·미보호/부분체결·호스트/DB/거래소 동시 장애는 별도입니다. 부모 감시 서버와 DB는 살아 있었습니다. 실제 Windows DEMO 보호 포지션 worker 종료를 수락한 결과가 아닙니다.

실제 부분체결/TP 체결과 다른 미완료 범위는 그대로 남깁니다. 기존 실패·UNKNOWN/NOT_SENT·기준금·키·export·main을 변경하지 않았고 LIVE/Phase5 또는 Phase4 전체 완료를 선언하지 않습니다. 자세한 결과는 PROTECTED_WORKER_REPORT_KO.md 및 PROTECTED_WORKER_VALIDATION_KO.md를 참고합니다.
