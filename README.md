# Phase4 복구 검토 HTTPS 연결 재사용

ZIP을 새 windows-demo-recovery-https-reuse 폴더에 풀고 RECOVERY_HTTPS_START_HERE_KO.md를 따릅니다. CMD 하나에서 빌드 Healthy → DEMO 키 RAM 재등록 → 인자 없는 읽기 전용 복구 검토를 한 번 실행합니다. 신규 주문·비상 종료·exports 생성·복구 적용 명령은 포함하지 않습니다. 현재 EMERGENCY/paused는 유지합니다.

기존 전송은 HTTPS 요청마다 연결을 닫습니다. 수정본은 한 번의 GET 감사 범위에서만 검증된 TLS 연결을 재사용하고 기존 프록시·CONNECT 인증 분리·리다이렉트 거부를 유지합니다. SDK 서명과 응답 해석, 전체 과거 요청 조회·스냅샷·기간/리스크·토큰·승인 함수는 그대로입니다. 40초/GET600/시계6/이력128/배치8/리스60초를 늘리지 않았습니다. 실패 요청 재시도·캐시·병렬 조회는 없습니다.

전체1156개 테스트 통과, 집중56개 통과, Ruff 및 mypy103개 소스 통과. 정확한 이전 ZIP에서 시간 초과를 재현하고 같은 조건으로 수정본의 전체 조회·동일 토큰·DB 불변을 검증했습니다. 로컬 실제 TLS와 PostgreSQL에 결정론적 연결 지연을 적용한 시험이며 사용자망에서의 속도 개선은 아직 검증 전입니다. 공개 시계 접근은 클라우드에서 기존/새 전송 모두 실패했습니다. 인증된 클라우드 거래소 요청은 없습니다.

Windows에서 새 검토 결과가 나올 때까지 잠금을 풀지 않습니다. 차단 시 반복하지 않고 전체 JSON을 공유합니다. 검토 성공도 자동 잠금 해제가 아닙니다. 기존371개 파일 중 복구 검토 진입부와 CLI 진단2개만 수정하고 전송·테스트·한국어 문서/증거7개를 추가했습니다. 이전 테스트·SDK·예산·실행/보호/청산·기준금·키·Compose·exports는 동일합니다. main/LIVE/Phase5 변경 없음.
