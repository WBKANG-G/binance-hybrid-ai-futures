# Phase4 기존 종료 확인 지연·진단 수정본

ZIP을 새 windows-demo-flat-confirmation-fix 폴더에 풀고 FLAT_FIX_START_HERE_KO.md를 따릅니다. CMD에서 빌드 Healthy → DEMO 키 RAM 등록 → 기존 --confirm-flat을 한 번 실행합니다. 신규 진입/종료/장애 시험을 하지 않습니다. 현재 NORMAL/paused를 유지합니다.

기존 확인은 과거 주문까지 포함한 독립 스냅샷을 최대5회 조회하며 요청마다 HTTPS 연결을 만들고 함수 안에서는 시계를 갱신하지 않습니다. 이전 ZIP의 정확한 함수를 로컬 실제 TLS/PostgreSQL 및 합성 연결 지연으로 시험해60.075초에 원래 SDK 시계 만료로 차단되는 것을 재현했습니다. Windows 약60초 차단의 당시 정확한 예외는 일반 출력만으로 확정하지 않습니다.

수정은 확인 문맥 안의 GET 연결 재사용,40초/서명600회/시계6회 예산,20초 경과 시 원래 verified 시계 갱신, QUERY/CLEANUP/VERIFY 단계와 안전한 진단입니다. 기존 인증서/호스트/프록시/리다이렉트 거부, 시계 수명60초/리스60초/사후 펜스는 유지합니다. 중간 리스 갱신·캐시·이력 조회 생략·병렬화·HTTP 실패 재시도는 없습니다. 원래 증거 판정 본문은 단계 라벨을 제외하면 AST가 동일하며 다른 coordinator 메서드는 모두 동일합니다.

진입/종료 POST 및 다른 변경은 차단합니다. 기존 flat·종료 체결 증거가 충족된 뒤 자기 이력의 잔여 보호 DELETE만 원래 SDK 전송으로 수행합니다. readonly이면 DELETE도 금지합니다. 모든 과거 주문 연결 ID 조회와 기존 모호한 request 증거를 보존합니다. 별도 복구 전체 감사는 바꾸지 않습니다. 성공해도 진입은 일시정지합니다.
