# 진입 만료 대기 수정 적용

기존10초 유효기간은 유지한다. 준비 직후/수신 대기 전 만료를 검사하고 이벤트 대기를 남은 유효기간(최대5초)에 맞춘다. 대기 종료 때 ping/REST보다 먼저 만료를 검사한다. 기존 취소 의도/재조회/부분체결 보호/리스·펜스/작업 종료 대기는 유지한다. 진행 중 작업을 강제로 끊지 않으므로 정확한10초 취소 완료를 보장하지 않는다.

ZIP을 새 폴더에 풀고 APPLY-EXPIRY-WAIT-FIX.cmd와 infra 폴더가 함께 보이는 폴더에서 CMD를 연다. 기존 파일 위에 덮어쓰지 않는다. 다음 명령 한 번을 실행한다.

```bat
APPLY-EXPIRY-WAIT-FIX.cmd
```

먼저 기존 계정의 기간 일치/NORMAL/paused/거래소 주문·포지션 없음을 읽기 전용으로 확인한다. 실패하면 빌드 전 중단하므로 출력 그대로 공유한다. 이어 기존 hybrid-windows 프로젝트의 api 서비스만 빌드·재생성하고 실행 파일SHA256과 읽기 전용 준비 상태를 다시 확인한다. DB/key-session/alerts/web 재생성·볼륨 삭제를 하지 않는다. 빌드는 Docker/uv 의존성 캐시에 따라 네트워크가 필요할 수 있다. 키는 명령에 넣지 않는다. 캐시 키가 없거나 기간이 바뀌면 준비 검사에서 중단한다.

성공 시 EXPIRY_WAIT_FIX_SOURCE_VERIFIED와 READ_ONLY_READY_ENTRIES_STILL_PAUSED가 출력된다. 전체 출력을 공유한다. 새 DEMO 주문은 실행하지 않는다. 출력 실패 시 추가 거래나 down -v 없이 결과를 공유한다. 기존 소스 폴더와 자료는 보관한다. 되돌림이 필요한 경우 기존 소스 폴더에서 동일 프로젝트의 api만 다시 빌드하며 DB 이력을 되돌리지 않는다.

이 패키지는 전체 소스 전송본이다. main 병합/LIVE/Phase5/Phase4 전체 승인을 포함하지 않는다. 과거 TP 미체결 및 미해결 요청·실패 이력은 보존한다. 과거 안내 파일의 거래 명령을 재실행하지 말고 이 문서와 적용 CMD만 사용한다. Windows 실제 적용은 아직 검증되지 않았다.
