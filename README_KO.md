# DEMO 공유 요청 가중치 제어 — 개발 검토 자료

프로세스마다 따로 계산하던 REQUEST_WEIGHT를 같은 공유 저장소를 사용하는 프로세스들이 합산하도록 추가했습니다.
요청 전 디스크 커밋, 응답 완료 후 60.001초 유지, 응답 없는 예약 무기한 보존을 적용합니다.
같은 파일·범위·UUID·호스트 부팅 환경을 사용하는 협력 프로그램에 한정됩니다. 실제 IP를 자동 감지하거나 외부 프로그램의 용량을 예약하지 않습니다.

- 모델 상한 5,700. 일반 요청은 640, WATCH는 512, PROOF는 128의 여유를 보존합니다.
- 기존 주문 소유권·수량·임대·중복 방지·전체 청산 확인과 실실행 기본 차단을 유지합니다.
- 낮거나 순서가 뒤바뀐 헤더를 받았다고 사용량을 반환하지 않습니다.
- 헤더 누락·418/429는 공유 중단 상태를 기록합니다. 전송 예외의 미완료 예약도 반환하지 않습니다.
- 시작 시계 가속 외에는 실제 단조 시계를 사용한 모의 생명주기 검증을 수행했습니다.

테스트 1,125개(중복 제외), mypy 151개 소스, Ruff, 네트워크 없는 Docker 스모크 통과.
8개 프로세스가 동시에 각 1,000을 요청하면 5개만 허용되고 3개는 용량 부족으로 차단됩니다.
SIGKILL 후에도 이미 기록한 5,700 예약이 유지됩니다.
부분 체결 청산과 저널 장애 시 기존 위험 축소 청산을 최종 소스로 검증했습니다.
짧은 관찰과 가속한 시작 대기를 사용했으며, 새 300초 자연 관찰이나 거래소 검증이 아닙니다.

새 기능은 선택적 개발 경로입니다. 운영 CLI 연결·Windows 설치·DB 변경·거래소 요청·거래 재개: 0.
실제 계정 주문 사용량은 UNKNOWN, 실제 IP 용량 예약은 false입니다.
공유 파일의 정상 보존을 전제하며, 새 프로세스에서 유효한 과거 백업으로 되돌린 상태를 독립적으로 탐지하는 외부 기준은 추가하지 않았습니다.
따라서 운영 전체에 대한 실행 허가로 해석하지 마세요. 현 PC에서 추가 조회나 거래 명령을 실행할 필요가 없습니다.
