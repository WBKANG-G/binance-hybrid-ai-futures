# DEMO 시각 조회 거부 후 증명 차단 — 개발 검토 자료

사용량 헤더가 정상이어도 시각 응답의 본문·JSON·형식·오프셋·왕복 시간이 잘못되면 SDK는 조회를 거부합니다. 이때 비용 게이트에는 새 관측이 남아 증명 준비 검사가 통과하는 공백을 수정했습니다. 시각 응답 사례 6개와 중간 구현의 동시 실행 사례 1개를 재현했습니다. 원래 SDK의 거부는 이전에도 있었으므로 실제 서명 요청이나 가중치 초과를 재현한 것은 아닙니다.

이제 실패한 시각 조회는 해당 실행을 중단시키고 이전 SDK 시각 샘플을 무효화합니다. 시각 조회부터 본문 검증까지 기존 실행 잠금을 유지해, 다른 스레드가 중간 관측으로 증명을 시작하지 못하도록 했습니다. 원래 오류와 첫 중단 사유를 보존하며 자동 재시도나 초기화는 추가하지 않았습니다. 수신 확인된 응답은 완료된 비용 기록을 유지하고, 전송 불명·429는 기존 미완료/중단 기록을 보존합니다.

기존 확인 루프가 증명 보류 후 WATCH 시각 조회로 관측을 갱신하는 것도 확인했습니다. 이 스케줄링 테스트는 실제 증명 직전의 검사용 예외에서 멈추며 가짜 VERIFIED_FLAT 결과를 만들지 않습니다. 별도 모의 TP·부분 체결 청산은 원래 전체 청산 확인까지 통과해야 합니다.

검증: 테스트 1,301개, mypy 156개 소스, Ruff, 네트워크 없는 Docker 클라이언트·게이트 스모크 통과. 전체 모의 청산의 시작 대기는 가속했고 관찰은 0.8초입니다. 새로운 300초 자연 관찰이나 거래소 검증은 아닙니다.

실제 계정 주문 사용량·외부 IP 여유·전체 요청 비용 상한은 미확인입니다. 운영 실행 기본값은 비활성입니다. Windows 설치·Windows DB 변경·실제 거래소 요청·실제 주문·거래 재개는 수행하지 않았습니다. 현재 PC에서 추가 실행할 명령은 없습니다.
