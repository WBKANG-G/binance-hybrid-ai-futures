# 취소 대기 중 청산 확인 비용을 줄이는 후보 — 검토 전용

후보 소스 `2ea564f4c146edc836161a2b873d07b6a8ea129a`
이전 예산 후보 `00489ecd99e5b77ae2581fddded4eb64cf18e316`
현재 Windows 설치 기준 `4e967dc6751c6f04786ba63cdcc97e7eb1c80a39`

이 ZIP은 설치용이 아닙니다. Windows 상태와 DB에 접근하지 않았으며, 실제 DEMO/LIVE 주문을 보내지 않았습니다. 새 후보는 CLI에서 참조하지 않습니다. 기존 진입 예산 가드의 기본 실행 거부와 6,000 한도 진입 차단은 그대로입니다.

## 결과

동일한 가짜 거래소·로컬 WSS·분리된 PostgreSQL에서, 10페이지 이력과 취소 ACK 이후 지연된 상태 반영을 재현했습니다. 처음 3회 UNKNOWN 후 4회째 원래 전체 검증으로 VERIFIED_FLAT이 되는 조건입니다.

| 모델 측정 구간 | 기존 확인 | 단계별 확인 후보 |
| --- | ---: | ---: |
| 전체 이력 스냅샷 횟수 | 20 | 10 |
| 최종 확인 GET 비용 | 9,422 | 4,544 |
| 최종 확인 모든 요청 비용 | 9,582 | 4,624 |
| 청산 준비를 포함한 CLEANUP 비용 | 12,113 | 7,155 |

최종 확인 GET 비용이 약 51.77% 줄었습니다. 하지만 후보의 전체 청산 비용은 여전히 **7,155 > 6,000**입니다. 진입이나 관찰 비용을 포함하기 전에도 초과하므로 실제 TP 실행이 가능해졌다는 결과가 아닙니다. 이 수치는 관찰된 합성 경로 비용이며 모든 경로의 상한 증명이 아닙니다.

## 변경 방식

첫 번째 최종 확인은 항상 기존 전체 검증을 수행합니다. 전체 검증이 VERIFY까지 진행했고, 정리 요청 이후에도 로컬 포지션·주문이 모두 닫힌 상태에서 UNKNOWN이면 다음 시도에서 먼저 전 종목 포지션과 기존 보호 주문 ID의 상태만 조회합니다.

- 해당 ID의 취소 요청이 SDK에서 오류 없이 돌아온 경우에만 취소 대기 조회를 사용할 수 있습니다. 실패한 DELETE는 예전 ACK 기록도 지워 기존 전체 정리 경로를 유지합니다.
- 취소 ACK를 받았어도 signed GET에서 NEW이면 UNKNOWN을 반환합니다. 이 조회는 POST/DELETE를 보내거나, 재무 상태를 갱신하거나, 청산 성공을 판정하지 않습니다.
- 취소가 확인되거나 상태가 바뀌면 기존 전체 확인으로 돌아갑니다. 성공 전에 원래의 전체 이력·쌍 스냅샷·최종 스냅샷 증명이 모두 필요합니다. 원래 확인 함수, 이력 파서, 보호 삭제 결정은 수정하지 않았습니다.
- 다른 종목의 포지션, 잘못된 응답, 새 미체결 잔량, 불일치 로컬 상태에는 가벼운 대기 경로를 쓰지 않습니다. SDK 오류/418/429 및 펜싱도 유지합니다.
- 기존 4회 시도·1초 간격 범위 안에서만 처리합니다. 4회 모두 취소 미확인이면 UNKNOWN·EMERGENCY·일시정지를 유지합니다. 더 낮은 비용으로 끝나도 청산 성공으로 표시하지 않습니다.

## 검증

**78개 통과**: 비용 비교 통합 10개, 안전 경로 통합 24개, 새 구성요소로 다시 실행한 기존 진입 예산 통합 14개, 기존 예산 단위 검사 30개. Ruff와 mypy(135개 운영 소스 파일) 통과. 자세한 XML은 test-results/에 있습니다.

가상 한도는 100,000이고, GET 비용은 이전 모델을 사용했으며 변경 요청 비용은 각 40으로 가정했습니다. 공유 IP 용량, 별도 주문 횟수 제한, 거래소 비용 상한은 증명하지 않았습니다. 네트워크 응답은 가짜이며, 관찰 시간은 테스트에서만 0.8초로 줄였습니다. 실제 운영 300초 상수는 바꾸지 않았고 이번 후보의 실제 300초 시험은 하지 않았습니다.

## 다음 개발 지점

이 조건에서 최종 확인 앞의 기존 명령/대조 구간이 2,531의 모델 비용을 사용합니다. 이 구간의 중복 대조를 줄일 여지가 있는지 조사하되, 주문 소유권·잔여 체결·fresh position·펜싱·보호 손절·전체 거래 이력 검증은 유지해야 합니다. 현재 후보의 28,352 청산 예산 가정이나 진입 차단 기준을 측정값 7,155/4,544로 낮추면 안 됩니다. 단일 경로의 측정은 최대 비용 보장이 아닙니다.

## 파일

source/와 source.patch는 현재 설치 기준 대비 누적 변경 파일 12개입니다. staged-only.patch는 이전 후보 대비 새 파일 5개만 담았습니다. 전체 테스트에는 기준 저장소와 의존성이 필요합니다. cleanup_reports/에는 10개의 최종 비용 비교 결과, admission_reports/에는 새 구성요소로 재검증한 13개 시나리오 기록이 있습니다. 모든 요청 기록은 경로·비용만 남기며 키·서명·요청 쿼리를 담지 않습니다. manifest는 자기 자신을 제외한 패키지 파일 SHA256 목록입니다.

Windows는 일시정지를 유지합니다. 이 패키지의 코드를 기존 컨테이너에 복사하거나 거래를 재개하지 마세요.
