# DEMO 청산 확인 단계의 원래 실행 연결 검사 — 개발 검토 자료

리스 갱신 전에 코디네이터·저장소·클라이언트·예산의 원래 연결을 검사하지 않는 순서 문제를 보완했습니다. 수정 전 참조 변경 13개 사례를 검사용 스케줄러로 재현했습니다. 후단의 원래 서명·펜싱 검사는 이전에도 있었으므로 실제 잘못된 계정 쓰기나 거래소 요청을 재현한 것은 아닙니다.

원래 리스·스토어·엔진·저널·브리지·클라이언트·예산을 캡처하고, 첫 갱신과 각 단계 전후 및 작업 스레드 진입 시 검사합니다. 기존 클라이언트·예산 검사를 재사용하며, 변경된 설정·자격 증명·비용 모델·공유 제공자를 거부합니다. 정상적인 활성/비활성 전환과 단순 비용 부족 시 정리 규칙은 유지합니다.

거부 시 새 예약이나 교체 컨텍스트를 만들지 않습니다. 기존 기록·이미 커밋된 증명·미확인 요청은 되돌리지 않습니다. 검사는 명시한 경계의 일관성 검사이며 원래의 실제 효과 시점 펜싱·요청 검사를 대체하지 않습니다. 취소 시 작업 완료 대기도 유지하므로 강제 시간 종료를 보장하지 않습니다.

검증: 테스트 1,398개, mypy 157개 소스, Ruff, 네트워크 없는 Docker 예산 연결 검사 스모크 통과. 별도 모의 TP·부분 체결 청산이 원래 전체 증명까지 완료됐고 정상 흐름에서 연결 거부가 0회인 것도 확인했습니다. 시작 대기는 가속했고 관찰은 0.8초입니다. 새로운 300초 자연 관찰이나 거래소 검증은 아닙니다.

실제 계정 주문 사용량·외부 IP 여유·전체 요청 비용 상한은 미확인입니다. 운영 실행 기본값은 비활성입니다. Windows 설치·Windows DB 변경·실제 거래소 요청·실제 주문·거래 재개는 수행하지 않았습니다. 현재 PC에서 추가 실행할 명령은 없습니다.
