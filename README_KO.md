# 주문 없는 TP 조회 가중치 관찰

대상은 설치 완료된 `e9327bd4729c7b5a4eeebff0e309f0f631395098` 코드와 현재 수동 종료 완료 원장입니다. 앱/이미지/원장/정책/키를 변경하지 않습니다. 재빌드도 필요 없습니다.

SDK와 API 원본 파일29개의 해시, 로컬 NORMAL/진입 일시정지·CLOSED/잔여0·수동 종료 영수증·실패 마커·리더 없음부터 확인합니다. 읽기 전용 클라이언트와 전송 경계 양쪽에서 거래소 쓰기를 금지합니다. 세션/listen-key를 생성하지 않고 리더 임대·heartbeat·신호·주문·복구를 수행하지 않습니다. SQL 트랜잭션은 READ ONLY로 강제하며 전후 계좌/owner/fence/lease/원장 내 이력이 그대로인지 확인합니다.

## 실행

ZIP을 바탕화면에 풀고 CMD에서 실행하세요. Windows 보안 설정은 유지합니다. 다운로드한 CMD/BAT/PS1 파일은 없습니다.

```cmd
cd /d "%USERPROFILE%\Desktop\windows-demo-tp-read-weight-profile"
```

`RUN_COMMAND.txt`의 한 줄을 CMD에 붙여 넣으세요. 파일 해시를 검증한 뒤 **한 번의 읽기 관찰**만 실행합니다. 대략35초이며, 요청 시작 기한45초에 도달하면 추가 요청을 중단합니다. 진행 중인 네트워크 요청/로컬 확인 시간은 추가될 수 있습니다. HTTP 시도160회·시각 조회6회 상한입니다. 측정 중 같은 계좌에서 다른 명령을 실행하지 말고 Docker와 창을 유지하세요.

관찰은 공개 `exchangeInfo.rateLimits`의 정확한 REQUEST_WEIGHT/MINUTE/1 한도를 먼저 확인합니다. 한도 또는 가중치 헤더가 없거나 모호하면 서명 조회를 시작하지 않습니다. 준비 후0·15·30초 시작을 목표로, 각 회차에 시각 GET과 운영 스냅샷3회를 읽습니다. 현재 freshness 정책이 짧다면 15초 대신 정책 절반을 사용합니다. 요청이 느려 다음 시작을 지났다면 따라잡기용 추가 회차를 만들지 않습니다.

관측 가중치가 공개 한도60%에서 여유분(최대100, 작은 한도는10%)을 뺀 값에 도달하면 추가 요청을 중단합니다. 418/429는 원래 SDK가 쿨다운을 기록하며 자동 재시도하지 않습니다. 공유 IP의 다른 요청·별도 제한·진행 중 요청 때문에 이 장치만으로 제한을 완전히 방지한다고 보장하지 않습니다.

## 결과

완료 상태는 `READ_ONLY_OBSERVATION_FINISHED`이며 completed_rounds=3이어야 합니다. `database_changed_by_probe=false`, `leader_acquired=false`, `order_writes=0`, `local_state_unchanged=true`가 나옵니다. 세 회차의 빈 포지션/주문·스냅샷/입출금 안정성과 손실/기간/레버리지도 확인합니다. 완료 결과는 정상적인 빈 계좌 관찰을 뜻하며 신규 주문 허용 판정이 아닙니다.

`STOPPED_KEEP_PAUSED_NO_RETRY`의 WEIGHT_HEADROOM_THRESHOLD/TIME_BUDGET_REACHED/HTTP_BUDGET_REACHED는 관찰을 제한한 결과입니다. RATE_LIMITED_STOPPED_KEEP_PAUSED 또는 BLOCKED도 재실행하지 말고 출력을 보내주세요. 관측 결과를 더 얻으려고 반복하지 않습니다. 현재 진입 일시정지와 이전 실패/수동 종료 기록은 유지합니다.

출력은 공개 한도, 시각/서명 GET 수, 회차별 시작/소요시간/관측 가중치, 경로별 요청 수와 인접 응답 사이 가중치 증분의 최소/최대, 분 경계/카운터 초기화 수를 요약합니다. 전체 요청/응답/서명/키/원문 헤더는 출력하지 않습니다. 데이터가 없는 증분은 null로 남기고 음수나 새 분의 값을 이전 구간 증가분으로 합산하지 않습니다. 시각은 동기화된 로컬 시계의 서버 분 힌트이므로 정확한 서버 경계 증명이 아닙니다.

**가중치 증분에는 같은 IP의 다른 활동과 유휴 대기 중 사용량이 섞일 수 있습니다.** 이를 해당 endpoint의 고정 가중치나 이 프로세스만의 사용량이라고 단정하지 않습니다. 활성 포지션·private WSS·진입/SL/TP 생성·취소·비상 종료의 전체 부하를 측정하지 않습니다. 따라서 결과가 좋아도 TP 체결 성공/429 방지/안전한 새 진입을 보장하지 않습니다. 결과 화면을 보내주세요.
