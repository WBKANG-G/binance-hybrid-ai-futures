# DEMO 요청 매개변수와 비용 모델 계약 — 개발 검토 자료

동일 경로라도 매개변수가 바뀌면 요청 비용이 달라지는 공백을 재현하고 수정했습니다.
이전 소스에서는 K선 1,500개 요청, 종목 없는 premiumIndex/bookTicker 요청이 작은 고정 비용으로 통과했습니다.
가짜 전송으로 여섯 사례를 확인했으며, 실제 거래소 가중치 초과를 측정한 것은 아닙니다.

이제 현재 흐름에 승인된 형태만 허용합니다: K선 BTCUSDT/1m/2개, 단일 종목 시세, 원래의 전역 계정 조회, 10페이지 소득 증명, 원래 주문·청산·취소 형태입니다.
클라이언트 진입점과 최종 전송 직전에서 검사하며, 중복 키·인코딩 오류·알 수 없는 필드·변경된 서명 형식을 새 예약 전부터 거부합니다.
기존 소유권·수량·펜싱·완전 청산 확인은 계속 적용합니다. 의미 있는 기존 예약이나 UNKNOWN 기록을 반환·삭제하지 않습니다.

공식 SDK 고정 커밋에서 K선 LIMIT별 가중치, 시세의 symbol 유무별 가중치를 확인하고 URL·파일 해시·행 번호를 포함했습니다.
같은 SDK가 bookTicker 사용량 헤더를 신뢰하지 말라고 명시하므로, 그 헤더 처리와 실제 비용 상한은 미해결 실행 조건으로 남겼습니다.
요청 형태 통과는 실제 실행 허가가 아닙니다. 관련 진단은 execution_approved=false와 비용 상한 미증명을 명시합니다.

테스트 1,256개, mypy 156개 소스, Ruff 통과. 모의 TP·부분 체결 청산도 전체 확인까지 완료했습니다.
시작 대기는 가속했고 관찰은 0.8초, 요청 가중치 시계는 실제 시간입니다. 새 300초 자연 관찰이나 거래소 검증은 아닙니다.
Docker 스모크는 네트워크 없이 기본 차단·고비용 형태 거부·중복 키 거부를 확인합니다.
