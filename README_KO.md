# DEMO 청산 확인 작업 완료 후 취소·종료 처리 — 개발 검토 자료

호출 취소가 스레드를 중단시키지 않는데도 확인 호출이 먼저 끝난 것으로 처리되어, 저널 종료가 작업 완료보다 앞설 수 있는 공백을 수정했습니다. 취소·직접 확인 중 종료·종료 후 첫 확인의 수정 전 실패 6개를 실제 대기 스레드로 재현했습니다. 금융 작업은 검사용 대체 함수이며 가짜 전체 청산 성공을 만들지 않습니다.

기존 settled_call을 네 확인 단계에 재사용해 작업 완료를 기다린 뒤 취소를 전달합니다. 확인 중 종료는 예산 철회·저널 닫기 전에 거부하고, 종료가 먼저 완료되면 첫 확인 시작도 차단합니다. 기존 미확인 기록·첫 결과·중복 호출 차단·종료 재시도는 보존합니다.

작업을 강제로 중단하지 않습니다. 외부 작업이 끝나지 않으면 취소 완료도 지연되며 소유권을 유지합니다. 전체 함수의 강제 시간 제한이나 모든 분리된 스레드의 종료를 보장한 것은 아닙니다. 기존 네 확인 단계의 완료 순서를 보강한 변경입니다.

검증: 테스트 1,375개, mypy 157개 소스, Ruff, 네트워크 없는 Docker 대기 작업자·시작 권한·기본 차단 스모크 통과. 별도 모의 TP·부분 체결 청산은 원래 전체 증명까지 완료했고 재호출 거부도 유지합니다. 시작 대기는 가속했고 관찰은 0.8초입니다. 새로운 300초 자연 관찰이나 거래소 검증은 아닙니다.

실제 계정 주문 사용량·외부 IP 여유·전체 요청 비용 상한은 미확인입니다. 운영 실행 기본값은 비활성입니다. Windows 설치·Windows DB 변경·실제 거래소 요청·실제 주문·거래 재개는 수행하지 않았습니다. 현재 PC에서 추가 실행할 명령은 없습니다.
