# DEMO 계정의 공유 저장소 설정 고정 — 개발 검토 자료

실제 우회를 재현하고 수정했습니다. 이전 소스에서는 기존 저장소에 미완료 요청이 있어도 다른 유효한 빈 저장소를 지정하면 실행 객체가 만들어졌습니다.
이제 계정 원장에 저장소 범위·UUID·체크포인트 설치 ID·정책을 고정하고 시작 전에 대조합니다.

- 다른 유효한 빈 범위 또는 같은 UUID의 새 DB 기준으로 교체하면 차단합니다.
- 실행 객체 생성 후 제공자 교체·원장 설정 삭제도 새 예약/HTTP 전에 차단합니다.
- 설치 ID는 PostgreSQL 트리거로 UPDATE/DELETE를 거부하며, 살아 있는 기준 객체의 백엔드 변경도 거부합니다.
- 설정 바인딩은 별도의 명시적 메타데이터 API입니다. 동일 설정은 반복해도 새 이벤트를 만들지 않고, 다른 기존 설정으로 덮어쓸 수 없습니다.
- 자동 바인딩·파일 초기화·예약 반환·구성 복구·스키마 마이그레이션은 하지 않습니다.

수정 전 재현은 ‘예상한 거부가 발생하지 않음’으로 실패했고, 같은 사례가 수정 후 통과했습니다. evidence/REPRODUCTION.json과 최소 재현 소스를 포함했습니다.
테스트 1,181개, mypy 154개 소스, Ruff 통과. 네트워크 없는 Docker에서는 기본 차단과 설정 식별값 분리를 검증했습니다.
실제 PostgreSQL/파일 검증과 모의 TP·부분 체결 청산도 수행했습니다. 시작 대기는 가속했고 관찰은 0.8초, 요청 가중치 시계는 실제 시간입니다.
새 300초 자연 관찰이나 거래소 검증은 아닙니다.

계정 JSON을 직접 다시 쓰는 관리자/다른 신뢰 코드, 모든 저장소의 일치하는 과거 복원, 악의적인 Python/호스트 조작은 보장 범위 밖입니다.
바인딩 성공이나 동일 설정 응답은 거래 준비 완료를 뜻하지 않습니다. 실제 계정 주문 사용량·외부 IP 여유·요청 비용 상한은 여전히 미확인입니다.

이전 프로토타입 스키마에 대한 자동 업데이트는 없습니다. 명시적 새 스키마/설정 준비는 클라우드 격리 테스트에서만 했습니다.
운영 CLI·Windows 설치·Windows DB 변경·거래소 요청·실제 주문·거래 재개: 0. 현재 PC에서 추가 조회나 거래 명령을 실행할 필요가 없습니다.
