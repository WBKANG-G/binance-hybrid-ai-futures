# 수정본 보호 worker 단일 검증

복구 결과 `NORMAL`, `paused=true`, 날짜 일치와 거래소 잔여 주문·포지션 없음이 확인된 다음 사용하는 실행기입니다. 설치된 직렬화 수정본을 사용하며 API 재빌드·재시작은 하지 않습니다.

ZIP을 새 폴더에 풀고 `RUN-ONE-SERIALIZED-WORKER.cmd`를 한 번 실행하세요. Docker와 창을 계속 켜 두세요. 사전 검사와 lease 대기·정리 때문에 몇 분 걸릴 수 있으며, 콘솔 결과는 감독 프로세스가 반환한 뒤 표시됩니다. 결과는 같은 폴더의 `serialized-protected-worker-result.log`에 남습니다.

실제 DEMO 계좌에서 BTCUSDT ISOLATED 2배 LONG OPPOSITE_QUOTE LIMIT 진입을 최대 1건 수행합니다. 수량 상한 0.0007 BTC, 명목 상한 100 USDT입니다. 체결 후 원래 손절·익절 보호가 확인되어야 해당 자식 worker만 최대 1회 강제 종료합니다. 감독 프로세스는 계속 실행하여 자연 lease 만료, fencing, 보호 연속성, 새 세션에서 같은 주문 ID 대조와 최종 잔여 포지션·주문 정리를 검증합니다. 정리 과정에서 기존 프로그램의 위험 감소 청산이 실행될 수 있습니다.

새 작업 ID: `e85a00f2-6b8e-4b39-bac2-b958a001c8c0`. 이전 실패 작업 `5bb5814c-55e0-4b7f-882c-a7a449ec2182`와 다릅니다. 이전 결과 파일은 그대로 보관하세요. 예전 `RUN-ONE-PROTECTED-WORKER.cmd`는 사용하지 마세요.

실행기는 설치된 코드·설정 9개 SHA256, 한국 날짜 2026-11-06, NORMAL/일시정지, 날짜·주간 기준 일치, 읽기 전용 준비 검사와 거래소 빈 상태를 먼저 확인합니다. 실제 실행은 원래 프로그램의 추가 안전 검사를 거칩니다. 날짜가 바뀌었거나 키가 만료됐거나 상태가 다르면 중단하며 자동 갱신·복구·진입 재개·재시도를 하지 않습니다. 기존 결과 로그가 있으면 다시 실행하지 않습니다.

완료 화면 전체를 보내주세요. 성공 기준은 내부 결과의 `PROTECTED_CHILD_SIGKILL_FENCED_RECOVERY_FLAT_VERIFIED`와 실행기 `VERIFIED`입니다. `NOT_ACCEPTED`, `BLOCKED`, `NOT_VERIFIED`는 성공이 아닙니다. 그런 경우 로그를 지우거나 작업 ID를 바꾸어 재실행하지 말고 결과를 보존하세요. 안전 청산 후 EMERGENCY/일시정지로 남을 수 있으며 자동 승인하지 않습니다.

DB·API·호스트·알림 worker는 강제 종료하지 않습니다. 이 명령은 메일 테스트나 전송을 요청하지 않지만, 실제 위험 상태 전환이 일어나면 기존 알림 worker가 해당 경고를 발송할 수 있습니다. LIVE 거래는 비활성화 상태를 유지합니다.

이 패키지의 오프라인 검증은 실행기의 차단·호출 범위를 확인합니다. 이번 실제 계좌의 강제 종료·복구 성공, 부분 체결 보호, 실제 TP 체결 및 원래 SL 정리, 장시간 운영 완료를 미리 증명하지 않습니다.
