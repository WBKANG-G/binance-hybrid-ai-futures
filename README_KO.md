# DEMO 확정된 차단을 비용 예약 전에 적용 — 개발 검토 자료

시각 조회 실패로 이미 차단된 실행의 요청도 공유 비용을 예약한 뒤 거부되어, HTTP 전송 없이 기록이 늘어나는 순서 문제를 수정했습니다. 경로 5개 × 범위 4개의 수정 전 실패 20개를 재현했습니다. 실제 전송 차단은 이전에도 있었으므로 추가 거래소 요청이나 가중치 초과를 재현한 것은 아닙니다.

이제 이미 확인된 untrusted 상태는 공유 비용 예약·주문 권한 검사 전에 거부합니다. 첫 중단 사유와 기존 예약·불확실한 요청은 보존합니다. 단순 비용 부족으로 중단된 경우의 기존 청산·시각 조회·세션 종료 규칙은 유지합니다. 기록 삭제·환불·새 비용 여유 인정·자동 재시도는 추가하지 않았습니다.

검증: 테스트 1,328개, mypy 156개 소스, Ruff, 네트워크 없는 Docker 클라이언트·게이트 스모크 통과. 모의 TP·부분 체결 청산도 원래 전체 청산 확인까지 통과했습니다. 시작 대기는 가속했고 관찰은 0.8초입니다. 새로운 300초 자연 관찰이나 거래소 검증은 아닙니다.

실제 계정 주문 사용량·외부 IP 여유·전체 요청 비용 상한은 미확인입니다. 운영 실행 기본값은 비활성입니다. Windows 설치·Windows DB 변경·실제 거래소 요청·실제 주문·거래 재개는 수행하지 않았습니다. 현재 PC에서 추가 실행할 명령은 없습니다.
