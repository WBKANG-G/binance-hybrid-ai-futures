# 관찰 자원 대기의 현재 리스 확인

관찰 대기는 로컬 연결·소유권 객체와 원장의 청산 상태를 검사했지만, 그 원장을 일반 read(account_id)로 읽었습니다. 로컬 lease 객체가 바뀌지 않았더라도 PostgreSQL의 소유자·fence가 이미 다른 리더로 넘어가거나 lease_until이 만료될 수 있습니다. 특히 새 시간 조회나 예산 검사 전에 이 상태를 알지 못했습니다. 기존 DB 상태 변경과 주문 효과의 fencing은 유지되어 있었으며, 이 재현을 무단 주문 발생으로 설명하지 않습니다.

수정 전 실제 PostgreSQL 검사 6개가 예상 거부에 실패했습니다. 리스 이전과 만료를 각각 대기 진입 전·대기 중·예산 반환 시점에 주입했습니다. 일부 경로는 이후 renew에서 늦게 거부했지만, 그 전에 다음 예산 점검에 도달할 수 있었습니다. 오래된 예산 정보를 갱신하는 시점에는 시간 GET도 발생할 수 있었습니다.

새 코드는 기존 current_runtime_ledger를 재사용해 바인딩된 원래 저장소와 리스로 원장을 읽습니다. REPEATABLE READ / READ ONLY 트랜잭션에서 소유자·fence·lease_until을 함께 확인하며, 2초 statement timeout을 사용합니다. 기존 관찰의 세션 실패·로컬 소유권 검사 후, 시간 조회·예산 확인 전에 실행하고, 예산이 반환된 뒤에도 같은 확인을 합니다. 읽기 트랜잭션은 HTTP나 잠들기 전에 종료됩니다. 읽기 실패나 리스 불일치를 예산 조회로 우회하지 않습니다.

수정 뒤 6개 경계 검사에서는 상실이 확인된 뒤 시간 GET·추가 예산 점검·포지션 watch·원래 일반 재조회가 없고, 그 이후 계정/이벤트/outbox 및 두 저장소의 전체 바이트가 유지됩니다. 각 검사는 합법적인 이전 또는 시계 변경이 끝난 지점에서 상태를 기록합니다. 그 전에 정상 소유 상태에서 수행한 heartbeat·로컬 pause까지 없었다는 주장은 아닙니다. 이전 검사는 리스를 release한 뒤 새 소유자와 증가한 fence를 실제로 취득합니다. 만료 검사는 저장소 시계를 제어합니다.

추가 검사 8개는 기존 물리 포지션 파서를 바꾸지 않고 실제 bound client와 공유 예산을 통해 시간 GET 및 전 종목 positionRisk GET을 수행합니다. 합성 응답은 정상 zero, ETH 외부 노출, BTC 양수/음수 재노출, BTC 누락, 중복 종목, 헤지 positionSide, NaN 문자열입니다. 정상 zero에서만 원래 일반 재조회 진입점에 도달합니다. 나머지는 거부하고 flat 관측을 해제하며, 어떤 경우에도 이 watch가 금융 증명이 되거나 주문을 보내지 않습니다. 두 GET의 모델 비용 6은 남습니다. 과거 주문·금융 값은 유지되고 신규 진입 pause만 적용됩니다. 이 작은 검사에서 일반 재조회 진입점은 표시용 함수로 대체됩니다.

전체 검증에서는 정상 TP·부분 체결·봉인 실패·관찰 중 로컬 WSS 단절을 별도로 새로 실행합니다. 기존 원래 금융 확인·봉인, 수신 오류 후 일반 관찰 차단, 비용 계약, V1/V2 판독기는 그대로입니다. 이번 리스·포지션 경계 검사 자체를 실제 거래소의 포지션 발생이나 새 300초 자연 관찰이라고 계산하지 않습니다.

현재 리스의 확인은 DB 스냅샷 시점과 애플리케이션 시계를 기준으로 합니다. 반환 직후 다른 프로세스가 리스를 바꿀 수 있으므로 여러 시스템에 걸친 원자적 예약이나 이후 모든 HTTP 요청을 보장하지 않습니다. 기존 주문 효과·DB 변경의 fencing이 최종 권한 검사로 남습니다. 일반 관찰의 대기 경계에 대한 개선이며, 이미 시작한 I/O 강제 취소나 모든 teardown 요청의 전역 중단을 구현한 것은 아닙니다. 새 노출을 임의로 소유한 청산 대상으로 간주하지 않습니다.

실제 계정 주문 사용량·외부 IP 여유·실제 거래소 비용 상한은 여전히 별도 검증 대상입니다. Windows 설치·DB 변경·실제 거래소 요청·주문·거래 재개는 수행하지 않습니다. 검증은 합성 HTTP·localhost WSS·격리 PostgreSQL을 사용합니다. 실제 검사 수와 통과 여부는 검토 ZIP의 VALIDATION.json 및 evidence/에 기록합니다.

현재 회귀 검사 1,872개, 집중 검사 38개(회귀에 포함), 새 모의 실행 4개가 통과했습니다. 이전 JUnit·300초 실행을 현재 수에 재사용하지 않았습니다. 검토용 소스 ZIP이며 설치 프로그램이 아닙니다.
