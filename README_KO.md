# 활성 포지션 조회 부하 합성 검증 — 2026-11-06 (한국시간)

검증 결과: 61개 테스트 통과(89.02초). 정상 300초 주기 모델은 가정 한도 안에서 종료됐지만, 이벤트 집중 및 공유 IP 급증 시 종료 요청이 막히는 위험은 남아 있습니다. 신규 DEMO 주문 재시도나 운영 재개 근거로 사용하지 않습니다.

이 패키지는 **검토용 보고서와 클라우드 전용 합성 테스트**입니다. Windows에서 실행할 명령이나 설치 변경은 없습니다. 실제 거래소, 키, 사용자 DB를 사용하지 않았고 운영 소스와 스키마도 변경하지 않았습니다. 실제 계좌의 마지막 확인 상태는 NORMAL / paused=true / 포지션·일반 주문·조건부 주문 0입니다. 이 보고서가 그 이후 계좌 상태를 실시간 확인한 것은 아닙니다.

## 실측 기준과 모델의 구분

사용자가 완료한 읽기 전용 프로파일: 3회, HTTP 132회, signed GET 126회, 33.957초, 최대 관측 분당 카운터 1,151, 공개 REQUEST_WEIGHT 한도 6,000, 카운터 초기화 또는 분 변경 1회. 418/429는 관측되지 않았습니다.

인접 응답의 카운터 차이는 공유 IP의 다른 활동을 포함할 수 있어 엔드포인트별 고정 비용을 입증하지 않습니다. 합성 모델은 이 차이를 참고값으로 사용했습니다. positionSide/dual은 30과 35, 실측하지 않은 경로·쓰기의 비용은 1과 40으로 각각 비교했습니다. 40은 증명된 최대 비용이 아닙니다. 거래소의 별도 주문 한도, WSS 서비스 한도, IP 동시 부하 전체를 모델링하지 않았습니다.

가상 300초 모델의 총 요청은 각 조합 1,706회이며, 총 가정 가중치는 17,109~18,051입니다. 총량은 여러 분에 걸친 합계로, 분당 한도와 직접 비교하면 안 됩니다. 첫 분 최대는 4,625~5,096, 중간 분은 2,312~2,372, 마지막 종료 분은 3,236~3,467입니다. 분 경계는 합성 거래소 시계에 따른 것이며 모든 가능한 진입 시점·분 경계를 검증하지 않았습니다.

가상 시간은 EventInbox의 대기 경로에서만 진행시켰습니다. 실제 localhost WSS 연결과 ping/pong, 원래 coordinator·조회 라우터·PostgreSQL 상태 전이를 사용했습니다. 거래소에서 실제로 300초 관찰한 결과가 아닙니다. 테스트 종료는 세션 취소·회수 뒤 원래 finalization 경로를 호출합니다.

## 보존한 검증과 남은 작업

테스트는 중복 진입 방지, 신규 LIMIT 진입 최대 0.0007 BTC/100 USDT, reduce-only 종료 최대 1회, 일시정지, 기존 이력·요청·위험 기준값 보존, 노출이 남으면 VERIFIED_FLAT로 보고하지 않음, rate-limit 중 노출은 EMERGENCY/UNKNOWN을 검사합니다. 의도적으로 실패 상황을 주입한 테스트의 통과는 해당 시나리오가 안전하게 청산됐다는 뜻이 아닙니다.

현재 정상 flat 확인 경로도 전체 이력 스냅샷을 5회 조회합니다. 이 증거를 줄이거나 기존 안전 검증을 완화하지 않았습니다. 다음 구현 과제는 진입·반복 조회·종료 확인의 요청 예산을 분리하고, 한도 소진 전에 반복 조회를 제한할 수 있도록 하는 것입니다. 종료 여유 확보 정책과 공유 IP 급증 대응을 검증하기 전까지 신규 주문 재시험은 보류합니다. 실제 부분체결 보호와 실제 TP 체결 후 원래 SL 정리의 승인 증거도 여전히 미확보입니다.
