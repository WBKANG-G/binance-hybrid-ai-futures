# TP 진입 예산 후보 — 검토 전용

설치된 기준 소스: `4e967dc6751c6f04786ba63cdcc97e7eb1c80a39`
후보 소스: `00489ecd99e5b77ae2581fddded4eb64cf18e316`

현재 Windows에 설치하거나 실행할 패키지가 아닙니다. 실행 파일, 설치 도우미, 거래 활성화 CLI는 없습니다. Windows의 일시정지, 계정 상태, DB 및 주문에는 접근하지 않았습니다. main도 변경하지 않았습니다.

## 변경 내용

- 공개 exchangeInfo의 1분 REQUEST_WEIGHT 한도와 최신 사용량 헤더를 읽고, 준비·진입 보호·청산·여유분의 모델 비용을 검사합니다. 6,000에서는 세션/TP 마커/예약/주문 이전에 차단합니다.
- 기본값은 큰 한도에서도 실제 실행을 거부합니다. 별도로 명시한 합성 테스트만 가상의 100,000 한도에서 실행했습니다.
- 진입 가능성을 한 번 소비하면 응답 유실에도 환불하거나 재전송하지 않습니다. 진입 후에는 같은 제출 스레드의 기존 SL/TP 보호 처리를 마친 뒤 로컬 중단을 알립니다.
- 일반 조회는 청산용 여유를 사용하지 않습니다. 로컬 중단 뒤에도 listenKey 종료와 기존 청산 경로의 알려진 요청을 전달합니다. 알 수 없는 경로는 차단합니다.
- 기존 SDK의 418/429 쿨다운, 원래 보호·청산·거래내역 전체 검증은 유지합니다. 공유 IP의 다른 사용자가 예산을 소진하면 청산 완료를 보장할 수 없습니다.
- 기존 파일 변경은 demo_validation.py의 선택적 훅 두 곳, 총 6줄입니다. 기존 CLI 및 설치 가드의 소스 고정값은 그대로이며, 기존 설치 가드는 이 후보를 거부합니다.

## 실제 검증 결과

후보 44개(단위 30 + 통합 14), 적용 가능한 전체 단위 752개, 기존 TP/보호/읽기 풀/레이트 제한/비공개 세션 통합 59개가 통과했습니다. 후보 단위 30개가 전체 단위에 포함되므로 서로 다른 통과 검사는 **825개**입니다. Ruff 및 mypy(134개 운영 소스 파일)도 통과했습니다.

과거 읽기 풀 설치 가드의 소스 고정 긍정 검사 3개는 변경 전 기준 소스에서도 SOURCE_HASH_MISMATCH로 실패했습니다. 가드를 수정하거나 완화하지 않았습니다. 초기 전체 실행 결과와 기준 소스 재현 XML을 포함했고, 최종 단위 실행에서는 해당 3개 정확한 노드만 제외했습니다.

HTTP 응답과 주문은 가짜 거래소, 이벤트는 로컬 WSS, DB는 분리한 테스트 PostgreSQL입니다. 실제 계정/API 및 Windows DB를 사용하지 않았습니다. 후보 통합 관찰 시간은 0.8초 또는 2초이며 실제 300초 후보 시험은 실행하지 않았습니다. 원래 300초 운영 상수는 변경하지 않았습니다.

가상 100,000 모델에서 TP 체결, 미체결·부분체결, TP 미체결 후 원래 reduce-only 청산, 최대 10페이지의 완료 이력, 10페이지도 가득 찬 불완전 이력, 일반 조회 예산 차단, 진입 응답 헤더 누락, 보호 예산 추정 초과, 공유 IP 급증, 동일 작업 재실행 차단을 확인했습니다. 일반 예산 차단/헤더 누락/추정 초과에서는 원래 최종 확인이 FINISHED_FLAT이어도 세션 오류가 있으므로 TP 전체 보고서는 NOT_ACCEPTED/UNKNOWN을 유지합니다. 불완전 이력과 실제 쿨다운 상황에서도 성공으로 바꾸지 않았습니다.

## 모델의 한계와 다음 작업

이력 2개 모델의 청산 비용 28,352와 전체 수명주기 34,268은 **검증된 상한이 아닌 보수적 설계 가정**입니다. 이것이 실제 청산에 항상 필요한 비용이라는 뜻은 아닙니다. HTTP 변경 요청 비용 40도 합성 모델 가정입니다. 공유 IP 용량 확보, 별도 주문 횟수 제한, 엔드포인트 비용 상한은 증명하지 않았습니다. 분 경계나 낮아진 헤더를 새 크레딧으로 사용하지 않습니다.

따라서 6,000 한도에서 실행 가능한 TP가 완성됐다는 결과가 아닙니다. 다음 개발은 원래 청산·이력 증명 요건을 유지하면서 비용 상한을 정하고, 6,000에서 실행 가능한 설계인지 입증하는 작업입니다. Windows는 계속 paused 상태로 유지합니다.
