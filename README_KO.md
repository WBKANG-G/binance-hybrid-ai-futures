# 검토 결과의 명시적 새 파일 저장

--save-receipt 옵션을 추가했습니다. 원본·기존 결과·링크·디렉터리를 덮어쓰지 않고, 비공개 임시 파일을 완성한 뒤 배타적인 하드 링크로 게시합니다. 지원하지 않는 파일 시스템은 실패하며 덮어쓰기 우회는 없습니다. 기본 출력과 읽기 전용 --verify-receipt는 그대로입니다.

현재 소스 회귀 검사 1,522개, 집중 검사 103개(회귀에 포함, 새 저장 검사 20개), mypy 158개 소스, Ruff, 네트워크 없는 Docker 검사가 통과했습니다. 저장 경합·부분 쓰기·sync 실패·게시 응답 불확실성·임시 파일 정리 실패를 검증합니다. 오류 시 이미 게시되었을 수 있는 최종 결과를 삭제하지 않습니다. 부모 디렉터리·하드웨어 장애 후 영구 보존을 인증하지 않습니다.

해시를 검증한 이전 ZIP의 모의 TP·부분 체결·봉인 실패 자료 3개를 새 CLI로 저장·대조했습니다. 정상 종료 0/0, 봉인 실패의 추가 검토 코드 3을 유지했고 기존 결과·원본으로의 저장 6건은 거부했습니다. 원본 바이트와 기존 결과는 보존되었습니다. 이전 금융 JUnit 3개는 출처를 표시한 재사용 기록이며 이번 실행 수에 넣지 않았습니다. 금융 실행 코드를 바꾸거나 새 청산 흐름을 실행하지 않았습니다. 원래 자료는 대기 가속·0.8초 관찰 결과이며 새 300초 관찰 또는 거래소 검증이 아닙니다.
