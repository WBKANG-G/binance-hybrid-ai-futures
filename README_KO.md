# 공개 DEMO 호가 잔량의 제한 관측

앞선 사용자 결과에서 e0e27c9a-8616-48bb-aab7-5f061bff908b 복구는 NORMAL/paused, 이력4건 그대로 보존/상태해결처리false, 금융·과거이력보존, 리더반환 및 Nov5/Nov2 기준일 일치·원격empty 준비 확인을 보고했다. 새 주문은 아직 계획하지 않는다.

이번 작업은 실제 부분체결 검증의 준비 조건을 확인하기 위한 공개 DEMO 호가 조사다. 클라우드에서 직접 공개API 연결을 시도했으나 DemoUnknown/network request failed로 현재 데이터를 받지 못했다. 실제 데이터나 잔량 조건을 추정해서 채우지 않았다. 사용자 PC의 기존 API 컨테이너에서 다음 읽기 도구를 실행한다.

ZIP을 새 폴더에 풀고 CHECK-PUBLIC-LIQUIDITY.cmd가 보이는 위치에서 CMD를 연다.

```bat
CHECK-PUBLIC-LIQUIDITY.cmd
```

약25~30초와 준비/진행 중 요청 완료 시간이 필요할 수 있다. 시계·exchangeInfo를 먼저 확인하고2초 간격으로 호가를 최대12회 조회한다. 샘플링 시간 상한30초 이후 새 요청을 시작하지 않으며 이미 진행 중인5초 제한 요청은 마친다. 데이터 없음/잘못된·과거·미래호가/시계실패/요청실패/429이면 중단하고 자동재시도하지 않는다. 원래 신선도5초 및 시계 RTT/offset 안전한도를 완화하지 않는다.

API키/Secret/키 세션/DB를 읽지 않는다. SDK public 메서드가 항상 api_key=None으로 전송하는 것을 시험했다. public/time, exchangeInfo, BTCUSDT bookTicker 세 경로만 허용하고 모든 signed/account/order/session 경로는 차단한다. API소스/이미지/설정/위험상태/계정/기준금·이력을 변경하거나 재시작하지 않는다. 실제 LIVE/DEMO 주문/취소 없음.

samples에는시각/호가가격/최우선 잔량/공개필터 최소수량 추정치를 기록한다. within_cap_thin_top_samples는 LOT범위·step·0.0007BTC·100USDT 한도를 만족하는 최소수량보다 매도1호가 잔량이 작게 관측된 횟수다. 전체 호가장, 현재 private 계정·담보·포지션·손실 게이트, mark-price 가격필터/체결확률은 확인하지 않는다. 공개필터 추정치가 실제 실행을 승인하는 것은 아니다.

작은 잔량은 순간적인 부분체결 가능 조건의 단서일 뿐이다. 호가와 잔량은 전송 전에 바뀔 수 있어 체결/부분체결/보호 성공을 보장하지 않는다. 후보가0이라고 부분체결 자체가 불가능하다는 뜻도 아니다. 현재 cap을 늘리거나 가격을 추격하거나 이 보고서 가격으로 주문을 만들지 않는다. 이벤트/부분체결을 만들기 위한 반복 주문도 하지 않는다.

결과는 public-liquidity-report.json에 저장한다. 기존 파일을 덮어쓰지 않는다. 출력 전체를 공유한다. BLOCKED면 같은 명령을 자동반복하지 않는다. 새 거래 단계가 아니며 Phase4 전체/Phase5/LIVE/main 병합을 포함하지 않는다.
