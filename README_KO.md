# 별도 반대 호가 TP 단일 DEMO 검증 — 검토용

코드/시험/전송본을 준비했으며 사용자 PC 적용과 실제 주문은 아직 실행하지 않았다. 기존 PASSIVE 실행 범위와 다른 진입 가격 결정 방식이므로 실행 전 사용자 확인이 필요하다는 운영 판단이다. AGENTS.md가 이 특정 모드 승인을 직접 요구한다고 주장하지 않는다.

## 변경 내용

기존 TPTriggerCoordinator는 PASSIVE만 허용하고 반대 호가를 거부하는 시험도 그대로 유지했다. 새 전용 coordinator와 명시적인 entry-style+추가 enable 플래그가 함께 있어야 반대 호가 TP 관찰을 시작한다. 베이스 실행기의 원래 신선도/최소 수량/담보/예산/리스/펜스/종목/유효기간/손실/멱등성 검사를 재사용한다.

매수는 새 조회 당시 매도1호가를 한 번 LIMIT 가격으로 사용한다. 즉시 체결되거나 taker 수수료가 발생할 수 있다. 호가 조회와 전송 사이 시세가 움직이면 체결되지 않을 수도 있다. 가격 추격/재가격 조정/추가 진입/자동 재시도는 없다. 사용자 최신 미리보기의80317/56.2219USDT 등은 만료된 참고값이며 실행 시 사용하지 않는다.

## 고정 검증 범위

DEMO BTCUSDT LONG ISOLATED2배, entry POST 최대1회, 수량 최대0.0007 BTC/명목100USDT. 최소 수량을 충족하지 못하거나 실제 새 최소 수량이cap을 넘으면 중단한다. 신호 생성부터10초, 준비/제출 후 관찰 상한300초, SL0.5%/TP1% 및 기존 위험/수수료/슬리피지 가정은 변경하지 않는다. 추정 손절 비용은 실제 최대 손실 보장이 아니다.

체결 후300초 내TP가 없으면 원래 안전 종료/flat 확인을 수행하며 EMERGENCY 잠금이 남을 수 있다. 자동으로 잠금/미해결 요청을 해제하지 않는다. TP 성공은 실제 TP FINISHED/연결된reduceOnly 실행 FILLED/포지션0 확인 후 원래 SL DELETE 및 CANCELED, 운영자 종료 POST0과 기존 이력/기준금 보존이 모두 있어야 한다. 단순 체결/보호 접수/운영자 종료로 대체하지 않는다.

같은 검증의 WSS 수신 힌트e/E+시계 정보만 함께 기록·재생한다. 별도 이벤트 발생용 주문은 없다. 원문 전체 private frame 재생은 아니며 이벤트가 없거나 재생이 실패하면 해당 범위만 미검증이다. 재생 실패는 실제 주문 결과를 지우거나 추가 주문/종료를 발생시키지 않는다.

## 실행 경로 — 아직 실행하지 않음

확인된 뒤 새 폴더에서 RUN-ONE-OPPOSITE-TP.cmd 한 번으로 읽기 전용 준비 검사→api만빌드/갱신→수정 소스SHA4개 검증→준비 재확인→단일검증을 진행할 수 있도록 준비했다. DB/key-session/alerts/web를 재생성하지 않는다. 주문 및capture 결과는 opposite-tp-result.log에 남기고 기존 로그가 있으면 덮어쓰거나 실행을 반복하지 않는다. 고정 작업ID는 OPPOSITE_TP_REVIEW_PLAN.json을 따른다.

준비/적용 실패면 거래 명령을 실행하지 않는다. 실제 검증 결과 실패/UNKNOWN/NOT_ACCEPTED면 로그를 보존하고 반복하지 않는다. 이전 소스 폴더도 보관한다. 되돌림은 기존 소스의api만 재빌드하며 DB 이력/실제 거래 결과를 되돌리지 않는다.

LIVE/Phase5/main 병합 및 Phase4 전체 완료를 포함하지 않는다. 기존 PASSIVE 기본값, 한도, SL/TP 수락 조건을 낮추지 않았다.
