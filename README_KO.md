# DEMO 청산 확인 중 원래 저널 잠금 소유권 검사 — 개발 검토 자료

저널 객체가 같아도 프로세스 잠금이 닫히거나 잠금 경로가 없어지거나 교체되면 연결 검사만으로는 알 수 없었습니다. 초기 진입과 비용 대기 후의 수정 전 실패 6개를 실제 저널 파일·검사용 스케줄러로 재현했습니다. 실제 무단 주문이나 가짜 청산 성공을 재현한 것은 아닙니다.

기존 잠금 소유권 검사를 확인 단계·작업자 진입의 연결 검사에서 재사용합니다. 상실 시 다음 작업 전에 거부하며 잠금 재획득·기록 초기화·봉인·환불은 추가하지 않았습니다. 잠금과 DB 무결성의 구분 및 원래의 비상 청산 예외 규칙은 유지합니다.

별도 실제 격리 PostgreSQL 검사에서는 대기 중 소유자·펜스·만료 시각이 바뀌면 원래 리스 갱신이 거부되고 기존 미완료 6슬롯 예약이 보존됨을 확인했습니다. 이 동작은 원래 있던 펜싱이며 새 계정 전체 사용량 증명이 아닙니다.

검증: 테스트 1,410개, mypy 157개 소스, Ruff, 네트워크 없는 Docker 격리 가드·실제 저널 스모크 통과. 별도 모의 TP·부분 체결 청산이 원래 전체 증명까지 완료됐고 정상 흐름에서 연결 거부가 0회임도 확인했습니다. 시작 대기는 가속했고 관찰은 0.8초입니다. 새로운 300초 자연 관찰이나 거래소 검증은 아닙니다.

실제 계정 주문 사용량·외부 IP 여유·전체 요청 비용 상한은 미확인입니다. 운영 실행 기본값은 비활성입니다. Windows 설치·Windows DB 변경·실제 거래소 요청·실제 주문·거래 재개는 수행하지 않았습니다. 현재 PC에서 추가 실행할 명령은 없습니다.
