# 첫 취소 대기 확인 후보 — 검토 전용

이 ZIP은 **검토용**입니다. 설치 CLI나 거래 활성화 명령은 없습니다. 실제 DEMO/LIVE 거래와 Windows DB에 접근하지 않았습니다. 기존의 기본 실행 거부와 6,000 한도 진입 차단은 유지합니다.

## 결과와 한계

가짜 거래소에서 전체 이력 10페이지, 취소 요청 ACK 뒤 상태 반영 지연을 같은 조건으로 비교했습니다. 처음 3회 UNKNOWN, 4회째 기존 전체 검증으로 flat을 확인하는 경우입니다.

| 모델 비용 | 직전 후보 | 이번 후보 |
| --- | ---: | ---: |
| 최종 확인 전 청산 준비 | 1,717 | 1,717 |
| 최종 확인 | 4,624 | 3,409 |
| CLEANUP 합계 | 6,341 | 5,126 |
| 진입 준비·관찰 등을 합친 전체 구간 | 9,528 | 8,313 |

청산 구간 비용은 1,215(약 19.16%) 줄어 6,000 아래가 됐습니다. **전체 구간은 8,313으로 여전히 6,000을 초과**합니다. 이 값은 한 경로의 누적 모델이며 실제 서버의 분별 용량을 확보하거나 모든 경로의 상한을 입증한 값이 아닙니다. 거래를 재개할 근거가 아닙니다.

취소가 즉시 반영되는 조건에서는 첫 상태 조회 때문에 청산 비용이 4,255에서 4,267로 12 증가합니다. 끝내 취소가 확인되지 않는 조건은 비용이 줄어도 UNKNOWN을 유지합니다. 실패·불일치 경로는 이 성공 경로보다 비쌀 수 있습니다.

## 변경 동작

첫 확인에서 원래 QUERY의 전체 이력 스냅샷 2회, 일관성 대조, 원래의 fenced 보호 주문 정리를 그대로 수행합니다. 그 뒤 읽기 전용 상태 조회로 모든 관리 대상이 로컬에서 닫혀 있고, 전 종목 포지션이 0이며, 성공 응답을 받은 취소 ID가 아직 NEW인지 확인합니다. 상태 조회는 보호 주문을 새로 삭제하거나 재무 정보를 갱신하지 않습니다.

취소가 반영되지 않았으면 첫 시도의 VERIFY용 전체 스냅샷 3회를 미루고 **UNKNOWN만 반환**합니다. 다음 기존 시도에서 취소가 반영된 경우에는 원래 전체 확인을 처음부터 다시 수행해야 합니다. 성공한 마지막 시도의 전체 이력 스냅샷 5회 및 원래의 모든 최종 성공 조건은 유지합니다.

- 취소 요청 실패/불명확 응답, 아직 취소를 요청하지 않은 NEW 주문, 잘못된 상태 응답은 대기 성공으로 취급하지 않습니다.
- 오류·쿨다운·fence 거절은 원래의 실패 경로를 따릅니다. 마지막 전체 확인에서 이력이 불완전하거나 다른 종목 포지션이 있으면 성공하지 않습니다.
- 첫 대기 조회는 이미 진행 중인 전체 확인의 **동일한 시간·서명 조회·clock probe 예산**을 공유합니다. 새 예산으로 초기화하지 않습니다. source와 observer의 객체가 맞지 않으면 거부합니다.
- 같은 인스턴스의 명령과 확인은 같은 lock으로 직렬화합니다. source client는 오류와 대기 제어 흐름 모두에서 복원됩니다.
- 기존 4회 시도와 1초 간격을 늘리지 않습니다. 4회 모두 미확인이면 UNKNOWN과 일시정지를 유지합니다.

직전 후보의 대기 조회 helper에 선택적 source/observer 인자를 추가했습니다. 기존 인자 없는 호출은 기존 context 동작을 유지하며, 원래 실행·청산·스냅샷 파서·최종 확인 함수는 수정하지 않았습니다.

## 검증

**127개 통과**: 비용 비교 10개, 첫 확인 오류 경로 18개, 새 구성요소의 진입 예산 통합 14개, 청산 준비 오류 14개, 대기 조회 안전 경로 24개, 대상 범위·동시 명령 15개, observer/직렬화 2개, 기존 예산 단위 검사 30개입니다. Ruff와 mypy(137개 운영 소스 파일)도 통과했습니다.

취소 실패, ACK 정보 누락, 잘못된 주문 ID·상태·포지션 응답, 다른 종목 노출, 로컬 상태 변경, HTTP500/404/429, 공유 조회·시간·clock 예산 소진, fence 거절, 마지막 전체 확인의 income 불완전, 대기 중 잔고 변경, 마지막 확인 전 다른 종목 노출을 검증했습니다. 새 구성요소에 기존의 부분/미체결·응답 유실·중복 명령·손실 잠금 입력 검사도 다시 적용했습니다.

실제 PostgreSQL 분리 스키마와 로컬 WSS를 사용하고 HTTP/주문/체결은 모두 가짜입니다. 가상 한도는 100,000이며 변경 요청별 비용 40을 가정했습니다. 엔드포인트 비용 상한, 공유 IP 용량, 별도 주문 횟수 제한은 증명하지 않았습니다. 테스트 관찰 시간은 0.8초 또는 2초이며 운영 300초 상수는 바꾸지 않았습니다. 이번 후보의 실제 300초 시험은 하지 않았습니다.
