# DEMO 실행 시작·클라이언트 연결 검사 — 개발 검토 자료

조립 후 환경이나 전송 경로를 바꿨을 때 초기 조회 단계까지 진입하던 두 사례를 재현하고 수정했습니다.
수정 전에는 가짜 전송이 호출된 뒤 더 늦은 시각 응답 검사에서 실패했습니다. 진입 주문이나 실제 거래소 요청을 재현한 것은 아닙니다.
이제 시작 대기 전과 후에 환경·소유 연결·위험 상태·노출·기간·이력·저장소를 재검사합니다.

- 알려진 잘못된 시작 상태를 심박 쓰기·전송 전에 거부합니다.
- 공개/서명/listen-key 요청마다 클라이언트의 전송 경로·자격 증명·고정 설정을 확인합니다.
- 예산의 원본 전송 경로·제공자·모델·비용을 바꾸면 새 예약 전부터 거부합니다.
- 기존 내부 DEMO 활성화 전환은 허용하고, 실패·취소 후에는 조립 당시 비활성 설정으로 복구합니다.
- 종료는 공개 별칭이 바뀌어도 원래 소유한 예산과 저널만 정리합니다. 미완료 예약은 반환하지 않습니다.

수정 전 재현 두 건의 늦은 실패와 수정 후의 조기 거부를 evidence/REPRODUCTION.json 및 최소 재현 소스에 기록했습니다.
집중 검증 25개를 포함해 테스트 1,206개, mypy 155개 소스, Ruff 통과.
새 클라이언트를 사용하는 조립 경로에서 모의 TP 청산과 부분 체결 후 청산도 전체 확인까지 완료했습니다.
시작 대기는 가속하고 관찰은 0.8초이며 요청 가중치 시계는 실제 시간입니다. 새 300초 자연 관찰이나 실제 거래소 검증은 아닙니다.
Docker 스모크는 네트워크 없이 기본 차단·LIVE 시작 거부·변경된 전송 경로 거부를 검사합니다. 전체 PostgreSQL 프로토콜 검증은 별도 통합 결과입니다.

검사 후 발생하는 모든 동시 변경을 동결하는 전역 트랜잭션이나 악성 Python에 대한 샌드박스는 아닙니다.
기존 제출 시점의 펜싱·소유권·수량 검사와 전체 청산 확인이 계속 필요합니다. 기존 안전 마감시간이나 판정은 완화하지 않았습니다.
운영 CLI·Windows 설치·Windows DB 변경·실제 거래소 요청·실제 주문·거래 재개: 0.
실제 계정 주문 사용량·외부 IP 여유·비용 상한 증명은 여전히 미확인입니다. 현재 PC에서 추가 실행할 명령은 없습니다.
