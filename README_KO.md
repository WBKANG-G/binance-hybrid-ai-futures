# DEMO 같은 실행의 청산 확인을 한 번만 시작 — 개발 검토 자료

확인 함수를 다시 호출하면 시간·횟수 제한이 새로 시작되고, 동시에 호출하면 별도 확인 루프가 시작되는 공백을 수정했습니다. 재호출·동시 호출의 수정 전 실패 7개를 재현했습니다. 스케줄러 테스트는 UNKNOWN만 반환하며 가짜 전체 청산 성공을 만들지 않습니다.

이제 같은 실행 조립의 확인 진입점은 원자적으로 한 번만 시작 권한을 얻습니다. 성공·미확인·예외·호출 취소 후에도 권한을 되돌리지 않습니다. 재호출은 새 작업이나 시각 읽기 없이 UNKNOWN을 반환하고 첫 호출의 결과·횟수·중단 사유를 보존합니다. 이전 VERIFIED_FLAT을 새 확인 결과처럼 재사용하지 않습니다.

범위는 같은 코디네이터 객체의 이 진입점입니다. 계정 전체의 영속 횟수 제한이나 프로세스 잠금을 대신하지 않습니다. 기존 저널·펜싱·미확인 기록 검사는 유지합니다. 호출 종료가 진행 중인 스레드의 종료를 증명하지 않으며, 작업 강제 취소나 새 시간 여유는 추가하지 않았습니다.

검증: 테스트 1,363개, mypy 157개 소스, Ruff, 네트워크 없는 Docker 스레드 권한·가져오기·기본 차단 스모크 통과. 별도 모의 TP·부분 체결 청산에서 원래 전체 증명 성공 후 재호출이 추가 전송 없이 거부되고 첫 증명이 보존되는 것도 확인했습니다. 시작 대기는 가속했고 관찰은 0.8초입니다. 새로운 300초 자연 관찰이나 거래소 검증은 아닙니다.

실제 계정 주문 사용량·외부 IP 여유·전체 요청 비용 상한은 미확인입니다. 운영 실행 기본값은 비활성입니다. Windows 설치·Windows DB 변경·실제 거래소 요청·실제 주문·거래 재개는 수행하지 않았습니다. 현재 PC에서 추가 실행할 명령은 없습니다.
