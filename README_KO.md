# DEMO 청산 확인 작업의 시작 기한 — 개발 검토 자료

기존 120초 제한은 비용 보류 때만 검사되어, 시각 조회나 직전 작업에서 시간이 소진된 뒤에도 다음 확인 작업을 시작할 수 있었습니다. 작업 순서·대기 시간의 수정 전 실패 6개를 재현했습니다. 스케줄러 테스트는 UNKNOWN만 반환하며 가짜 전체 청산 성공을 만들지 않습니다.

검토용 조립에 새 스케줄러를 연결했습니다. 다음 작업을 시작하기 전 기한을 확인하고, 대기는 남은 시간까지만 사용합니다. 완료된 확인 4회 제한을 유지하며, 시계가 멈춘 경우에도 보류 120회 안에 끝납니다. 시계 이상은 UNKNOWN, 원래 오류와 호출 취소는 그대로 전달합니다.

120초는 다음 작업의 시작 기한입니다. 이미 시작한 작업은 원래 제한 안에서 완료하도록 두며 스레드를 강제 취소하지 않습니다. 이미 시작한 원래의 전체 증명이 기한 뒤에 유효하게 완료되면 그 결과를 버리지 않습니다. 전체 함수의 120초 강제 종료를 증명한 것은 아닙니다.

검증: 테스트 1,353개, mypy 157개 소스, Ruff, 네트워크 없는 Docker 산술·가져오기·기본 차단 스모크 통과. 별도 모의 TP·부분 체결 청산은 원래의 전체 청산 확인까지 통과했습니다. 시작 대기는 가속했고 관찰은 0.8초입니다. 새로운 300초 자연 관찰이나 거래소 검증은 아닙니다.

실제 계정 주문 사용량·외부 IP 여유·전체 요청 비용 상한은 미확인입니다. 운영 실행 기본값은 비활성입니다. Windows 설치·Windows DB 변경·실제 거래소 요청·실제 주문·거래 재개는 수행하지 않았습니다. 현재 PC에서 추가 실행할 명령은 없습니다.
