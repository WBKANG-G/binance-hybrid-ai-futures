# DEMO 청산 증명과 봉인·세션 실패를 구분하는 검토 진단

기존 확인 진단에 원래 청산 증명과 별도로 남던 봉인·세션·브리지 실패를 함께 분류하는 표시를 추가했습니다. 이전 소스에서 새 표시가 없던 10개 보고서 입력 사례를 확인했고, 현재 분류 검사 11개가 통과했습니다. 이 보고서 입력은 금융 증명이나 10개 거래 실패의 증거가 아닙니다.

진단은 첫 확인 소유자의 반환된 증명, 봉인 실패, 세션·브리지 상태, 취소·기한·횟수 제한·컨텍스트 거부를 구분합니다. 모든 결과는 execution_approved=false 및 KEEP_PAUSED_REVIEW_ONLY입니다. 진단 읽기는 금융 DB나 봉인 기록을 다시 검사하지 않으며, 실패 플래그가 없다는 사실을 새 봉인 증명으로 보지 않습니다. 실제 처리·실패 복구·승인 규칙은 바꾸지 않았습니다.

검증: 테스트 1,422개, mypy 157개 소스, Ruff, 네트워크 없는 Docker 보고서 입력 스모크 통과. 모의 TP·부분 체결에 더해 봉인만 의도적으로 실패시킨 실제 모의 전체 흐름을 검증했습니다. 마지막 경우 원래 청산 증명 성공은 보존되고 미완료 예약 1개가 남으며, PROOF_VERIFIED_QUOTA_SEAL_FAILED로 표시되고 실행 승인은 거부됩니다.

모의 시작 대기는 가속했고 관찰은 0.8초입니다. 새로운 300초 자연 관찰이나 거래소 검증은 아닙니다. 실제 계정 주문 사용량·외부 IP 여유·전체 요청 비용 상한은 미확인입니다. 운영 실행 기본값은 비활성입니다. Windows 설치·Windows DB 변경·실제 거래소 요청·실제 주문·거래 재개는 수행하지 않았습니다. 현재 PC에서 추가 실행할 명령은 없습니다.
