# DEMO 주문 저널 재시작 점검 — 소스·검증 자료

이번 추가 기능은 실행 객체를 만들지 않고 DB와 주문 저널의 일치 여부를 읽기 전용으로 검사합니다.
PostgreSQL은 REPEATABLE READ / READ ONLY, SQLite는 mode=ro / query_only와 공유 잠금을 사용합니다.
점검 중 세션·리더·파일을 만들거나 기존 예약·전송 권한을 지우지 않습니다.

- 저장소가 없으면 새로 만들지 않고 STORAGE_NOT_PROVISIONED 또는 저장소 누락으로 중단합니다.
- 실행 중인 작성자, 유효 리더 임대, 미완료 흐름, 기록 불일치, 날짜 불일치 등을 구분합니다.
- 모든 로컬 검사를 통과해도 KEEP_PAUSED이며, 주문 카운터는 null / 실제 계정 사용량은 UNKNOWN입니다.
- 적용·초기화·복구·거래 활성화 옵션은 없습니다. API 키와 거래소 HTTP를 사용하지 않습니다.

테스트 1,097개(중복 제외), mypy 149개 소스, Ruff 통과.
점검 도중 고의로 UPDATE를 시도해 PostgreSQL이 거부함을 확인했으며, 계정·이벤트·아웃박스와 저널 파일 동일성을 검증했습니다.
부분 체결 청산과 저널 장애 시 기존 위험 축소 청산도 모의 환경에서 재검증했습니다.
이 두 생명주기 검증은 시작 대기 시계를 가속하고 짧은 관찰 시간을 사용했습니다. 300초 자연 실행을 새로 수행했다는 의미는 아닙니다.
네트워크 없는 Linux Docker에서도 SQLite 쓰기 거부와 작성자 배제를 검증했습니다.

이 압축파일은 설치 프로그램이 아닙니다. 현재 Windows PC에는 추가 실행 명령이 없으며, 설치·데이터 변경·거래 재개는 하지 않았습니다.

SOURCE_PROOF.json: 고정 소스 커밋, 기존 운영 파일 152개 동일성
VALIDATION.json / evidence/: JUnit, 정적 분석, 스모크, 모의 트레이스
source/: 고정 기준 커밋 이후 추가된 파일 12개
SOURCE.patch: 기준 커밋에 대한 누적 변경 / STARTUP_DELTA.patch: 이전 검토 소스에 대한 이번 변경
