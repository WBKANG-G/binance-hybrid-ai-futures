# 관리형 TP 런타임의 요청 비용 계약

공식 SDK의 고정 커밋 `f75b4a52c5aebf52b1c6ad671b0ce53b96f8e179`에서 현재 허용 쿼리에 대응하는 21개 경로의 문서 비용을 확인했습니다. 공개 GitHub 파일 4개의 원본 SHA-256과 21개 메서드·경로·문서 인용을 다시 다운로드해 검증했습니다. 실제 거래소에 요청하지 않았습니다. 근거는 `request_cost_evidence/PINNED_RUNTIME_COST_PROOF.json`에 있습니다.

기존 런타임은 조립 시 처음 받은 모델 비용표를 그대로 고정했습니다. 초기 비용표가 잘못되었거나 공개 쿼리의 LIMIT·symbol 선택이 변경되어도 조립을 통과할 수 있었습니다. 수정 전 계정 조회 과소 계산, 새 주문 과소 계산, 경로 누락, 추가 경로, klines limit=1500 변경의 5가지 검사가 모두 예상 거부에 실패했습니다.

새 계약은 현재의 21개 경로와 검토한 정수 비용을 정확하게 요구합니다. 작은 비용뿐 아니라 더 큰 값·bool·float·누락·추가 경로도 재검토 없이 받아들이지 않습니다. 더 큰 값도 원래 묶음 예산과 분석 가정을 바꾸므로 자동 허용하지 않습니다. 공개 쿼리의 symbol=BTCUSDT, klines interval=1m/limit=2, 전역 조회 집합, 서명 필드와 쿼리 정책 버전도 함께 확인합니다.

조립 기본 실행 거부는 그대로 가장 먼저 실행됩니다. 명시적인 합성 실행 경로에서도 원장 SQL 조회, 파일 저장소 열기, writer session 생성, HTTP 요청 전에 초기 비용 계약을 검사합니다. 직접 OwnedSharedBudget 구성 시에도 검사하며, 각 요청과 증명 점검에서 기존 연결·모델 검사와 함께 정책 변경을 다시 거부합니다. 실행 중 정책 변경 거부는 새 공유 예약이나 주문 권한 소비를 만들지 않습니다. 기존의 비용표 변경 오류 코드는 유지합니다.

| 현재 허용 형태 | SDK 문서 IP 비용 | 유지한 모델 비용 |
|---|---:|---:|
| symbol 없는 openOrders/openAlgoOrders | 각각 40 | 각각 40 |
| limit=2 klines | 1 | 1 |
| BTCUSDT premiumIndex/bookTicker | 각각 1 / 2 | 각각 1 / 2 |
| income 한 페이지 | 30 | 30 |
| 새 일반 주문·알고 주문 | 각각 0 | 각각 40 |
| 취소·listenKey 관리 | 각각 1 | 각각 40 |

새 주문의 SDK IP 비용 0은 주문 개수 제한 0을 뜻하지 않습니다. SDK는 새 일반 주문과 알고 주문에 대해 10초·1분 주문 개수 비용을 각각 1로 기술합니다. 기존 여섯 슬롯 예약과 별도 주문 제한 처리는 바꾸지 않습니다. 보수적인 모델 비용 40도 줄이지 않습니다.

진단 `request_cost_contract`는 고정 문서의 21개 경로를 현재 모델이 덮는다는 비교 결과입니다. 실제 거래소의 현재 비용 상한, 계정 전체 주문 사용량, 외부 IP 여유 또는 실행 승인을 증명하지 않습니다. 문서 비용을 실제 비용의 상한이라고 이름을 바꾸지 않으며, production 기본 비활성화를 해제하지 않습니다. query 계약 밖의 형태는 기존처럼 거부합니다. Python 코드를 직접 바꿀 수 있는 공격자를 격리하는 보안 샌드박스도 아닙니다.

현재 검증은 새 비용 계약 검사, 기존 회귀 검사, 새 합성 TP·부분 체결·봉인 실패 실행, 네트워크 없는 Docker 검사입니다. 지난 변경의 300초 자연 시간 모의 관찰은 원본 ZIP 해시·소스 커밋과 함께 재사용 기록으로 구분합니다. 이번에 새 300초 검사를 했다고 계산하지 않습니다. 관찰 대기·전체 금융 확인·요청 비용표·원래 운영 파일은 바꾸지 않았습니다.

Windows 설치·DB 변경, 실제 거래소 요청·주문·거래 재개는 수행하지 않습니다. 미제공 계정 사용량을 0으로 간주하거나 가짜 사용량 증거를 만들지 않습니다. 구체적인 검사 수와 근거는 검토 ZIP의 VALIDATION.json과 evidence/에 기록됩니다.

회귀 검사 1,790개, 집중 검사 119개(회귀에 포함), 새 TP·부분 체결·봉인 실패 3개가 통과했습니다. 이전 300초 검사는 재사용 기록이며 현재 실행 수에 포함하지 않습니다. GitHub 다운로드와 내부 해시를 확인한 검토용 소스 모음이며 설치 프로그램이 아닙니다.
